# PRD · P32 多账户仓位（仓库）

> 版本：待开发（预计 v6.52+）
> 前置：P15（记账与档位对账）、P21（卖出摊派回滚）、P27（双币口径）、P30（满仓成本）
> 一句话：**把"一个持仓"拆成"多个银行账户的持仓"，账本按账户记，计划仍只有一套；顺带把回本价补进浮动盈亏。**

术语：**账户**与**仓库**同义，都指一个银行积存金账户（招行 / 工行 / 建行…）。正文统一用「账户」。

---

## 0 这一轮在解决什么

现在整个应用默认"我只有一仓金"：`holdStats()` 把所有买入减所有卖出算成一个数，均价、浮盈、止盈、仓位进度都挂在这一个数上。

实际使用中，钱分散在几个银行积存金账户里（招行、工行、建行…），每个账户的买入价不同、卖出时从哪个账户出也不同。现在的做法只能靠"标签"字段自己写"招行"，汇总永远是混在一起的。

本轮要做的是：**在不破坏"一套档位计划"的前提下，把持仓拆到账户维度**。

---

## 1 现状：持仓页其实有两条数据链路

这一点必须先说清，否则多账户一定会做歪。

| 链路 | 数据 | 谁在用 | 是否进"持仓汇总" |
|---|---|---|---|
| **账本链路** | `cfg.buys` / `cfg.sells` 逐笔记录 | 持仓克重、均价成本、浮动盈亏、止盈阶梯、仓位进度 | ✅ 是 |
| **计划链路** | `cfg.gearMarks` 每档 g / cost / sold | 建仓阶梯的"已买 / 待补 / 已买超"、执行复盘 | ❌ 否（只有 `syncMarksFromBuys` 单向同步过去） |

两条链路的关系是单向的：**有记账的档，档位的克重与成本由记录重算；只标记不记账的档，保留手工值。**

这意味着：

- "标记已买"（建仓页的快速按钮）**不写账本**，所以它不进持仓汇总；
- 因此**账户余额只能由买卖记录汇总**，不能由档位标记汇总；
- 一个账户的克重 = 该账户的买入 − 该账户的卖出，与档位标记无关。

这条边界决定了多账户只能建在账本链路上，**不能建在档位链路上**。

## 2 三个维度，别混

| 维度 | 回答 | 归属 | 是否随账户变化 |
|---|---|---|---|
| **账户（仓库）** | 这批金放在哪个银行账户 | 记录级（每笔买入/卖出带一个） | — |
| **档位计划** | 按第几档、什么价买 | 全局唯一（高点、档距、权重、目标总克重） | ❌ 不变 |
| **成交记录** | 某天买了多少、什么价 | 记录级，带账户 + 可选档位 | ✅ 按账户过滤 |

**核心裁决：账户是"钱和货的归属"，档位是"买入的节奏"。两者正交，不互相嵌套。**

不做「每个账户一套档位计划」，也不做「每档绑定一个账户」。理由在 §3.1。

---

## 3 六个歧义点，先裁掉

### 3.1 一档的克重，跨账户怎么办？

例如第 4 档 72g：招行买了 40g、工行买了 32g。

**裁决：允许跨账户。** 档位只认"这一档买了多少克"，不认是谁买的。建仓页仍显示 `已买 72 / 72g`，账户拆分只在持仓页体现。

如果改成"一档只能一个账户"，会逼出两种情况：要么一档拆成两个伪档（计划变形），要么买满一档就必须换账户（实际操作不允许）。两种都更糟。

### 3.2 目标总克重、档位价、权重，属于谁？

**裁决：属于全局，与账户无关。** 设置页的「目标总克重」改名为「目标总克重（全账户合计）」，其余不动。

不提供"每个账户单独设目标"。理由：档位计划是一套按金价走势设计的节奏，不是按银行拆的预算。若按账户设目标，就得回答"金价跌到第 4 档时，是招行买还是工行买"——这个问题本身没有答案。

### 3.3 切换账户后，建仓页要不要变？

**裁决：不变。** 建仓页的档位进度、待补、下沉、满仓成本全部是全局口径，不随持仓页的账户筛选变化。

页面之间用一句话说明：**持仓页的账户筛选只影响账本，不影响计划。**

### 3.4 老数据（没有账户）怎么落？

**裁决：迁移时自动建一个「默认账户」，把所有历史记录归入。**

不做"未分配"这个第三桶。因为一旦存在"不属于任何账户"的持仓，账户卡片下面三项相加就对不上总数，用户会怀疑数据错了。归入默认账户是可逆的：需要拆分时，逐笔编辑记录改账户即可。

### 3.5 卖出时账户余额不够怎么办？

**裁决：按账户校验，不跨账户借。** 卖出只能从选定账户出，超过该账户余额直接拦下，提示「招行积存金只剩 12.4 克」。

编辑一笔卖出（改大克重）时，校验用的是「该账户余额 + 本笔原克重」。

### 3.6 卖出摊到哪几档，按账户摊吗？

现有逻辑：卖出不指定档位，按**全局各档净持比例**摊到 `gearMarks.sold`（P16），并把结果存进记录的 `allot`。

问题：招行只买过第 3 档，从招行卖 10g，摊派可能落到第 1、2 档头上。

**裁决：一期保持全局摊派，不改。** 理由：

- `gearMarks` 本身不带账户，要按账户摊就必须给它加一层账户明细，改动面比整个 P32 还大；
- 档位层只影响"待补多少、还差几档"，不影响持仓与金额，摊歪了不会算错钱；
- 卖出记录上的账户是准的，账户余额、均价、浮盈全部正确。

二期若确实需要（用户反馈"建仓页的待补看着不对"），再给 `gearMarks` 增加 `byAcct` 明细，届时只改摊派，不动记录结构。

## 4 功能需求

### 4.1 账户模型

```
cfg.accounts = [
  { id:"a1", name:"招行积存金", note:"尾号 3821", color:"#D4A24C", at:1759... }
]
```

| 字段 | 规则 |
|---|---|
| id | `a` + 时间戳，创建后不变 |
| name | 1–12 字，同一份数据内唯一（重名直接拦） |
| note | 选填，≤20 字，显示在账户名右侧的灰字 |
| color | 6 色预设（金 / 蓝 / 绿 / 紫 / 橙 / 灰），用于徽标与占比条 |
| at | 创建时间，同时作为默认排序 |

约束：**至少保留 1 个账户**，不允许删到 0。

### 4.2 账户管理

入口：持仓页「账户」卡片右上角「管理」。

管理面板（复用 sheet）：

- 列表：色点 + 名称 + 备注 + 当前克重 + 记录笔数 + 右侧「编辑 / 删除」
- 底部：「+ 新建账户」
- 新建/编辑：名称、备注、颜色（6 选 1），保存校验重名
- 删除：
  - 该账户有记录 → 不允许直接删，弹出「转移到…」选择器，转移完成后才删
  - 该账户无记录 → 二次确认后删
- 删除写墓碑 `cfg.delAccts`，避免另一台设备合并时复活（与 `cfg.del` 同一套思路）

### 4.3 记账带账户

「记一笔」弹层（买入与减仓共用）在「标签」下方加一行：

```
账户  [ 招行积存金 ▾ ]
```

规则：

| 场景 | 行为 |
|---|---|
| 新建 | 默认选中上次使用的账户（`cfg.acctLast`）；只有一个账户时锁定不可改，只显示名字 |
| 编辑已有记录 | 显示该记录当前账户，可改（等于转移，两账户余额同步重算） |
| 没有账户 | 不可能出现（迁移保证至少一个） |
| 卖出 | 校验所选账户余额，见 §3.5 |

记录列表每行在第二行（名称 · 时间）前加账户徽标：`● 招行 · 第3档 · 10-14 09:20`。

### 4.4 持仓页结构调整

```
总览页
└─ 仓位条（不变：全账户）

持仓页
├─ 仓位进度卡（不变：全账户，上限 = 全局目标总克重）
├─ 持仓汇总卡
│   ├─ 筛选条： [全部 3] [●招行] [●工行] [●建行]     ← 新增
│   ├─ 浮动盈亏（大字）
│   ├─ 持仓克重 / 持仓成本 / 均价成本 / 现价 / 收益率
│   └─ 回本价 / 还差                                ← 新增
├─ 账户卡片（新增，恒定显示全部账户）
├─ 买入记录（跟随筛选）
├─ 执行复盘（不变）
└─ 止盈阶梯（不变：一期仍按全账户均价）
```

筛选条与持仓汇总卡绑在一起，视觉上是一个整体；仓位进度卡与止盈阶梯在它之外，明确不受影响。

为什么筛选不做成"全局开关"（顶部常驻）：一旦放在页面顶部，用户会以为建仓页也跟着切了。放在持仓汇总卡内部，它的作用域就是这张卡加下面的记录列表，边界一眼可见。

### 4.5 账户卡片

标题：`账户 3` + 右侧「管理」。下面是桌面示意，手机端折成三行（见 §4.8）。

```
总持仓 128.428 g · 成本 ¥119,420 · 浮盈 +¥740
● 招行积存金   尾号3821    79.6g   均价 929.62   回本 939.62   +¥320   ████████░░
● 工行积存金   尾号 1102   38.5g   均价 941.08   回本 951.08   +¥120   ████░░░░░░
● 建行积存金   主卡        10.3g   均价 950.20   回本 960.20   +¥300   █░░░░░░░░░
```

- 每行可点 → 等价于选中该账户筛选（点了之后卡片本身不消失，仍然显示全部，方便对比）
- 占比条宽度 = 该账户克重 ÷ 全账户克重
- 空账户（0 克）也显示，用于"这个账户还没开始买"
- 卡片底部一行小字：**账户只影响记账口径；档位与目标克重是全局计划，不按账户拆分。**

### 4.6 回本价

定义：**回本价 = 均价成本 + 回本加点**，默认加点 10 元/克，设置页可改（0–50）。

- 展示在持仓汇总卡，与均价成本并排：
  ```
  均价成本 929.62        回本价 939.62
  现价 935.10            还差 0.48%
  ```
- 「还差」= 现价 ÷ 回本价 − 1，为负时显示 `还差 0.48%`（绿色），转正后显示 `已过 +1.2%`（红色）。涨红跌绿，与全站一致。
- 文案脚注（点击问号展开）：`回本价 = 均价 + 10 元/克，用来覆盖买卖双边手续费与点差；不是保本线，只是"卖出后每克净赚 10 元"的出清参考。`
- 账户卡片每行也显示该账户的回本价（各自均价 + 同一点数）。
- 总览页的仓位小条**不加**回本价（一行三个数已经挤满），点进持仓页看。
- 「回本加点」放在设置页「仓位」卡，与底仓保留同区，默认 10，范围 0–50。

### 4.7 筛选口径

| 区域 | 筛选影响 |
|---|---|
| 总览页仓位条 | ❌ 不变 |
| 持仓页 仓位进度卡 | ❌ 不变 |
| 持仓汇总卡（克重/均价/浮盈/回本价） | ✅ 变 |
| 买入记录列表 | ✅ 变（只列该账户） |
| 账户卡片 | ❌ 不变（恒列全部，用于横向对比） |
| 执行复盘 | ❌ 不变（档位是全局的） |
| 止盈阶梯 | ❌ 一期不变（按全账户均价），二期再评估 |
| 建仓页所有内容 | ❌ 不变 |
| 待办 / 角标 / 提醒 | ❌ 不变 |

筛选中时，持仓汇总卡顶部显示 `当前：招行积存金（79.6g / 共 128.4g）`，避免误以为数据丢了。

### 4.8 移动端布局

页面是移动优先，账户信息在 390px 宽下要能读：

- **筛选条**：横向滚动，按钮 `min-height: 34px`，不换行；账户多于 3 个时右侧渐隐提示可滑
- **账户行**：两行式，不要挤成一行
  ```
  ● 招行积存金  尾号3821              79.6g
    均价 929.62 · 回本 939.62        +¥320
    ████████░░░░░░░░░░░░  62%
  ```
- **账户管理面板**：全屏 sheet，列表行高 ≥ 56px，删除按钮放右侧、用弱化的红字（不放大红块）
- **记账弹层的账户下拉**：字号 16px（避免 iOS 聚焦放大），选项文字超过 8 字时截断加省略号
- 账户名超过 6 字时，账户卡片行内截断，完整名放在 `title`

## 5 与建仓页的联动规则

| 建仓页元素 | 多账户后 | 说明 |
|---|---|---|
| 档位价、权重、档数 | 不变 | 全局计划 |
| 每档「已买 / 待补」 | 不变 | 按 `gearMarks`，由所有账户的记录合并重算 |
| 「标记已买」快速按钮 | 不变，不选账户 | 它只释放计划额度，不写账本；要留账户就走「记一笔」 |
| 满仓成本、逐档均价 | 不变 | 与持仓无关的静态属性 |
| 「我的位置」 | 不变 | 全局持仓 |
| 执行复盘 | 不变 | 档位口径 |

**唯一新增的联动（二期）**：建仓阶梯每档展开时，多一行「这笔在哪个账户」——把该档的买入记录按账户聚合，例如 `招行 40g · 工行 32g`。一期不做。

## 6 数据模型与迁移

```js
cfg.accounts   = [{ id, name, note, color, at }]
cfg.acctLast   = "a1"          // 上次使用的账户
cfg.comeback   = 10            // 回本加点，元/克
cfg.delAccts   = ["a9"]        // 删除墓碑
cfg.buys[i].acct  = "a1"       // 必填
cfg.sells[i].acct = "a1"       // 必填
cfg.schemaVersion = 3
```

迁移（`migrateCfg` 里新增一段，只跑一次、幂等）：

1. 没有 `accounts` → 建 `{ id:"a0", name:"默认账户", color:"#D4A24C" }`
2. 所有 `buys` / `sells` 缺 `acct` 或指向不存在的账户 → 设为 `"a0"`
3. `acctLast` 无效 → 设为第一个账户
4. `comeback` 非数字 → 10

回滚提示：升到 v3 后旧版本会忽略并覆盖这些字段，回退到 v6.51 会丢账户信息。写进 CHANGELOG，与 P24 的版本说明同一节。

## 7 空态与文案

| 场景 | 文案 |
|---|---|
| 只有一个账户 | 账户卡片不显示占比条，只显示一行；筛选条隐藏（没有可切换的） |
| 某账户 0 克 | `● 建行　还没开始买` |
| 筛选后无记录 | `招行积存金还没有买入记录` |
| 删除有记录的账户 | `招行有 12 笔记录，先转移到其他账户才能删除` |
| 卖出超余额 | `招行只剩 12.4 克，卖不了 20 克` |
| 重名 | `已经有叫「招行积存金」的账户了` |
| 删到最后一个 | `至少保留一个账户` |

## 8 边界与非目标

**做**：账户 CRUD、记录带账户、账户统计卡、按账户筛选、账户级回本价、全局回本价。

**不做**：

- ❌ 每账户独立档位计划 / 独立目标克重
- ❌ 真实金条划转（银行不支持）。删除账户时的「转移到…」只是改记录的归属字段，不产生任何"划转"记录，也不改金额
- ❌ 账户级止盈阶梯（一期）
- ❌ 按账户的待办与提醒
- ❌ 账户权限 / 密码（这是个人工具，不是多人账本）

## 9 验收清单（供测试用）

**数据与迁移**

1. 老数据无 `accounts` → 打开后自动出现「默认账户」，所有记录归入，持仓克重与迁移前完全一致
2. 迁移幂等：连续打开两次，不重复建账户、不改记录
3. `acct` 指向已删除账户 → 自动落到第一个账户，不报错

**账户 CRUD**

4. 新建账户后立即出现在筛选条与账户卡片
5. 重名被拦，提示文案正确
6. 删除无记录账户 → 二次确认后消失
7. 删除有记录账户 → 被拦，转移后才能删
8. 转移后原账户记录清零，目标账户克重增加

**记账**

9. 记一笔默认选中上次账户
10. 改记录账户 → 两账户克重同步变化，全局合计不变
11. 卖出超账户余额被拦
12. 只有一个账户时，账户下拉不可改

**汇总与回本价**

13. 账户卡片三项（克重 / 成本 / 浮盈）相加 = 全局值（误差 ≤ 0.01）
14. 筛选某账户后，持仓汇总只算该账户，仓位进度卡仍是全局
15. 回本价 = 均价 + 10，改设置为 5 后所有位置同步
16. 「还差 / 已过」的颜色与文案正确：低于回本价显示绿色「还差 X%」，高于显示红色「已过 +X%」
17. 空账户显示「还没开始买」，不显示 NaN / ¥0

**联动不串味**

18. 建仓页档位进度在切换账户筛选后不变
19. 纯「标记已买」不产生账户持仓，账户卡片合计仍等于账本
20. 止盈阶梯一期仍按全账户均价，切换筛选后数值不变（并有一行说明）

## 11 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 迁移写坏历史 | 一次性改所有记录的 acct | 迁移只加字段不改金额；迁移前后持仓/成本必须完全一致（写测试守住） |
| 回滚丢账户 | 旧版本保存会覆盖掉 accounts | CHANGELOG 明示；导出 JSON 时含 accounts |
| 筛选造成误解 | 用户以为克重变少是丢数据 | 筛选条显示 `79.6g / 共 128.4g`，账户卡片恒定显示全部 |
| 账户与档位对不上 | 纯标记不落账本，账户合计 ≠ 档位已买 | 已知口径差，沿用执行复盘的"每克拉低"解释，不新增对账指标 |
| 多设备合并 | 两台设备各自加了账户 | 账户按 id 合并、同 id 以最新 `at` 为准；删除靠墓碑 |
| 档位摊派跨账户 | 卖出按全局比例摊，可能摊到该账户没买过的档 | 已知近似，不影响金额（§3.6）；二期再按账户细化 |

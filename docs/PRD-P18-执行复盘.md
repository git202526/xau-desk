## 零、为什么取消过，又为什么现在能做

原方案被否掉时有三个理由，逐条对照现在的状态：

| # | 取消理由 | 现在 | 结论 |
|---|---|---|---|
| ① | 逐档成本偏差使用频率低，**看完也不改参数** | 本期不只给偏差，还给「执行状态」四态。**「未到价」直接指向参数问题**（档设得太深），这是能改的 | 已解决 |
| ② | 账本模式缺档位归属，整张表只能降级成汇总 | **P20 把账本模式删了**，全站只有标记一套数据源，逐档归属天然成立 | 已消失（但硬依赖 P20） |

## 一、问题：数据都在，但没人把它拼起来

用户想知道「我这套阶梯，到底执行得怎么样」，现在要拼四张表：

| 在哪 | 有什么 | 缺什么 |
|---|---|---|
| 计划页档位卡 | 每档「净持 / 计划」、`+$412 / 2.3 轮` | 看不出**成交均价跟计划价差多少** |
| 持仓页持仓卡 | 总克重、总均价（元/克） | 只有总账，**不分档** |
| 持仓页买入记录 | 逐笔克重、单价、时间 | 记录与档位的对应关系要自己回忆 |
| K 线图 | 过去价格走势 | 「这一档的价，过去一年到过没有」得自己数 |

四条信息各自成立，合起来才回答一个问题：**该买的买了没有？买贵了还是买便宜了？没买是因为没到价，还是因为我忘了？**

## 二、目标

1. **一屏看清每档的执行质量**：计划价、成交均价、偏差、净持完成度
2. **把「没买」拆成两种**：价格没到（不怪你）vs 到过价没买（漏单）
3. **给出能改参数的依据**：某档全程未触及 → 档距设深了
4. **对账**：档位累计买入 vs 账本累计买入，差额是否说得清

## 三、口径（先定死，后面全靠它）

### 3.1 成交均价

```
成交均价ᵢ($/oz) = gearCost(i, mkᵢ, 计划价ᵢ) / grossᵢ × OZ_PER_G
```

- `gearCost`（`:2492`）已有：有 `cost` 用它，没有就按档位价估
- `grossᵢ` 是**累计买入**（`gearMarks[i].g`），不是净持 —— 摊派只改 `sold`，不改 `g`
- 现成写法先例：`index.html:5683`（标记面板的「买入均价」）

### 3.2 偏差

```
偏差ᵢ(%) = (成交均价ᵢ / 计划价ᵢ − 1) × 100
```

- **负数 = 买得比计划便宜（好事）**，正数 = 买贵了
- `|偏差| ≤ 0.3%` 视同打平（挂单正常滑点）
- `costEst` 为真的档，均价就是档位价，偏差恒为 0 —— **这类档不参与加权汇总**，避免把真实偏差稀释成 0

### 3.3 执行状态四态

`待补ᵢ = 计划ᵢ − 净持ᵢ`，`净持ᵢ = grossᵢ − soldᵢ`：

| 状态 | 条件 | 含义 | 用户该做什么 |
|---|---|---|---|
| **已执行** | `待补 ≤ 0.05` | 达标（含超买） | 无 |
| **待补 · 未到价** | `待补 > 0.05` 且 `gross ≤ 0.05` 且历史未触及 | 价格从没跌到这 | 不用管，或调档距 |
| **待补 · 到过价** | `待补 > 0.05` 且 `gross ≤ 0.05` 且历史曾触及 | **漏单** | 补上，或确认放弃 |
| **已周转** | `待补 > 0.05` 且 `gross > 0.05` | 买过又卖了 | 正常，循环档就该这样 |

**为什么要用 `gross` 而不是净持做判据**：买过又卖出的档，净持会掉回 0，若拿净持判就会误报「漏单」。买过就是买过，卖不卖是另一件事。

### 3.4 触价扫描

```
触及 = 历史某根日线的 low ≤ 档位价
```

- 数据源：`scaled("1d")`（缩放后日线，PERIODS 里 limit 800）
- **必须用缩放后序列**：档位价 `H` 来自 `computeHEff()`（`:2211`），它读的是 `scaled("1d")`，两者同坐标系；用原始 `S.kl["1d"]` 会差一个 `S.scale` 倍，判出来的"触及"是错的
  - 这一条跟 P19-1 相反：P19-1 只用相对关系，所以用原始序列（`test_p19_backtrace.py::b12` 锁住），本期要比较绝对价格，必须缩放
- 本期不需要预热（不算 MA200），**全部 800 根都能扫**
- 输出：`{ hit:次数, lastT:最近一次时间, low:区间最低 }`

### 3.5 币种

**全程美元 $/oz**，不折人民币。理由：标记里的 `cost` 本身是 `gramToUsd()` 写进去的美元金额，档位价也是 $/oz，同源不需要汇率。

## 四、P18-1 逐档执行表

每档一个**三行块**（不是表格行），按 `gearCount()` 顺序，预警行跳过：

```
第 1 档                                      已执行
计划 4029.0  →  成交 4041.2   +0.30%
净持 16 / 计划 16g
```

六档连起来长这样：

```
第 1 档                                      已执行
计划 4029.0  →  成交 4041.2   +0.30%
净持 16 / 计划 16g
────────────────────────────────────
第 2 档                                      已执行
计划 3984.5  →  成交 3961.0   −0.59%
净持 16 / 计划 16g
────────────────────────────────────
第 3 档                                待补 · 到过价
计划 3940.0  →  成交 3940.0 估    —
净持 0 / 计划 16g
────────────────────────────────────
第 4 档                                待补 · 未到价
计划 3895.5 · 未成交
净持 0 / 计划 16g
────────────────────────────────────
第 5 档                                      已周转
计划 3851.0  →  成交 3830.5   −0.53%
净持 8 / 计划 16g
────────────────────────────────────
第 6 档                                已执行 · 超 8g
计划 3806.5  →  成交 3809.0   +0.07%
净持 24 / 计划 16g
```

**为什么不用表格**：320 宽塞不下 6 列；且项目所有渲染都过 `sanitizeHtml()`，它的白名单 `_ALLOW`（`:1335`）只放行 `div / span / button / i / s / b / strong / em`，`table / tr / td` 会被整棵剥掉。要加表格就得动全局安全层，为一个卡片不值当。三行块窄屏天然适配，不用横滑。

规则：

- **成交均价**：`gross ≤ 0.05` 时整段省略（只留「计划 3895.5」），不显示 `$0/oz`
- **`估` 角标**：`costEst` 为真时挂在均价后面（与档位卡 `:5150` 附近的「估」同一套语义）
- **偏差**：`gross ≤ 0.05` 或 `costEst` 时显示 `—`，不显示「0.00%」（会让人误以为成交价刚好等于计划价）
- **净持 / 计划**：超买时只写在状态里（「已执行 · 超 8g」），净持数字不标红
- **状态**：四种状态见 §3.3，「待补 · 到过价」是唯一需要用户行动的，前面加一个橙点
- **档名后缀**：档名下不重复档位价（第二行已经有了）

## 五、P18-2 合计与对账

明细下方一组汇总（窄屏折行）：

```
成交均价 计划 $4001.2 → 实际 $3998.7（−0.06%）  累计买入 168g · 卖出 32g · 已实现 $412 · 周转 2.4 轮
每克拉低 $84.3/oz（$2.71/g）   档位累计 168g · 账本累计 152g · 差 16g
```

四块各自的意义：

| 指标 | 算法 | 回答什么 |
|---|---|---|
| 计划均价 → 实际均价 | 按各行**克重加权**，跳过 `—` 行 | 整体是买贵还是买便宜了 |
| 累计买入 / 卖出 / 已实现 / 周转 | 由 `rvRows()` 逐档累加（`Σgross / Σsold / Σrealized / Σturns`） | 这套阶梯转了几轮、赚了多少差价 |
| **每克拉低** | `Σrealized / 净持仓克重`，再 `× OZ_PER_G` 折 $/oz | **已实现差价摊到现有持仓上，等于成本降了多少** |
| 档位 vs 账本 | `Σgrossᵢ` vs `holdStats().bought` | 档位表是不是虚的 |

四个细节：

- **加权均价跳过 `—` 行**：估算档的均价恒等于计划价，混进去会把偏差拉回 0。若参与加权的档数为 0，整行写「成交均价：全部为估算，无法计算偏差」
- **每克拉低**：`Σrealized` 是美元金额（`proceeds − 卖出克重 × 克重成本`），除以净持克重得 `$/g`，`× OZ_PER_G` 换成 `$/oz`。例：$412 / 152g = `$2.71/g`，折 `$84.3/oz`。两个单位都写（`$84.3/oz（$2.71/g）`），因为 $/oz 是全站口径、$/g 更好跟克重对上。净持为 0 时显示 `—`
- **档位 vs 账本差额**：差额 > 0.05g 时补一句「差额来自手动标记（标记不写账本）」，差额为 0 时补「一致」
- **不复用 `planSummary()` 的 `grossBought / soldTotal / realizedTotal`**：P20 批四已定把它们当死代码删除（P20 计划书 §4）。本期这四个数从 `rvRows()` 自己累加，口径与那三个字段相同（都来自 `gearMarks`），只是不共享变量

## 六、界面

### 6.1 位置

持仓页，**「买入记录」之后、「止盈阶梯」之前**：

```
[仓位进度卡]
持仓汇总
买入记录
[执行复盘]  ← 新增，默认折叠
止盈阶梯
```

放这里而不是计划页的理由：复盘的对象是**已经发生的事**，跟买入记录同类；计划页放的是还没发生的事，混在一起会让「这是计划还是回顾」说不清。

### 6.2 折叠

```
┌──────────────────────────────┐
│ 执行复盘          待补 22g  ⌄ │
└──────────────────────────────┘
```

- **默认收起**，收起时标题行右侧显示摘要（待补克重 / 已建满），不渲染明细
- 展开才跑触价扫描（800 根 × 档数，`touchScanIn()`），首屏零开销
- 折叠状态**不持久化**，每次进页面回到收起（不往 `cfg` 加字段，避免 P17 脏值比对多一个项）

### 6.3 窄屏

- **不分列，不做横滑**：每档三行块（§四）在 320 宽也是单列竖排，天然适配
- 合计行是 `flex-wrap` 的标签组，窄屏自然折行
- 三行块的第二行（`计划 → 成交 +偏差`）在 320 宽允许折成两行，不截断数字

## 八、诚实边界（三条，必须写进页面注释）

1. **档位价是「当前参数」算的**。用户中途改过起始跌幅、档距、档数的话，早期成交的偏差里混了参数变化的影响，不是纯粹的成交质量。页面脚注一句：`档位价按当前参数计算；改过参数后，早期成交的偏差含参数变化的影响。`
2. **「触及」用的是当前换算坐标**。`S.scale` 随现价变动，今天判「曾触及」的档，明天现价跳一手可能判「未触及」。这是缩放机制固有的，不修，但页面要标统计区间：`统计区间 2024-02-11 ~ 2026-10-31 · 800 根日线`。
3. **只覆盖日线能提供的时间**。约 800 个交易日，更早的成交不在扫描范围 —— 那几档的「未到价」只代表「近 800 根没到」，不代表历史上没到。

## 十、边界与异常

| 场景 | 处理 |
|---|---|
| **没有任何档位标记** | **照常出明细**：每档都是「待补 · 未到价 / 到过价」，第二行只有计划价。表尾加一句「还没有买入标记。在档位卡点「标记已买」，或记一笔带档位的买入，这里就会有成交价」。**不要用一句空话替掉明细** —— 六档各自差多少、离现价多远、历史到没到，本身就是信息 |
| 一档计划克重都没有（`totalGrams` 异常） | 才显示空态：「档位克重为 0，先在设置页定目标总克重」 |
| 全部档位 `costEst` | 偏差全 `—`，合计行写「成交均价：全部为估算，无法计算偏差」 |
| 净持仓为 0（全卖了） | 每克拉低显示 `—`；「已周转」状态照常显示 |
| 日线不足 30 根 | 跳过触价扫描，「待补」档一律显示「未到价」，表尾注明「K 线不足，未做触及判定」 |
| 某一档计划克重为 0 | 该档状态显示 `—`，不参与份额统计（除零保护） |
| 档数改成 10 档、标记只有 6 档 | 后 4 档 `gross = 0`、`sold = 0` → 「待补 · 未到价」或「到过价」，正常 |
| 超买档 | 状态「已执行 · 超 X g」，偏差照算 |
| `S.fx` 缺失 | 不影响：本期全美元，不碰汇率 |
| `cost` 存在但为 0（老数据） | `gearCost` 会按档位价估 → 视为 `costEst` |

## 十一、验收标准

1. 逐档块数 = `gearCount()`（无预警行）；10 档时仍单列竖排，不横向溢出
2. 成交均价与标记面板「买入均价」（`:5683`）对同一档算出**同一个数**
3. 全 `costEst` 时偏差全为 `—`，不出现 `0.00%`
4. 估算档不进加权：手工构造「1 档真实成交 +5%、5 档估算」，合计偏差必须是 +5%，不是 +0.83%
5. 四态判定：构造「买过又全卖」的档 → 「已周转」，不是「待补 · 到过价」
6. 「未到价」判定与 `scaled("1d")` 的最低点一致：把某档价设到历史最低价以下 → 必为「未到价」
7. 把某档价设到历史最低价以上 → 必为「到过价」
8. 触价扫描用缩放序列：改 `S.scale` 后结论随之变化（锁住 §3.4 那条）
9. 每克拉低 = `Σrealized / 净持 × OZ_PER_G`，与手算一致；净持 0 时为 `—`
10. 档位 vs 账本差额：只有手动标记时差额 = 手动克重之和；纯记账时差额 = 0
11. 无标记时仍出六档明细，且有引导文案；计划克重全 0 时才走空态
12. 页面不出现 `NaN` / `Infinity` / `undefined`
13. 默认收起，首屏不触发触价扫描（用调用计数断言）
14. 320 / 390 宽度下不横向溢出整页
15. 667 条老测试一条不改

测试：`test_p18_review.py` **16 条**。

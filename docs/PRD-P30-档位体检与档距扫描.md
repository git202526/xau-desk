## 1 为什么单参数回测必须退场

### 1.1 它在做循环论证

```
档位价 = H × 0.86 − i × d          （d 由目标均价反解，H = 最近 60 天最高收盘价）
H = 4,696 → 档位 3,518 ~ 4,039
放进 740 天前的行情（市价 2,756）
→ 十档全在市价上方 → 第一天全部跌穿
→ 按档位价成交 → 实质等于「在 3,518 以上一次性买入」
```

实测结果：本策略 **+5.36%**，一次性 **+42.99%**。37 个百分点的差不是 bug —— 金价从 2,756 涨到 3,952，用 3,518 以上的价格买入，结果必然差。

**这个卡测的不是「策略好不好」，是「金价涨了多少」。**

### 1.2 单参数 = 抛一次硬币

回测的正当用途是**参数扫描**：同一条行情，换 5 组参数各跑一遍，看指标怎么变。只跑一组，得出的数字没有对比对象，无法支撑任何决策。

现在的实现只跑一组，这就是「看了半天不知道该拿它干什么」的根源。

### 1.3 维护成本已经不低

| 项 | 数量 |
|---|---|
| 回测相关函数 | 30 个 |
| 回测 CSS | 56 行 |
| 回测专属测试 | 57 条（占全量 870 的 6.5%） |
| 改动次数 | 4 次里 3 次在修上一版的错 |

## 3 P30 · 档位体检

### 3.1 现有覆盖（不重复造）

| 问题 | 阶梯页现有 |
|---|---|
| 跌到多少才触发 | ✅ 每档 `dist`：距现价百分比 |
| 大概多久跌到 | ✅ 「40 日触及 X%」概率 |
| 买满的均价 | ✅ 均价卡 `avgAll`（$/oz） |
| 满仓要多少钱 | ❌ 只有均价，没有总额 |
| 跌到第 N 档时均价多少 | ❌ 只有「全部买满」一个口径 |

所以 P30 只做后两块，不新开卡 —— 新开卡就是两张卡说同一件事。

### 3.2 满仓成本

```
满仓成本($) = Σ(gram_i × price_i) ÷ 31.1035     i = 1..n，跳过 warn 档
满仓成本(¥) = 满仓成本($) × S.fx                仅参考，汇率缺失时显示「—」
```

- `gram_i` 用 **`g.plan`**（已含下沉后的实际克重），不用 `planBase` —— 否则和阶梯行显示的克重对不上
- `price_i` 用 `g.price`（档位价，$/oz）
- `warn` 档（pct 为正、高于高点）没有克重，跳过

### 3.3 逐档累计均价

```
累计均价(k) = Σ(gram_i × price_i) / Σ gram_i     i = 1..k，单位 $/oz
```

- 第 1 档均价 = 第 1 档价（自我校验点）
- 第 n 档均价 = `avgAll`（与均价卡一致，第二个校验点）
- 已买过的档按 `boughtG` 计，未买按 `plan` 计 —— 与阶梯页「实际 / 计划」口径一致

### 3.4 界面

均价卡新增一行：

```
满仓成本  $36,182（≈¥259,900）   300 g · 均价 $3,751/oz
```

阶梯每行新增一个小字（右对齐，`dist` 下方）：

```
第3档  $3,924  计划 24g   买到此档均价 $3,987
```

### 3.5 不做

- 不做独立卡片
- 不做「已买 / 未买」双口径均价拆分（均价卡已有 `avgAnchor`）
- 不引入历史数据

## 4 P31 · 档距扫描

### 4.1 扫什么：档距系数，不是档数

**不能扫档数。** `curW()` 读 `S.cfg.wPct`，默认 6 个权重 `[8,12,24,36,12,8]`。扫到 10 档时权重数组不够，必须人为造扩展规则 —— 那是假设，不是用户参数。

**改扫档距系数**：

```
d_k = d × k        k ∈ {0.6, 0.8, 1.0, 1.2, 1.4}
第 1 档价不变（p1Of(he) 不含 d），第 2 档起按 d_k 递减
```

好处：
- 权重、档数、高点、区间全部不动，只改一个维度
- 直接回答「档距该调宽还是调窄」
- k = 1.0 就是当前设置，可作为基准行

| k | 含义 | 第 1 档 | 第 10 档（示例） |
|---|---|---|---|
| 0.6 | 档位更密，更早买入 | 4,039 | 3,727 |
| 1.0 | **当前设置** | 4,039 | 3,518 |
| 1.4 | 档位更疏，更晚买入 | 4,039 | 3,311 |

### 4.2 结果表（5 列）

```
档距系数  首档价   触发     满仓成本    溢价率
×0.6     $4,039   10/10   $38,410    +44.1%
×0.8     $4,039   10/10   $37,120    +39.3%
×1.0     $4,039   10/10   $36,182    +35.7%  ← 当前
×1.2     $4,039    8/10   $32,050    +20.2%
×1.4     $4,039    5/10   $21,480    −19.4%
```

- **溢价率** = `满仓成本 ÷ (基准克重 × 区间首日收盘价 ÷ 31.1035) − 1`。正数=比一次性贵，负数=便宜
- 当前系数那一行加 `← 当前` 角标

### 4.3 不标「最优」

因为答案会退化：档距越大 → 档位价越低 → 成本越低。如果只看溢价率，永远推荐 ×1.4；但 ×1.4 只触发 5 档，另外 5 档的钱一直没花出去。

所以表里**并排给「触发档数」和「溢价率」**，让用户自己权衡，不给单一结论。

只标两个角标：
- `成本最低`：溢价率最小的那一行
- `触发最全`：触发档数最多的那一行（可能有多行并列）

### 4.4 继承 P29 的两项

| P29 内容 | 处置 |
|---|---|
| 取消预算上限 | ✅ 保留。扫描时预算上限会让不同组的买入被不同时点截断，结果不可比 |
| 区间可设（90/180/365/全部/自动） | ✅ 保留。扫描必须能指定区间 |
| 三组同本金 → 同克重 | ❌ 作废。扫描表本身就是同克重配额 |
| 均价列 | ✅ 保留，作为扫描表一列 |

### 4.5 保留什么、砍什么

| 现有 | 处置 | 理由 |
|---|---|---|
| 三组同本金对照表 | **砍** | 取消预算后三者本金无法一致；溢价率列已替代 |
| 权益曲线 | **留**，改单条收益率口径 | 「亏在哪一段」仍有价值；三组重合无意义 |
| 逐档对照表（P28） | **留**，改为点击某组后展示 | 复用 `bbGearsHtml` |
| 参数快照条（P28） | **留**，加「区间」一行 | |
| 高点三态（P28） | **留**，不改 | |
| P25 逐条依据 | **留**（依赖曲线） | |

### 4.6 交互

- 默认展开：结果表 + 当前系数那组的曲线
- 点任一行 → 下方展开该组的逐档表与统计
- 5 组结果一次算完（5 × 740 根 × 10 档 ≈ 3.7 万次循环，毫秒级），不需要异步

## 5 口径汇总

| 量 | 定义 | 单位 |
|---|---|---|
| 满仓成本 | `Σ(克重 × 档位价) ÷ 31.1035` | $ |
| 累计均价(k) | `Σ(前 k 档克重 × 档位价) ÷ Σ前 k 档克重` | $/oz |
| 区间首日价 | `bars[i0].c` | $/oz |
| 一次性成本 | `基准克重 × 首日价 ÷ 31.1035` | $ |
| 溢价率 | `满仓成本 ÷ 一次性成本 − 1` | % |
| 基准克重 | 本策略实际成交克重（k 组各自不同） | g |

**溢价率的分母用「本组实际成交克重」，不用总配额** —— 否则 ×1.4 那组只买 5 档却按 300g 折算，会算出一个虚假的低价。

## 8 验收标准

| # | 标准 |
|---|---|
| 1 | 满仓成本 = `Σ(plan × price) ÷ 31.1035`，与手算一致（±0.5%） |
| 2 | 第 1 档累计均价 = 第 1 档价；第 n 档累计均价 = `avgAll`（两个自我校验点） |
| 3 | 下沉开启时，满仓成本随 `plan` 变化（不等于 `planBase` 的算法） |
| 4 | `warn` 档不进累计均价，累计长度 = 实际档数 − warn 数 |
| 5 | 扫描返回 5 行，`scale` 依次为 0.6/0.8/1.0/1.2/1.4 |
| 6 | `scale = 1.0` 那组的满仓成本与阶梯页满仓成本一致（跨页对账） |
| 7 | 溢价率 = `满仓成本 ÷ (基准克重 × 首日价 ÷ 31.1035) − 1`，基准克重用本组成交克重 |
| 8 | 5 组的第 1 档价完全相同（`p1Of(he)` 不含档距） |
| 9 | 5 组的档距严格递增：`d × 0.6 < d × 0.8 < ... < d × 1.4` |
| 10 | 取消预算上限后，十档全触发时 `invest == fullCost`（±0.5%） |
| 11 | 区间选 365 天时 `meta.range.roots == 365`；K 线不足取全部不报错 |
| 12 | 4h / 1h 下区间控件隐藏，`range.kind == "all"` |
| 13 | 点数不足或 0 成交时不出现 `NaN` / `Infinity` / 除零 |
| 14 | 卡上明写「无预算上限 · 按档位价成交 · 不含盘中路径」 |
| 15 | 320 / 390 宽均无横向溢出，扫描表 5 列可读 |

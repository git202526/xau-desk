# PRD · P28 回测与设置参数关联

> 版本 v6.45 · 2026-11-03
> 起因：用户反馈「整个策略回测，没有参数设置选项，也没有和我设置里的参数联动，他自己判断的高点怎么是 2700 多……我搞不懂怎么使用」

## 一、问题

策略回测卡（`#btBackCard`）在页面上是独立的：它有自己的一套周期切换、循环档开关、下沉开关、手续费，然后给出一组数字。用户看不出这组数字和自己在设置页配的档位有什么关系。

三个具体现象：

| 现象 | 用户看到 | 实际原因 |
|---|---|---|
| 高点 $2760 | 设置页锚定的是 4400 左右 | 回测取**起点之前**的最高收盘价，防未来函数，但卡上没有任何说明 |
| 预算 $826,800 | 像「我有 82 万美元」 | 量纲错误：`克 × $/oz`，漏除 31.1035，放大 31.1 倍 |
| 0 / 10 档触发 | 这套档位好像废了 | 档位价整体挂在当时高点下方，而区间内金价单边上行 |

用户进一步澄清口径：

> 「策略回测金价可以是美元盎司，我们回测的是我人民币买金当时参考的美元价。口径一致，因为汇率换算人民币波动太大。不需要换算。关键是策略回测数据如何和设置参数关联？」

因此 **币种不动**，本期的唯一命题是「关联」。

## 二、现状：其实关联了 5 项，断在高点

| 设置页参数 | 回测是否读取 | 代码位置 |
|---|---|---|
| 档数（6–10） | ✅ | `gearCount()` |
| 档距（目标均价 / 区间 / α×ATR） | ✅ | `gearBase().d` |
| 各档权重 | ✅ | `planBase()` → `curW()` |
| 总克重 | ✅ 读了，但量纲错 | `totalGrams()` |
| 哪些档是循环档 | ✅ | `isSwingGear()` |
| 手动高点 `H_BASE` | ❌ | 用 `btbHigh()` |
| 自动高点 | ❌ | 同上 |
| 配额下沉开关 | ❌ 另有一套 | `btOpts.realloc` |

**档位价 = `p1Of(H) − i × d`。H 一换，十个档位价整体平移。** 而档位价是用户唯一能一眼对上阶梯页的东西，所以只要 H 不对，其余五项即使全部生效，用户也感受不到。

### 附带发现的两个缺陷

**（1）量纲错误**

```js
var budget = totalGrams() * Number(bars[i0].c);   // 克 × 美元/盎司
```

300g × $2756/oz = $826,800；正确值是 300 ÷ 31.1035 × 2756 = **$26,583**。

同一错误波及 `invest`、`endMV`、`rec`（卖出回款）。`lumpHold = budget / price` 得到的单位是盎司，却和「克」混用。收益率不受影响（分子分母同错），绝对金额全部放大 31.1 倍。

**（2）`planOf()` 把实盘状态带进回测**

```js
var plan = planOf();     // 内部 reallocPlan(base) 无 ctx
```

无 ctx 时它读三样东西：`S.price`（今天金价）、`S.reallocDead`（今天哪些档跌穿）、`gearPrices(gm.he)`（今天高点算的档位）。后果：

- 回测起点还没走，就按今天的状态把额度挪走了（未来函数）
- `reallocPlan` 会写 `S.reallocDead`，回测运行会改动实盘状态

另外，设置页开着下沉时，`plan` 已经下沉过一次，回测开关再下沉一次，**双重下沉**。这是「为什么有两个下沉开关」的答案。

## 三、目标（本期范围）

**A 方案：只读快照 + 高点跟随。** 回测卡不提供就地调参，只如实显示「这次回测用的是哪套参数」，改参数去设置页。

1. **高点默认跟随设置**（`gearBase().he`），可切「当时高点」对照
2. **参数快照条**：来源、高点、档数、档距、配额，一眼可见
3. **档位对照表**：逐档价格 + 克重 + 触及次数，可与阶梯页逐行核对
4. **修量纲**：内部统一 `$/g`，金额回到真实量级
5. **下沉跟随设置**：回测内部改用 `planBase()`，不再读实盘状态
6. **一段人话说明**：这张卡回答什么问题、三组对照怎么读、前视偏差是什么

## 四、非目标

- 不做「就地试算不同参数」（那是不写回设置的 what-if 面板，留待后续）
- 不改币种、不引入汇率
- 不存回测快照（仍是每次现算）
- 不改动实盘的下沉 / 档位逻辑

## 五、设计

### 5.1 参数快照条

位于周期切换下方，一行四段：

```
档位来源   [ 设置 $4432 ]  [ 当时 $2760 ]
8 档 · 档距 $46    配额 300 g    下沉 开（跟随设置）
```

- 两个 chip 切换高点来源，选中态持久化到 `cfg.btOpts.height`（`"set"` / `"then"`）
- 档数、档距、配额只读，点击「档数 / 档距」跳到设置页对应卡片
- 下沉显示当前设置值，后跟「（跟随设置）」

### 5.2 高点来源的语义

| 值 | 取数 | 显示 | 适用 |
|---|---|---|---|
| `set`（默认） | `gearBase().he` | 设置页高点，如 `$4432` | 回答「我这套档位在过去一年会怎样」 |
| `then` | `btbHigh(bars, i0)` | 回测起点前的高点 | 回答「如果当时就用一套档位会怎样」 |

`set` 有前视偏差：用今天的最高点去锚定两年前的行情。这一点必须在卡上写明，不能只在文档里。

若设置高点取不到（无手动值且自动高点失败），自动回退 `then`，并在快照条标注「设置无高点，已回退当时高点」。

### 5.3 档位对照表

替换现有的一行 chip：

```
档1  $3854   40 g   0 次 · —
档2  $3808   45 g   0 次 · —
档3  $3762   50 g   1 次 · 09-12
```

- 价格：`pr[i]`，$ 两位（<1000 时一位）
- 克重：`plan[i]`，g 整数或一位小数
- 触及：`hits[i]` 次 + 最后触及日期；0 次显示「—」
- 已触发档加 `on` 态（沿用现有样式）

### 5.4 金额口径

- 价格：`$/oz`（与行情、阶梯页一致，不换汇率）
- 金额：`$`，由 `克 ÷ 31.1035 × $/oz` 得出
- 卡片注明：`本金 = 总克重 × 起点价 · 美元口径，不折算汇率`

### 5.5 说明文案

卡片底部固定三段：

```
这张卡回答：按你设置页的档位，在一段历史行情里机械买入，结果会怎样。
三组同本金对照：本策略 / 每周定投 / 起点一次性。
档位取自设置（$4432）时存在前视偏差 —— 相当于假设这套档位当时就在用。
```

## 六、验收标准

| # | 标准 |
|---|---|
| 1 | 默认 `height="set"`，档位价与建仓阶梯页逐档相等（±0.01） |
| 2 | 切到 `then` 后，档位价按 `btbHigh` 重算，切回 `set` 复原 |
| 3 | `budget == totalGrams / 31.1035 × 起点收盘价`（±0.5%） |
| 4 | `invest == Σ(plan[i] / 31.1035 × pr[i])`（±0.5%） |
| 5 | 无触发时 `endV == budget`（现金 + 0 市值） |
| 6 | 设置开下沉、回测不勾 → 回测下落；勾选框取消 → 不下沉（真正可控） |
| 7 | 回测运行不修改 `S.reallocDead` |
| 8 | 参数条四项数值与设置页一致 |
| 9 | 档位表行数 == 档数，价格与 chip 一致 |
| 10 | 390 / 320 宽无横向溢出，档位表不截断 |
| 11 | 卡内出现前视偏差说明，且 `height="then"` 时文案切换 |
| 12 | 既有 848 条除 b2/b3/b4 外全部通过（那三条属测试固化错误，同步修正） |

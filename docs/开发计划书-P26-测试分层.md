## 零、问题：反馈周期 15 分钟

改一行 CSS 想确认没崩，代价是 15 分 32 秒。这导致两个后果：

1. 迭代时不敢频繁跑，错误发现得晚，回滚成本变高
2. 发布前跑全量时人会走开，跑完只看最后一行，中间的红容易被忽略

四期开发中已经反复出现：每次定位一个 UI 细节，都要等全量。**这不是测试写得不好，是缺一层「够快但不空」的验证。**

## 一、分层设计

| 层 | 范围 | 目标耗时 | 何时跑 |
|---|---|---|---|
| **冒烟** | 22 条，覆盖 10 个核心域各一条主链路 | **≤ 2 分钟** | 每次改完就跑 |
| **全量** | 762 + 新增 | ~16 分钟 | 每期收尾、发布前 |

冒烟**不是**全量的子集抽样（不做随机抽），而是**按链路挑**：每条都回答「这个功能还活着吗」，而不是「这个功能的第 7 个边界还对吗」。

## 二、批一：配置与冒烟文件

### 2.1 `pytest.ini`

```ini
[pytest]
testpaths = tests
addopts = -q --strict-markers
markers =
    smoke: 核心链路冒烟，2 分钟内跑完
    slow: 超过 3 秒的用例
```

`--strict-markers` 是硬约束：以后谁写了个没注册的 marker，pytest 直接报错，不会静默忽略（静默忽略会让 `-m smoke` 悄悄少跑，是最坏的情况）。

### 2.2 `tests/test_smoke.py`（22 条）

不侵入既有 54 个文件，**新建一个文件**，每条独立构造环境。覆盖矩阵：

| 域 | 条数 | 断言什么 |
|---|---|---|
| 加载 / 首屏 | 3 | `__xt.ready`、现价渲染、无 JS 报错 |
| 档位表 | 3 | 六档行数、计划克重、净持=标记−卖出 |
| 标记与账本同源 | 2 | 标 16g 后账本记 4g → 以记录为准（P15 规则） |
| 减仓摊派 | 2 | 卖 100g 摊到六档、删记录精确退回（P21） |
| 执行复盘 | 2 | 折叠态零扫描、展开六行、无 NaN |
| 策略回测 | 3 | 卡片存在、三组同本金、无 NaN |
| 判定回溯 | 2 | 色带段数、点格子出依据 |
| 设置与保存 | 2 | 改档数生效、保存后刷新仍在 |
| 响应式 | 2 | 320 宽不横向溢出（行情页 + 持仓页） |
| 云端 | 1 | 拉取到配置并渲染 |

**写法要求**：只用 `conftest.py` 的 `make_env` / `env` 公共 fixture，**不 import 其它测试文件的私有 helper**（否则改一个 helper 会同时弄坏两层）。

### 2.3 运行方式

```bash
python3 -m pytest                 # 冒烟 + 全量（默认）
python3 -m pytest tests/test_smoke.py    # 只跑冒烟，≤2 分钟
python3 -m pytest -m "not slow"   # 排除慢用例
```

## 四、验收标准

`tests/test_p26_smoke.py`（元测试，**5 条**）：

| # | 断言 | 说明 |
|---|---|---|
| t1 | `tests/test_smoke.py` 存在，用例数在 18–30 之间 | 太少不覆盖，太多就跑不进 2 分钟 |
| t2 | `pytest.ini` 存在且 `markers` 段包含 `smoke` 与 `slow` | 防配置被删 |
| t3 | 冒烟文件不 `import` 其它 `test_*` 模块 | 独立性 |
| t4 | 冒烟文件覆盖的域 ≥ 8 个（按注释分区 `# ==== 域名 ====` 计数） | 防退化成单域 |
| t5 | `pytest -m smoke --collect-only` 能收集到用例（子进程调用，验证 marker 已注册） | 防 marker 名写错 |

> t5 用子进程跑 `--collect-only`，不真正执行用例，约 3 秒。

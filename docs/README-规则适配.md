# 规则适配 README

> 给要把这套「建仓 / 持仓 / 减仓」规则搬到自己的应用里的人。
> 你不需要照搬代码，只需要照搬**判据**。本文给出一张可勾选的规则清单、一份输入输出契约、一份坑表。

配套细读：`PRD-总览-建仓-持仓-设置.md`（为什么这么定）、`开发计划书-总览-建仓-持仓-设置.md`（怎么分层）。

---

## 1. 先明确你要搬什么

这套产品有五个可独立剥离的"规则包"。按依赖顺序排列，**前面的不做，后面的会算错**。

| 包 | 内容 | 依赖 | 可独立使用 |
|---|---|---|---|
| **A. 仓位账本** | 买卖记录 → 克重/成本/均价/回本价/已实现 | 无 | ✅ 任何记账类应用 |
| **B. 价格分档** | 高点 + 档距 → 每档触发价 | 无（只要一个高点） | ✅ 定投/网格类 |
| **C. 计划分配** | 预算 + 权重 → 每档买多少克 | A（要知道已持）、B | ✅ 需要"跌到哪买多少"的场景 |
| **D. 减仓建议** | 持仓 + 成本 → 止盈阶梯 + 分配克重 | A | ✅ 止盈/再平衡类 |
| **E. 提醒与待办** | 到价 / 止损 / 底仓 → 今天要处理 | A、B、D | ✅ 任何"执行辅助"场景 |

**最小可用组合是 A + B**（能算价、能记账）。C/D/E 可以后加。

**不要移植的**：多周期结构判定、宏观定价、事件雷达。这三块依赖外部数据管线，且与交易规则可完全解耦——用你自己的方向判断替换即可（见 §6）。

## 2. 输入输出契约

### 2.1 输入：一份配置 + 三份数据

```jsonc
// ① 配置（用户可改）
{
  "TOTAL": 100,              // 目标总克重
  "keepGram": null,          // 底仓（克）；null 则按 cutRatio 算
  "cutRatio": 70,            // 减仓比例 %
  "comeback": 10,            // 回本加点（元/克）
  "H_BASE": null,            // 建仓高点 $/oz；null = 自动
  "avgTarget": null,         // 目标均价 $/oz
  "avgBand": 20,             // 命中容差（美元）
  "spanMode": "target",      // alpha | target | range
  "alpha": 1.0,              // 0.6–3.5
  "startDrop": 13,           // 起始跌幅 %
  "endDrop": 25,             // 终止跌幅 %（硬上限）
  "avgAnchor": 0,            // 锚定档位；0 = 自动
  "gearCount": 6,            // 6–10
  "wPct": [8,12,24,36,12,8], // 权重 %
  "swingGears": [1,2],       // 循环档（可反复买卖）
  "stopMode": true,          // 允许成本下方减仓
  "noCap": false,            // 不设仓位上限
  "realloc": {"on":false,"mode":"near","ratio":1,"maxDrop":3}
}

// ② 买入记录
[{"id":"b1","gram":8,"priceCny":931.42,"time":"2026-11-16T05:00:00Z","gear":"第2档","acct":"a0"}]

// ③ 卖出记录
[{"id":"s1","gram":4,"priceCny":1002.10,"time":"2026-11-20T06:00:00Z","acct":"a0","allot":{"2":4}}]

// ④ 档位标记（执行到哪一步）
{"2":{"g":16,"sold":4,"costCny":14890.5,"proceedsCny":6120,"at":1750000000000}}

// ⑤ 行情（只要三个数）
{"priceOz": 4211.67,   // XAU/USD
 "fx": 6.9123,          // USD/CNY
 "atr14": 40.2}         // 日线 ATR（美元）；没有就传 null
```

### 2.2 输出

```jsonc
{
  "hold": {                        // 来自 A
    "grams": 96, "avg": 916.67, "cost": 88000,
    "sold": 4, "realized": 341.7,
    "backPrice": 926.67,           // 均价 + comeback
    "pnl": 2400.5                  // (现价克价 − avg) × grams；汇率缺则 null
  },
  "gears": [{                      // 来自 B + C
    "idx": 1, "name": "第1档", "price": 3664.15,
    "plan": 8, "bought": 0, "pending": 8, "over": 0,
    "state": "waiting"             // waiting | full | over | warn
  }],
  "meta": {                        // 关键中间量，界面要显示
    "he": 4211.67, "highManual": false, "auto": {"win":"D60"},
    "d": 101.08, "alpha": 2.51,
    "target": 3800, "targetEff": 3800, "band": 20,
    "avgAnchor": 3802.4, "anchorK": 4, "hitAnchor": true,
    "deepestPct": -25.0, "capD": 101.08, "clamped": false
  },
  "takes": [{                      // 来自 D
    "name": "+15%", "cnyVal": 1054.2, "dist": 6.1,
    "score": 72, "prob": 18, "cut": 12.0,
    "role": "plan"                 // plan | hit（已到价待核销）
  }],
  "todos": [{                      // 来自 E
    "kind": "buy", "title": "第2档 到价",
    "detail": "可买 12 克 · 触发价 3864.2", "action": "mark_buy:第2档"
  }]
}
```

**契约要求**

- 所有金额单位元，克重单位 g，美元价单位 $/oz。**不许混用**。
- 任何一个数算不出，返回 `null`，**不要返回 0**。前端负责把 `null` 渲染成 `--`。
- `gears[].pending` 与 `over` 互斥（一个 > 0 时另一个必为 0）。

## 3. 规则清单（逐条勾选）

> 每条都是**判据**，不是建议。改数值可以，改方向不行。
> 「不做会怎样」列是这条规则存在的理由——如果你不认同那个后果，才可以不实现。

### A. 仓位账本

| # | 规则 | 判据 | 默认 | 不做会怎样 |
|---|---|---|---|---|
| A1 | 持仓克重 | `Σ买入.gram − Σ卖出.gram`，下限 0 | — | 克重与实际不符 |
| A2 | 持仓成本 | `Σ(买入.gram × 买入.priceCny)` | — | — |
| A3 | **均价分母** | `成本 / Σ买入.gram`（**不是**卖出后余额） | — | 卖过一半的账户均价虚高 |
| A4 | 卖出不改均价 | 只减克重，`avg` 不动 | — | 越卖均价越"好看"，失真 |
| A5 | 已实现盈亏 | `Σ(卖出.gram×卖出.priceCny) − Σ卖出.gram × avg` | — | — |
| A6 | 成本未知 | `costCny = 0` → `realized = null` | — | "不知道赚多少"显示成"不赚不亏" |
| A7 | 回本价 | `avg + comeback` | comeback=10 | — |
| A8 | 回本加点下限 | 夹到 `≥ 0` | — | 手输负数会算出"已盈利 −x" |
| A9 | 距回本 | `(现价克价/回本价 − 1)×100`；<0 绿"还差"，≥0 红"已过" | — | 方向取反，读起来别扭 |
| A10 | 汇率缺失 | 所有人民币派生量 → `null` | — | 用 0 会读成"不要钱" |
| A11 | 旧数据兼容 | 无逐笔但有汇总时用汇总，**仅全账户视图** | — | 筛空账户会显示"历史汇总 100 克" |

### B. 价格分档

| # | 规则 | 判据 | 默认 | 不做会怎样 |
|---|---|---|---|---|
| B1 | 第 1 档 | `p₁ = H × (1 − startDrop/100)` | 13% | — |
| B2 | 第 i 档 | `pᵢ = p₁ − (i−1)×d` | — | — |
| B3 | 自动高点 | 近 60 根日线**收盘价**最高 | D60 | — |
| B4 | 高点降级 | `现价 < h60×0.8` 或 `h60×0.82 > 现价` → 改用 `max(h20, 现价)` | D20 | 单边上涨时第 1 档排到天上，一档都不触发 |
| B5 | 档距·波动率 | `d = α × ATR14` | α=1.0 | — |
| B6 | ATR 缺失 | `base = 1% × H`，界面标「（估）」 | — | 直接算 0 会让所有档重合 |
| B7 | 档距·目标 | `d = (p₁ − T) / c_front`；`c_front` = 前 1..k 档权重重心 | — | 用全档重心会偏离用户意图 |
| B8 | 重心公式 | `c = Σ(wᵢ·i)/Σwᵢ`，i 从 **0** 起 | — | 从 1 起会整体偏 1 档 |
| B9 | 锚定档 k | 显式 2..n 用之；自动 = `round(重心)+1` 夹 `[1,n]` | 自动 | — |
| B10 | 重心为 0 | 返回"档距调不动均价"，退回 α 排法并提示 | — | 除零 |
| B11 | 档距·区间 | `d = (endDrop − startDrop)/100 × H/(n−1)` | — | — |
| B12 | **终止跌幅是上限** | `d = min(名义 d, capD)`，`capD` 同上式 | — | 用户设 −25% 却排到 −27%，钱不够 |
| B13 | 只压不拉 | 未越界时 `min` 取回原值，档位价**一个字节不改** | — | 改终止跌幅会莫名其妙动到已算好的价位 |
| B14 | 两条出口互不串改 | 「改目标」只改 T；「放开终止」只改 endDrop | — | 一个按钮改两个参数，用户无法归因 |
| B15 | 深度可见 | 常驻显示「最深档 −x% · 终止 y% · 余量 z pp」 | — | 改了终止看不到效果 |
| B16 | 高点值域 | 1000–9000（UI 层）；配置层 `> 0` 即可 | — | 手输 42 会让全表变 0 |
| B17 | 对齐写回哪个参数 | `alpha`→写 α；`target`→只放开终止；`range`→写终止 | — | 三种方式都写 α，等于把用户选的模式偷偷换掉 |
| B18 | 对齐不许无动作 | 需要更深就放开终止（≤60%）；超边界按边界落地并报差 | — | 反解比上限深一点就 return，用户点十次参数不变 |
| B19 | α 下限是提示线 | 硬下限 0.1；0.6 只用于「各档会挤」提示 | 0.1 | 先抬到 0.6 再写，写进去的 α 与命中判据对不上 |
| B20 | 夹取阈值按显示精度 | 0.05pp 以内不算夹取 | 0.05pp | 文案出现「需 −26.00% / 收到 −26.00%」 |
| B21 | 有持仓时判整体均价 | 有货且 `T_eff>0` 判 `mix`，反解重心换 `pendingCenter` | `anchor` | 拿不含持仓的锚定均价判命中，永远判不中 |
| B22 | 均价口径用未下沉计划 | `avgAnchor` / `mix` 都按 `planBase` 加权 | — | 下沉一开，同一张卡出现两个差 180 的数 |

## 4. 单位与四则运算

### 4.1 三个"事实"必须分开存

| 事实 | 单位 | 精度 | 谁提供 | 可信度 |
|---|---|---|---|---|
| 克重 | g | 0.1 | 用户 | 事实 |
| 美元价 | $/oz | 0.01 | 用户填的成交价 / 行情 | 事实 |
| 实付人民币 | 元/克 | 0.01 | **用户** | 事实 |
| 折算人民币 | 元/克 | 0.01 | `美元价 × 汇率 ÷ 31.1035` | **估算** |

**这条是整套规则的地基**：折算值会随汇率变，实付值不会。把两者混成一个字段，用户永远对不上账。

界面上必须能区分：估算值带「估」角标，未填显示 `¥ —`。

### 4.2 换算常数

```
1 金衡盎司 = 31.1035 克
人民币克价 = XAU/USD × USD/CNY ÷ 31.1035
美元盎司价 = 人民币克价 × 31.1035 ÷ USD/CNY
```

### 4.3 显示精度

| 类型 | 规则 | 例 |
|---|---|---|
| 克重 | 最多 4 位，**去尾零**，整数不带点 | `8.4570→8.457`、`8.0000→8` |
| 价格 | 2 位 | `4211.67` |
| 人民币克价 | 2 位 | `931.42` |
| 金额 | 0 位（大额）/ 2 位（浮盈） | `¥58,320` |
| 缺失 | `--` / `—` / `¥ —` | **永不用 0 代替** |

### 4.4 颜色（与欧美相反）

| 场景 | 正 | 负 | 平 |
|---|---|---|---|
| 价格 / 涨跌 / 浮盈 | **红** | **绿** | 灰 |
| 距回本 | 已过 = 红 | 还差 = 绿 | 灰 |
| 宏观对金影响 | 利多 = 红 | 利空 = 绿 | 平盘 = 灰 |

后两行不是"涨跌"：距回本取反过一次，宏观是"对金价的影响"。**不要统一成一套涨跌色**。

## 5. 十二个坑（按踩坑代价排序）

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | 均价分母用卖出后余额 | 卖过一半的账户均价虚高 | 分母恒为 Σ买入克重 |
| 2 | `costCny=0` 当 0 处理 | "不知道赚多少"→"不赚不亏" | 返回 `null`，显示 `¥ —` |
| 3 | 空仓时夹底仓到 0 | 输入框 20、引擎 0、永远判脏 | 空仓只 `max(0,v)`，不夹上限 |
| 4 | 派生显示参与脏值判定 | 买入一笔就冒"未保存" | 只认真实输入事件 |
| 5 | 计划层写死 `TOTAL` | 待补凭空多一截 | 扣未标档持仓 |
| 6 | 已标档持仓再扣一次预算 | 已买满的档标"已买超" | 只扣未标档 |
| 7 | 下沉无滞回 | 价格抖动时额度来回搬 | 跌破 1% 进、回 0.3% 出 |
| 8 | 摊派先摊新后退旧 | 双重累加，克重越改越多 | 先退旧、再摊新 |
| 9 | 卖出换账户时把原克重加回 | 可卖出超过新账户持仓 | 换账户时退回量置 0 |
| 10 | 到价待核销整笔照搬 | 提示减 28.3g，实际剩 5g | 以剩余持仓封顶 |
| 11 | 止损开关只改选位 | 旧计划仍可点，一点就亏损卖出 | 选位 + 核销两条路径都过滤 |
| 12 | 空态分支不绑筛选条 | 筛到空账户后回不到"全部" | 三个空态都先渲染筛选条 |

## 6. 你可以替换掉的部分

以下四块与交易规则解耦，可以直接用你自己的实现换掉，规则包仍然成立。

| 可替换 | 本产品的做法 | 替换要求 |
|---|---|---|
| **方向判断** | 多周期共振（周线背景 / 日线方向 / 4h 节奏 / 1h 触发） | 只需提供 `dir ∈ {up, dn, rg}` 与 `adx`。缺失时传 `rg`，止盈评分会自动落到"震荡"分支，规则仍可用 |
| **高点来源** | 近 60 根日线收盘最高（可降级 20 根） | 只要求"一个高位参照"。可用前高、可用用户填、可用 52 周高 |
| **技术位** | 枢轴 / 斐波 / 均线 / 箱体 / 摆动高 | 只要求"现价上方的一组价位 + 各自指认数"，强度公式不变 |
| **触发概率** | 四点实测表 | 可换你自己的统计表，但**不要插值** |

**唯一不可替换的是 A（仓位账本）的口径**。均价、成本、已实现这三个数一旦换了口径，后面全部对不上。

### 6.1 没有行情源怎么跑

只填 `priceOz` 与 `fx` 就能跑通 A、C、D、E 四条链。

- 档位价（B）只需一个高点，可以手填。
- 止盈位（D）若没有技术位，只用 `成本 +15/20/25/30%` 也能选出 4 个位，评分会偏低但可用。
- 触及概率（D21）无 ATR 时传 `null`，该列显示 `--`，不影响分配。

## 7. 适配步骤

### 第一步：对齐账本（半天）

1. 建两张表：`buys`、`sells`，字段严格按 §2.1。
2. 实现 `holdStats`：克重、成本、均价、已实现。**先写测试再写实现**，用 §8 的 A 组用例。
3. 界面上把均价与回本价并排显示。

此时你已经能回答"我赚多少"。

### 第二步：对齐分档（半天）

1. 实现 `p1 = H×(1−startDrop/100)` 与 `pᵢ = p₁−(i−1)d`。
2. 先只做 `alpha` 一种档距（最简单，`d = α×ATR`）。
3. 加"终止跌幅上限"（`min(d, capD)`）。

此时你已经能回答"跌到哪买"。

### 第三步：对齐计划（1 天）

1. 实现 `planBudget` + `planᵢ = B×wᵢ/Σw`。
2. 加三态标签（待补 / 已买满 / 已买超）。
3. 加"净持仓 = g − sold"。

此时你已经能回答"这一档还差多少克"。

### 第四步：对齐减仓（1–2 天）

1. 候选位只做「成本 +15/20/25/30%」四个，先跑通。
2. 加评分与门槛（`score≥50` 且 `dist≥1.5%`）。
3. 加底仓与 0.1g 整数分配。
4. 再加技术位、间距、断层截断。

此时闭环成立。

### 第五步（可选）：提醒与设置体验

待办六类、角标、脏值浮条。这些是体验层，不影响数字正确性。

## 9. 一张图看清数据流

```
用户填参数 ──┐
             ├─→ cfg ──┬─→ B 价格层（H, startDrop, spanMode, α）──→ 档位价[]
用户记买卖 ──┤         ├─→ C 计划层（TOTAL, w, noCap）───────────→ 计划克重[]
             └─→ 记录 ─┴─→ A 账本（buys, sells）──→ 克重/均价/已实现
                              │
                              ├─→ D 减仓（成本, 底仓, 技术位）──→ 止盈阶梯[]
                              └─→ E 待办（档位价, 计划, 止盈）──→ 今天要处理[]
```

**单向依赖，无环**。任何一环的输入变了，下游重算即可，不需要"撤销逻辑"——这正是把配额下沉做成**派生量**（`planOf()`）而不是改配置的原因：价格回弹、关掉开关，自动回到原值。

## 10. 术语表

| 术语 | 含义 |
|---|---|
| **档位（gear）** | 一个预设买入价位，从高点往下排，第 1 档最高 |
| **建仓档 / 循环档** | 只买不卖（拉低均价） / 可反复买卖 |
| **待补（pending）** | `计划克重 − 净持仓`，还差多少没买 |
| **已买超（over）** | 净持超过计划克重 |
| **锚定均价** | 只买前 1..k 档的加权均价，是"对齐目标"的第一对象 |
| **底仓（keep）** | 涨到目标也不卖的克重，用于保留复利 |
| **下沉（realloc）** | 跌破的档把待补额度让给现价附近的档 |
| **兜底（drip）** | 深档等太久后按现价买一部分 |
| **摊派（allot）** | 一笔卖出按各档净持占比拆到各档标记上 |
| **核销（hit）** | 价格已越过某止盈位，但还没在账本里记减仓 |
| **换日（trade day）** | 国际现货盘以**纽约 17:00** 为日界，不是 UTC 零点 |
| **D60 / D20** | 自动高点用的日线窗口（60 根 / 20 根） |

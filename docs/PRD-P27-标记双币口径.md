## 一、问题：标记层的钱只有美元，用户填的却是人民币

现在的标记面板长这样：

```
本次买入（g）        成交价 $/oz
26.4                 3919.37
本次金额
$3326.68                        ← 只读，系统算的
```

三处不对：

| # | 现象 | 为什么不成立 |
|---|---|---|
| 1 | 「本次金额」是**只读的美元**，由 `克重 ÷ 31.1035 × 价` 算出 | 用户银行扣的是人民币，金额和克重×金价永远对不上（点差、手续费、汇率点差） |
| 2 | 人民币金额只能靠 `S.fx`（**当前**汇率）反推 | 8 月买的 200g，11 月改一次代码，成本就跟着今天的汇率变了。历史成本不该随当下汇率浮动 |
| 3 | 阶梯表的已实现差价写成 `+1234 / 1.2 轮` | **没有币种**。用户默认读成人民币，实际是美元，差 7 倍 |

第 2 条是最要命的：一旦某档的美元成本被当前汇率折算过，它就不再是「我那天花了多少钱」，而是「按今天的汇率，我那天大概花了多少钱」。后者没有意义，却长得像事实。

---

## 二、根因

`markBuy(i, deltaG, px)` 只收两个数：克重和 `$/oz`。金额是**推导**出来的，所以系统里根本不存在「实付人民币」这个事实，只有一个能被任意汇率重算的美元数。

要修的不是显示，是**字段**。

---

## 三、口径：一次成交是三个独立事实

> **克重、当时的美元价、实付人民币 —— 三者互不推导。**

| 事实 | 谁来提供 | 用来干什么 |
|---|---|---|
| 买了多少克 | 用户 | 计划额度、持仓、摊派 |
| 当时美元价多少 | 用户（默认档位价） | 只用于和档位价比「买贵了还是买便宜了」 |
| 花了多少人民币 | 用户 | **所有钱的口径**：成本、盈亏、每克拉低 |

**规则一：人民币是唯一统计口径。** 页面上任何一个「钱」的数字都是 ¥，包括已实现盈亏、每克拉低。

**规则二：美元价不参与任何货币换算。** `$3919.37/oz` 只和 `$4089/oz`（档位价）比较，比完就结束。它不再乘克重变成「美元金额」再乘汇率变成人民币 —— 那条链路整条删掉。

**规则三：老数据不猜汇率。** 能精确知道的自动补（账本记录的 `priceCny` 是元/克，`克重 × priceCny` 就是真实人民币，不需要汇率）；不能知道的留空，标「未填」，不伪造。

### 3.1 字段

`cfg.gearMarks[i]` 从四数扩到六数：

| 字段 | 含义 | 单位 | 来源 |
|---|---|---|---|
| `g` | 累计买入克重 | g | 用户填 |
| `costCny` | **累计实付人民币** | ¥ | 用户填（主口径） |
| `cost` | 累计买入美元金额（Σ 克→盎司 × 价） | $ | 由 `$/oz` 推导，**仅供算 $/oz 均价** |
| `sold` | 累计卖出克重 | g | 用户填 |
| `proceedsCny` | **累计卖出到账人民币** | ¥ | 用户填（主口径） |
| `proceeds` | 累计卖出美元金额 | $ | 由 `$/oz` 推导，仅参考 |
| `at` | 最后更新时间 | ms | 系统 |

`cost` 保留但不升级为主口径 —— 它是 `$/oz` 均价的唯一来源（`cost / g × 31.1035`），而「买贵了 3.2%」这个判断必须用同一币种的价去比。

### 3.2 派生量

| 量 | 公式 | 备注 |
|---|---|---|
| 人民币均价 | `costCny / g` | ¥/g，面板与档位卡显示 |
| 美元均价 | `cost / g × 31.1035` | $/oz，**只在有 cost 时**，否则「—」 |
| 已实现盈亏 | `proceedsCny − sold × costCny / g` | ¥；`costCny = 0` 时返回 `null`（未知，不是 0） |
| 每克拉低 | `Σ已实现 / 净持` | ¥/g，替换掉原来的 `$/oz` 口径 |

**为什么已实现是 `null` 而不是 0**：成本未知时算出 0，等于告诉用户「不赚不亏」。这与「不知道」是两件事，后者必须显示「—」。

## 四、面板改造

### 4.1 买入 Tab

| 项 | 现在 | 改为 |
|---|---|---|
| 第一行 | 本档计划 26.4g　当前净持仓 0g | 本档计划 26.4g　净持 0g　**本档已填 ¥0 / 0g** |
| 本次买入（g） | 默认待补 | 不变 |
| 成交价 $/oz | 默认档位价 | 不变，label 加小字「仅记录，不折算」 |
| 本次金额 | 只读 `$3326.68` | **可填 `¥`，默认见 4.3，必填** |
| 底部说明 | 「填本次成交克重，会累加到该档…」 | 加一句「金额按银行实际扣款填，不按汇率折算」 |

### 4.2 卖出 Tab

| 项 | 现在 | 改为 |
|---|---|---|
| note | 净持仓 X g　买入均价 $4089/oz | 净持 X g　成本 **¥905.2/g**（$4089/oz）　已实现 **+¥1,234** |
| 本次金额 | 只读 `$` | **可填 `¥`（本次到账），必填** |

卖出金额同样是人民币。之前「持仓页记一笔」的卖出本来就是人民币（克重 + 元/克），这次是把标记面板的卖出拉到同一口径，两个入口终于说一种话。

### 4.3 默认值：沿用本档单价，不引入汇率

| 情况 | 金额默认值 | 副标 |
|---|---|---|
| 本档已有 `costCny > 0` | `round(costCny / g × 本次克重, 2)` | 「沿用本档 ¥905.20/g」 |
| 本档没有人民币成本 | 空 | placeholder「按实际扣款填」 |

默认值来自**用户自己上次填的单价**，不是汇率换算。改克重时金额跟着重算（输入即算），用户改价时不动金额 —— 金额是最终事实，不该被别的输入覆盖。

### 4.4 隐性体检：隐含汇率（只提示，不落库）

三个数都填了之后，可以反推一个「隐含汇率」：

```
隐含汇率 = 实付人民币 ÷ (克重 ÷ 31.1035 × 美元价)
```

它**不参与任何计算、不写入任何字段**，只在偏离当前汇率超过 **10%** 时显示一行灰字：

> 隐含汇率 ¥1.00/$（当前 ¥7.10）· 确认金额不是美元？

> **阈值为什么是 10% 而不是 2%**（落地时改的）：购汇时点的汇率与点差本来就有 2~4% 的正常差异，
> 2% 会让这条提示在正常数据上常驻，等于没有提示 —— 第一版就是这么写的，截图时才发现。
> 10% 仍然抓得住真正的错误：把 `$3326` 填进人民币框（隐含汇率 ≈ 1.00）、或多打一个零（≈ 70）。

这一条的价值在截图那个场景：用户把 `3326.68`（美元）填进人民币框，隐含汇率会算出 1.00，立刻红脸。没有它，这笔错的成本会安静地留在数据里，直到某天复盘时发现「每克拉低 ¥4000」。

## 五、关联口径打通（§二说的「统一规则」）

标记层的钱一旦变人民币，所有读它的地方必须同时改，否则会出现「成本是人民币、盈亏是美元」这种半拉子：

| # | 位置 | 现在 | 改为 |
|---|---|---|---|
| 1 | `gearRealized()` | `proceeds − sold × cost/g`（$） | `proceedsCny − sold × costCny/g`（¥，未知返回 null） |
| 2 | `gearState().realized` | $ | ¥ |
| 3 | `computeGears().realized` | $ | ¥ |
| 4 | `computeGears()` 新增 `costCny` / `avgCny` | 无 | 供档位卡与面板读 |
| 5 | 阶梯表循环档标签 | `+1234 / 1.2 轮` | `+¥1,234 / 1.2 轮`；成本未填时 `¥ — / 1.2 轮` |
| 6 | `markBuy` / `markSell` | 只收 `px` | 加可选第 4 参 `cny`（UI 必传，JS 调用可省） |
| 7 | `allotSell()` | 只累加 `proceeds` | 同时按比例累加 `proceedsCny` |
| 8 | `unallotSell()` | 按 `q/sold` 退 `proceeds` | 同时退 `proceedsCny`（同比例，保持与现状一致） |
| 9 | `markGear()` 减少分支 | 按比例折 `cost` | 同时折 `costCny` |
| 10 | `recalcGears()` 重排 | 写 `cost`（档位价估） | 沿用 `old.costCny`，没有就 0 |
| 11 | `syncMarksFromBuys()` | 用 `cnyToUsd(priceCny)` 折美元 | **加写 `costCny = Σ 克重 × priceCny`**（无需汇率） |
| 12 | `rvSum().perOz` | `realized / net × 31.1035`（$/oz） | 改 `perGram = realized / net`（¥/g） |
| 13 | 执行复盘页脚 | `已实现 $1,234 · 每克拉低 $12/oz` | `已实现 ¥1,234 · 每克拉低 ¥3.9/g` |
| 14 | `dripInfo().amt` | 美元金额 | 人民币金额（无本档单价时 `null`） |
| 15 | `cleanGearMarks()` | 四数补齐 | 六数补齐，`costCny` 不补值（不猜） |
| 16 | `schemaVersion` | 1 | **2**，`runMigrations` 加 v2：从账本补 `costCny` |

第 11 与第 16 是这次最省事的一环：账本记录的 `priceCny` 是元/克，`克重 × priceCny` 就是**真实**人民币成本，不需要任何汇率。所以老用户里「记过账」的那批，人民币成本能一次性补准。

## 六、老数据

| 数据来源 | `costCny` 能不能补 | 处理 |
|---|---|---|
| 账本 `buys[].priceCny`（带档位） | **能，精确** | v2 迁移自动补 |
| `gearsDone` 名单（只有档名） | 不能 | 留 0，标「未填」 |
| 纯手工标记（老四数） | 不能 | 留 0，标「未填」 |
| 迁移时用过 `S.fx` 折出来的 `cost` | 能保留 | `cost` 原样留着，`$/oz` 均价继续可用 |

「未填」在界面上是这样：阶梯表该档已实现位置显示 `¥ —`，执行复盘页脚显示 `已实现 —`，档位卡成本位显示 `—`。不写 0，不猜。

用户随时可以在标记面板补一笔（金额填 0 不算补，必须 > 0），补完立刻参与统计。

## 七、非目标

| 不做 | 为什么 |
|---|---|
| 改「持仓 · 记一笔」 | 它本来就是人民币（克重 + 元/克），是这次要统一到的目标形态 |
| 存汇率快照 | 换算是错的解法，不是缺数据。存了快照仍然在猜（用户实际结汇价 ≠ 中间价） |
| 多币种 / 美元账户 | 用户只有一个钱包，人民币 |
| 改回测（`btBack`） | 回测是「假如按这套参数买」的模拟，本来就是美元口径，与真实成交无关 |
| 自动抓银行流水 | 超出单文件应用边界 |
| 校验「金额 ÷ 克重」的合理性（硬拦） | 只提示不拦（§4.4）。用户的真实成交价可以离谱（含大额手续费、议价） |

## 八、边界与异常

| 情况 | 行为 |
|---|---|
| 金额留空 / 0 / 负数 | 拒绝保存，toast「请填本次实付金额（¥）」 |
| 金额填了但克重为 0 | 拒绝（克重先校验） |
| 隐含汇率偏离 > 10% | 灰字提示，**不拦** |
| `costCny = 0` 但有卖出 | 已实现返回 `null` → 显示「—」，不显示 0 |
| 只填金额不填 `$/oz` | 拒绝（`$/oz` 仍必填 —— 它是唯一能算偏差的价） |
| 老数据 `cost = 0`、`costCny > 0` | `$/oz` 均价显示「—」，人民币统计正常 |
| 撤销标记 | 六个字段一起清（现状如此，保持） |
| 摊派卖出后反摊 | `sold` / `proceeds` / `proceedsCny` 同比例退，`g` / `cost` / `costCny` 不动 |

## 九、验收标准

| # | 断言 | 判据 |
|---|---|---|
| a1 | 面板金额可编辑且是人民币 | `#markAmt` 无 `readonly`，前缀 `¥` |
| a2 | 金额留空时保存被拒 | toast 含「实付金额」，标记数不变 |

## 十、待拍板（附我的推荐）

| # | 问题 | 选项 | 推荐 |
|---|---|---|---|
| 1 | 金额必填还是可选？ | 必填 / 可留空只记克重 | **必填**。留空会让「未填」变成常态，统计长期缺数；必填只疼一次 |

| 4 | `$/oz` 还必填吗？ | 必填 / 可省 | **必填**。没有它就没有「买贵了多少」的判断，而这是复盘的全部意义 |

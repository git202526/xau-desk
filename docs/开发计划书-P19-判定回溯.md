## 一、可行性复核

### 1.1 判定是纯函数

`judgeOne(bars)` 只读 `bars` 的最后一根，不碰全局 `S`、不写状态。所以「第 i 天的判定」= `judgeOne(bars.slice(0, i + 1))`，天然可复现。

### 1.2 预热边界

`judgeOne` 内部要 `sma(bars, 200, i)`，以及 `i-39` 起的 20 根高低点。实测安全起点是 `i >= 209`（长度 ≥ 210）。所以：

```
可回溯点数 = 总根数 − 209
日线 800 → 591；4h 750 → 541；1h 1000 → 791；周线 220 → 11
```

PRD 里写的 590 / 540 / 790 / 10 是「约数」，实现按 `总根数 − 209` 精确算，页面显示精确值。

### 1.3 用原始序列，不用缩放序列

结构页当前判定走 `scaled(k)`（会乘汇率折算系数 `S.scale`）。回溯**必须走原始 `S.kl[k]`**。

依据：`judgeOne` 的五条条件全是「大小关系」和「比例」，线性缩放不改变真假：

| 条件 | 缩放后 |
|---|---|
| 收盘 vs MA20 | 两边同乘 k，不等号方向不变 |
| MA5 vs MA20 | 同上 |
| MA20 拐头 | 同上 |
| 20 根高低点抬高 / 下移 | 同上 |
| ADX ≥ 20 且 DI 占优 | 纯方向指标，与价格量纲无关 |

所以两者结论必然一致，但用原始序列可以保证「回溯结果不随汇率开关变化」。这条要写成测试锁住（§5 第 12 条）。

## 二、计算层

### 2.1 新增函数

```javascript
/* 可回溯窗口：{from, to, n, need}；数据不足返回 null */
function btWindow(k)

/* 序列：Array<{i, t, state, hits, names}>；i 是原始索引 */
function btRun(k)
```

`btWindow`：

- `bars = S.kl[k]`，为空或长度 < 210 → `null`
- `start = 209`、`n = bars.length − 209`
- `from = bars[start].t`、`to = bars[bars.length-1].t`

`btRun`：

- 逐 i 从 `start` 到末尾，`r = judgeOne(bars.slice(0, i+1))`
- `state = r.state`（`up` / `rg` / `dn`）
- `hits`：`up` 取 `r.upN`，`dn` 取 `r.dnN`，`rg` 取 `max(r.upN, r.dnN)`
- `names`：命中条件的 `k` 文本（最多 3 个，其余用「等 n 条」概括），用于点选展开

### 2.2 缓存

```javascript
var _btCache = {};   // key → { seq, at }
```

key = `k + "|" + bars.length + "|" + bars[0].t + "|" + bars[bars.length-1].t + "|" + bars[bars.length-1].c`

命中直接返回同一数组（只读使用，不 mutate）。缓存不落盘，页面刷新即失效——序列是纯派生数据，没必要存。

### 2.3 性能

`590 × judgeOne`，每次 `slice` 平均 400 个元素 + 内部 MA200 / MACD / ADX 全量扫。

预估 80–250ms。**先同步跑，实测再决定要不要分帧**：

- 日线 < 200ms → 同步，不引入异步复杂度
- ≥ 200ms → `requestAnimationFrame` 每帧 50 个点，先画骨架再填色带

计划书里不预先分帧，避免为了可能不存在的性能问题写异步。

### 2.4 派生统计（不进缓存，渲染时现算）

```javascript
function btStats(seq){ /* {up, rg, dn, total, pctUp, pctRg, pctDn, switches:[...]} */ }
```

- 占比：三者按 `round` 后做尾差修正，把差的百分点补给天数最多的一档，保证合计 100%
- `switches`：相邻 `state` 不同处，记 `{i, t, from, to}`

### 3.1 插入位置

```

```

### 3.2 结构

```html
<div class="sech"><h2>判定回溯 <span class="cnt" id="btMeta">—</span></h2></div>
<div class="card" id="btCard">
  <div class="fchips" id="btChips"> 周线 / 日线 / 4小时 / 1小时 </div>
  <div class="btwin" id="btWin">—</div>          <!-- 可回溯区间 + 天数 -->
  <div class="btstrip" id="btStrip"></div>        <!-- 横向滚动的 SVG 色带 -->
  <div class="btpick" id="btPick" hidden></div>   <!-- 点选结果，单行 -->
  <div class="btdist" id="btDist"></div>          <!-- 三行分布 -->
  <div class="btsw" id="btSw"></div>              <!-- 切换记录 -->
</div>
```

### 3.3 色带：按连续段合并，不是每天一个 rect

590 天每天一个 rect，宽 0.6px，既点不准也浪费节点。改为**同色连续段合并**：

```
扫一遍 seq，相邻同 state 的合并成一段 → 通常 20–40 段，而不是 590 段
```

- 每点像素 `PX = 1.5`（`1h` 791 点 → 1186px）
- 总宽 `W = max(容器宽, n × PX)`
- 外层 `overflow-x: auto`，挂载后 `scrollLeft = scrollWidth`（默认看最近）
- 段 rect：`x = (startIdx × PX)`，`width = (len × PX)`，`fill` 按 state

颜色映射：

| state | 变量 | 值 |
|---|---|---|
| up | `--up` | `#E5484D` 红 |
| rg | `--tx3` | `#657993` 灰蓝 |
| dn | `--dn` | `#2FA36B` 绿 |

> 与整站一致：红涨绿跌。灰用 `--tx3` 而不是纯灰，暗色底上更稳。

### 3.4 点选

点色带任意位置：

```javascript
var x = e.clientX - rect.left + strip.scrollLeft;
var idx = Math.min(n - 1, Math.max(0, Math.floor(x / PX)));
```

结果写到 `#btPick`，一行：

```
2026-05-12 · 下行 · 命中 4/5（收盘跌破 MA20、MA20 拐头向下、-DI 占优）
```

选中段加 1px 描边（`.sel`），再点别处就换。切周期时清空选中与 `#btPick`。

### 3.5 分布与切换记录

分布三行，`上行 312 天 · 53%` 这种格式，色块小圆点前置。

切换记录：

- 默认渲染最近 5 条，多于 5 条时出「展开全部 (23)」按钮
- 每条 `10-28　震荡 → 上行`（同年只显示 MM-DD）
- 0 条时渲染「区间内方向未发生切换」
- 展开状态存内存变量，不落盘

### 3.6 底部提示

按 PRD §4.7：

| 当前周期 | 提示文案 |
|---|---|
| 周线 | 周线数据只有 220 根，可回溯约 10 周 |
| 日线 / 4小时 / 1小时 | 四周期共振的回溯受 1 小时数据限制，最多 33 天。想看更长的方向轨迹，请用日线。 |

### 3.7 刷新入口

`refreshAll()` 里新增一行 `renderBt();`，排在 `renderChart()` 之后（两者无互调，符合单向调用）。

`renderBt()` 内部只读 `S.kl` 与 `S.btPeriod`，不调用任何其他渲染函数。

## 八、风险与取舍

| 风险 | 应对 |
|---|---|
| 590 次判定卡住主线程 | 先测实耗；>200ms 再分帧（每帧 50 点），不预先异步化 |
| `slice` 复制开销（590 × 平均 400 元素） | 实测可接受；若成瓶颈，改成传「长度」给判定（需改 `judgeOne` 签名，本期不做） |
| 色带 1.5px/点在手机上太细看不清 | 段合并后是色块不是细线；点选靠 x 反算，不要求点中单个像素 |
| 结构页变长 | 卡片内部高度可控（色带 28px + 统计 3 行 + 记录 5 行 ≈ 260px） |

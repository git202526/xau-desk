# 开发计划书 · P6 循环档（v1.0）

> 依据：`开发计划书-P5-单引擎重写.md` §13.2–13.3 的结论。
> 起点：v6.18 已上线，`cfg.gearMarks = { "1": {g, at} }`，只有「累计已买」一个数。
> 本期把它扩成四数，并开放「卖出」——**只对浅档开放**。

---

## 0. 一句话

**第 1/2 档改成循环档：买 16g → 反弹卖掉 → 额度释放 → 再跌再买，同一笔钱反复周转；第 3–6 档是建仓档，买了不卖。卖出只动计划层，不动账本。**

---

## 1. 为什么做这个

P5 §13.1 已经把问题量化过，这里只保留结论：

| 只买到 | 累计仓位 | 累计均价 | 还需再跌 | 40 日内概率 |
|---|---|---|---|---|
| 第 2 档 | 40 g | 4045 | −0.4% | ~55% |
| 第 3 档 | 88 g | 3988 | −2.2% | ~35% |
| 第 4 档 | 160 g | 3934 | −4.0% | ~24% |
| 第 6 档 | 200 g | 3900 | −7.7% | **13.6%** |

> 只有 −7.7% 一行是实测（回测表 −8% 点），其余是插值估算，只说明量级。

买满 6 档 40 天内只有 13.6% 概率。剩下 86% 的时间，仓位停在 88–160g，**浅档那 40g 买完就闲置了**。

用户的原话是：「一直不到 4/5/6 档，还不是需要在 1/2/3 反复操作。」

P5 的答案是**不许在浅档加仓**（会把子弹打光）。P6 补上另一半：**让同一笔钱在浅档反复用**。

---

## 2. 边界：本期做什么、不做什么

### 做

| 项 | 说明 |
|---|---|
| `gearMarks` 四数结构 | `{g, cost, sold, proceeds, at}` |
| 循环档角色 | `cfg.swingGears = [1,2]`，设置页可调 |
| 卖出面板 | 与买入同一个面板，顶部两个 Tab |
| 已实现差价 | 档位行尾 `+42 / 1.0 轮` |
| 额度释放 | 卖出后 `pending` 自动变大，可再次买入 |

### 不做（明确划出去，避免范围膨胀）

| 项 | 理由 |
|---|---|
| **不自动交易** | 虚拟计划，系统不下单 |
| **不改档位价** | 卖出不触发任何价格重算（延续 P5 铁律） |
| **不写 `buys[] / sells[]`** | 计划层与账本层互不干涉；实际成交请到「持仓」页记一笔 |
| **不做全局收益统计** | 已实现差价只显示在档位行，不进顶部卡片、不进账本汇总 |
| **不做税费/手续费** | 量级太小（单笔 42 美元），加了反而干扰判断 |
| **不做建仓档卖出** | 3–6 档买了不卖，这是策略的核心 |

> **为什么卖出不写账本**：账本 `buys[]/sells[]` 决定的是「真实持仓与成本」，计划层 `gearMarks` 决定的是「计划执行到哪一步」。两者混在一起会出现双重计数 —— 卖 16g 既减少账本持仓、又释放计划额度，`mix` 的整体均价会算错。P5 的 `markGear` 已经定了这个规矩，P6 沿用。

## 3. 数据模型

### 3.1 结构变更

```js
// P5（现状）
cfg.gearMarks["1"] = { g: 16, at: 1761753600000 }

// P6（本期）
cfg.gearMarks["1"] = {
  g: 16,           // 累计买入克重
  cost: 2103.43,   // 累计买入金额（美元）
  sold: 16,        // 累计卖出克重
  proceeds: 2145,  // 累计卖出金额（美元）
  at: 1761753600000
}
```

> **单位换算别搞错**：金价是 `$/oz`，克重要先除 `31.1035` 才是盎司。
> `16g @ 4089` = `16 / 31.1035 × 4089` = **2103 美元**，不是 `16 × 4089 = 65424`（那是「克·美元/盎司」，无意义量纲）。
> 常量统一用 `OZ_PER_G = 31.1035`，写成 `function gramToUsd(g, px){ return g / OZ_PER_G * px; }`。

### 3.2 新增配置

```js
cfg.swingGears = [1, 2];   // 循环档，可多选；默认 1/2
```

校验规则（写在 `normCfg()` 里）：

- 非数组、空数组 → 回 `[1, 2]`
- 元素转数字后过滤 `1–6` 之外的、去重、升序
- 全部非法 → 回 `[1, 2]`
- **允许为空数组**（= 关闭循环档功能，全部按建仓档处理），此时 UI 隐藏「卖出」Tab
- 包含 3–6 时不报错，但设置页给一行提示（见 §5.3）

### 3.3 迁移（老数据零丢失，且**不改写**老数据）

分成两半，只有一半需要写：

```js
// ① cleanGearMarks 里补齐这两个 —— 不需要价格，纯结构
if(m.sold === undefined)     m.sold = 0;
if(m.proceeds === undefined) m.proceeds = 0;

// ② cost 不迁移、不写回，计算时兜底
function gearCost(i, m, px){           // px = 该档档位价
  var c = Number(m.cost) || 0;
  if(c > 0) return c;
  return (m.g > 0 && px > 0) ? gramToUsd(m.g, px) : 0;
}
```

**为什么不给 `cost` 补值写回**：`cleanGearMarks()` 拿不到档位价（它只处理标记数据，不参与定价），硬补就得把 prices 传进去，污染这条纯清洗函数的职责。而兜底函数只在 `realized` 计算时需要一次，成本几乎为零。

老标记的 `realized` 因此是**按档位价估算**的 —— 只影响差价绝对值，不影响 `net / pending / turns`。UI 上给老标记加一枚 `估` 字角标，新标记（带真实成交价）不加。

迁移是幂等的：`sold/proceeds` 补 0 之后重复执行无变化；`cost` 根本不动。

## 4. 计算规则

### 4.1 派生量

```js
net[i]      = g − sold                        // 本档当前净持仓
pending[i]  = max(0, plan[i] − net[i])        // 还能再买多少
realized[i] = cost > 0 ? (proceeds − sold × cost / g) : 0   // 已实现差价（$）
turns[i]    = plan[i] > 0.05 ? sold / plan[i] : 0           // 周转次数
```

- `g === 0` 时 `realized` 直接返回 0（避免 0 除）
- `realized` 可以为负（卖亏了），显示时带负号，颜色走 `warn`
- `turns` 只有 1 位小数（`1.0 轮` 比 `1.00 轮` 好读）

### 4.2 `boughtOf()` 语义变更

```js
// P5
return m.g;

// P6
return Math.max(0, (Number(m.g) || 0) - (Number(m.sold) || 0));
```

**这是本期唯一的语义反转，必须全链路核对调用方**：

| 调用点 | 影响 | 处理 |
|---|---|---|
| `gearState().bought` | 变成净持仓 | 同时新增 `gross`（累计买入）、`soldG`、`realized`、`turns` 四个字段 |
| `gearState().pending` | 卖出后自动变大 | 正确行为，无需改 |
| `gearState().over` | 按净持仓算超买 | 正确（卖完就不超了） |
| `planSummary().bought` | 变成净持仓合计 | 另外加 `grossBought / soldTotal / realizedTotal` |
| `planSummary().done` | `pending <= 0.05` | 不变；但卖出后 `done` 会翻回 `false`，这正是要的 |
| `renderLadder` 的 `boughtG > 0.05` 判断 | 卖完后按钮回到「标记已买」 | 正确 |
| `ammoTxt` 弹药进度 | 跟着净持仓走 | 正确（卖掉就腾出弹药） |
| `mix` 整体均价 | `Σpending` 会因卖出变大 | **需要改**，见 §4.4 |

### 4.3 买入 / 卖出 API

```js
/* 买入 —— 增量语义。面板里填 8 就是「这次买 8g」，累加。
   px 缺省用本档档位价。 */
markBuy(i, deltaG, px)      // g += deltaG;  cost += gramToUsd(deltaG, px)

/* 卖出 —— 增量语义，累加到 sold 上。 */
markSell(i, deltaG, px)     // sold += deltaG;  proceeds += gramToUsd(deltaG, px)

/* 兼容壳 —— 绝对值语义，保持 P5 行为不变。
   老调用点（saveMarkGear、测试钩子）传的是「把累计买入设成 g」，不是增量。
   内部用 diff 转成增量，这样 cost 也能按比例增减而不是被覆盖。 */
markGear(i, absG)           // delta = absG − 当前 g → 走 markBuy 或折算撤销
unmarkGear(i)               // 删除该键（g / cost / sold / proceeds 一起清）
```

> **`markBuy` 是增量、`markGear` 是绝对值，这两个必须在注释里写死。** P5 的 `markGear` 从上线起就是「设置累计值」（`gearMarks[i] = {g: 你填的数}`），p47 测试里「二次标记」验的就是这个；而面板上的「买入」按钮天然是增量（填 8 = 再买 8）。混用会让用户点两次「买入 8g」得到 8g 而不是 16g。

**卖出校验（引擎层，不只是 UI 置灰）**：

| 条件 | 行为 |
|---|---|
| `swingGears` 不含该档 | 拒绝，`toast("建仓档不卖出")`，返回 `false` |
| `g <= 0` | 拒绝 |
| `g > net[i] + 0.05` | 拒绝，`toast("最多只能卖 " + gnum(net) + " g")` |
| `px <= 0` | 拒绝 |

卖出后 `net === 0` → 该档回到「待补 plan」，`markDone` 样式取消。

### 4.4 `mix`（整体均价）口径必须一起改

P5 §14.3 已经踩过一次坑：`Σpending` 不能当剩余额度用。P6 引入了卖出，这个坑会二次放大 —— 卖出会让 `Σpending` 增大，但**账户里的钱并没有变多**。

修正口径：

```js
// 剩余额度仍以「总仓 − 真实持仓」为准，不用 Σpending
var pendG  = Math.max(0, total - heldG);
// 单价用「未买档」加权均价；净持仓为 0 的档（从未买或已全卖）不参与
var pendPx = pendSum > 0.05 ? (pendAmt / pendSum) : aAll;
```

- `heldG` 用的是账本口径（`holdStats().grams`），不是 `Σnet` —— 因为 `Σnet` 是计划层
- 这条规则 P5 已经实现，P6 **只需确认卖出不影响它**（卖出不动 `buys[]`，所以 `heldG` 不变）

### 4.5 已实现差价的量级（先说清楚，别高估）

| 口径 | 金额 |
|---|---|
| 16g 周转一次、2% | ≈ 42 美元 |
| 40g（1/2 档全量）周转一次、2% | ≈ 104 美元 |
| 一年理想周转 4 次 | ≈ 414 美元 |
| 摊到 200g 持仓（6.43 oz） | 均价低 ≈ 64 美元/oz |

最后一行是**上限**，要求每次都吃满 2% 波段且从不被套。

> **波段是补贴，不是主力。** 它帮不了你把 3988 拉到 3900 —— 那 90 美元的缺口只能靠 4/5/6 档（P5 已做）或时间兜底（P7）。UI 文案里不要出现「靠循环把均价拉下来」这种暗示。

## 5. 交互

### 5.1 档位行（`renderLadder`）

循环档且 `net > 0` 时，行尾追加一枚小字：

```html
<span class="swing">+42 / 1.0 轮</span>
```

- `+42` = `realized` 取整；负数显示 `−18`，class 加 `neg`
- `1.0 轮` = `turns`，保留 1 位小数
- 建仓档不显示这枚标签（没有卖出，`realized` 恒为 0）

循环档的行尾按钮从单个变成两个：

```
[标记已买]  →  循环档：[买入] [卖出]
```

- 建仓档保持 `[标记已买]` / `[撤销]`
- `net === 0` 时只显示 `[买入]`（没有可卖的）

### 5.2 面板（`#sheetMark`）

顶部加两个 Tab：

```html
<div class="mktabs">
  <button class="on" data-mk="buy">买入</button>
  <button data-mk="sell">卖出</button>
</div>
```

| 元素 | 买入 Tab | 卖出 Tab |
|---|---|---|
| 标题 | `标记已买 · 第 1 档` | `标记卖出 · 第 1 档` |
| 说明行 | 计划 16 g　当前净持仓 X g | 净持仓 X g　买入均价 Y |
| 克重 | 默认 `plan − net`（待补） | 默认**全部净持仓** |
| **成交价** | 默认本档档位价 | 默认**现价** |
| 主按钮 | `确认买入` | `确认卖出` |

**新增「成交价」输入框**（`#markPx`）。P5 的标记只记克重、价格靠档位价推算，`realized` 就成了估算。加了这一格，`cost/proceeds` 全程是真值，差价才可信。

- 买入默认档位价：大多数人是挂单成交，价差可以忽略
- 卖出默认现价：卖出通常发生在反弹途中，按现价成交
- 两格都可改，改完实时重算「本次金额 ≈ $XXX」显示在按钮上方

### 5.3 设置页

在「档位分布」下面加一行「循环档」：

```html
<div class="wgrid" id="setSwingGrid">
  <!-- 六个 44px 高度的开关格，1–6 -->
</div>
<div class="wrow">
  <span class="wn">循环档可反复买卖，额度是「同时持仓上限」。</span>
  <button id="btnSwingReset">恢复默认</button>
</div>
```

- 点一下切换选中态（选中 = 金边 + 实心），不需要保存按钮，失焦即写
- 选中 3–6 时下方出现一行橙字：`3 档是建仓主力，反复买卖会削弱拉低均价的作用`
- 全不选 → 提示 `已关闭循环档，全部按建仓档处理`
- 复用 `.wgrid` 样式，320px 下不新增溢出风险（已有测试覆盖同类布局）

### 5.4 空态

`planOnly` 关闭时（走账本模式），循环档整套功能**不出现**：

- 档位行不显示 `+42 / 1.0 轮`
- 面板不出现 Tab
- 设置页的循环档一行置灰 + 说明「仅在计划模式下可用」

理由：账本模式已经有 `sells[]`，再叠一层会让「卖了几次」有两个答案。

## 6. 边界与提示

| 场景 | 表现 |
|---|---|
| 卖出超过净持仓 | 拒绝 + `toast("最多只能卖 X g")` |
| 建仓档点卖出 | 按钮置灰，`title` 写「建仓档不卖出，如要减仓请到账本模式记录」 |
| 卖完后 `net = 0` | 档位回到「待补 16g」，`markDone` 取消，行尾显示 `−18 / 1.0 轮`（保留历史差价） |
| `plan = 0`（权重填 0） | `turns` 显示 `—`，不显示轮次 |
| `g = 0` 却有 `sold > 0` | `cleanGearMarks` 剔除该键（数据异常） |
| 超买后卖出 | `over` 归零，`pending` 回到正数 |
| 切换计划模式开关 | `gearMarks` 原样保留（P5 行为不变） |
| 清空示例数据 | 连 `swingGears` 一起回默认 `[1,2]` |

### 待你拍板的两处（可先按默认走）

1. **卖出成交价要不要做成必填？**
   默认方案：预填现价，可改。若你希望「只填克重、价格自动取现价」，实现更简单，但差价会变成估算。

2. **循环档要不要包含第 3 档？**
   默认方案：只 1/2。第 3 档计划 48g，是拉低均价的主力，反复买卖会削弱它的作用。

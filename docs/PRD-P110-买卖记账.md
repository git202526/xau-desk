## 一、问题：卖得出，记不上

用户的判断是「持仓页只能记买，没有卖出记录，其它模块也记不了卖」。核对代码后，**能力其实早就写完了，缺的是入口和名字**——这比从零开发更麻烦，因为它让用户以为功能不存在。

### 1.1 现有入口盘点（逐条核实）

| # | 入口 | 位置 | 点下去是买还是卖 |
|---|---|---|---|
| 1 | 持仓汇总右侧「记一笔」`#btnHold` | `index.html:1181` | **只会买**（`openSheet(null)`，`:11335`） |
| 2 | 记录区右侧「+ 记一笔」`#btnAddBuy` | `:1193` | **只会买**（`openSheet(null)`，`:11332`） |
| 3 | 总览待办项「记减仓」`act:"take"` | `:10407` | 会卖（`openSell(null)`，`:11119`），但要先等止盈位触发 |
| 4 | 止盈阶梯执行位（整行可点） | `:10219` | 会卖（`openSell(档名)`），**没有任何视觉提示它是按钮** |
| 5 | 档位面板循环档「卖出」按钮 | `:8318` | **不记账**，只写 `gearMarks.sold`（`markSell`，`:4438`） |
| 6 | 档位面板「改成记一笔（留成交明细）」`#markToBuy` | `:1515` | 只在买入态显示（`:8501` 把卖出态藏了），**只会买** |

结论：6 个入口里，2 个能卖，但都不在「记账」这个心智位置上——一个藏在待办、一个藏在表格行的点击里，界面上没有任何「这里能点」的暗示。用户按「记一笔」走，永远只会买到买。

### 1.2 三个直接后果

**后果一：卖了记不上，持仓虚高。**
用户实际减了 20 克，`S.cfg.sells` 里没有这笔，持仓汇总仍是原数，浮动盈亏、仓位进度、回本价全部按虚高的克重算。而档位面板的「卖出」又确实让他看到净持仓变小了——**两个页面给出两个答案**。

**后果二：卖出记录没有名字。**
`renderBuys()`（`:10050`）确实把 `hs.sells` 混进了列表，卖出行也有 `−` 号和 `.cut` 色。但这一段的外层标题写的是「**买入记录**」（`:1193`），计数写「3 买 / 2 减」。用户扫一眼标题就判定「没有卖出记录」，不会去列表里找那个减号。

**后果三：档位「卖出」是半个动作。**
`markSell` 只改 `gearMarks[k].sold`，持仓、`sells[]`、盈亏一概不动，面板底部自己写着「只释放计划额度，实际成交请到「持仓」记一笔」——**而持仓页根本没有卖出入口**。这句话把用户指到了一条死路。

## 二、目标

1. 持仓页**一步**能记卖出，不需要先有止盈触发
2. 卖出记录**有自己的名字和位置**，买卖在同一张表里可分辨、可筛选
3. 其它出现「记一笔」的地方（档位面板）卖出后也能进同一张表单
4. 结算口径不变：卖出不改均价，只结转已实现盈亏
5. 卖出记录仍走既有校验：不超持仓、按账户隔离、摊派可回滚

## 三、非目标

- 不做 FIFO / 逐笔配对成本（现为移动加权平均，改口径会让历史盈亏全部重算）
- 不做手续费 / 税费字段（会引入 schema 迁移，本期不碰）
- 不做批量卖出、定投、条件单
- 不合并「档位标记卖出」与「记账卖出」两条轨（见第七节，只做提示，不做合并）
- 不改 `#panel-ov` 一屏预算（860）——本期改动全在持仓页与计划页

---

## 四、方案

四项改动，全部在展示层与入口层，`holdStats` / `saveSell` / `allotSell` 的函数体不动。

### 4.1 持仓汇总：「记一笔」拆成「买」「卖」

```
现状   持仓汇总                          [ 记一笔 ]
改后   持仓汇总                          [ 买 ] [ 卖 ]
```

**实测宽度代价（Playwright，390 / 360 / 320 三档）**：

| 宽度 | `.sech` 可用宽 | 原按钮 | 拆后（买+gap+卖） | `h2` 是否溢出 |
|---|---|---|---|---|
| 390 | 362 | 48px | 24 + 10 + 24 = 58px | 否（`scrollWidth == clientWidth`） |
| 360 | 332 | 48px | 58px | 否 |
| 320 | 292 | 48px | 58px | 否 |

`h2` 是 `flex:1 1 auto; min-width:0; overflow:hidden; white-space:nowrap`（`:118`），按 58−48 推算会被压 10px，仍然是一行省略，不折行、不横向滚动（实测 `scrollWidth == clientWidth`）。

不选「记一笔 → 弹层里再选买卖」的两步路径：卖出是这个页面的高频动作（止盈要反复减），两步会让每次多一次点击，而宽度代价只有 10px。

`#btnAddBuy`（记录区右侧）保留「+ 记一笔」并默认买入——它是「补一笔历史」的语义，与汇总区的「动仓位」分开。

### 4.2 表单顶部加「买入｜卖出」切换

任何入口进来都是同一张 `#sheet`，顶部加分段控件：

```
┌──────────────────────────────┐
│  记一笔                   关闭 │
│  ┌────────┬────────┐          │
│  │  买入  │  卖出  │          │
│  └────────┴────────┘          │
│  标签  [ 第3档 / 补仓 ]        │
│  账户  [ 招商银行积存金 ▾ ]    │
│  克重（g）    单价（元/克）    │
│  本次金额   ¥ 8,695            │
└──────────────────────────────┘
```

**切换时只做三件事**：`setSheetMode(mode)` 换 label 与按钮文案、重算「本次金额」提示、清空编辑态。

**关键边界（必须写进代码，否则会串账）**：

`S.editing` 同时被 `saveBuy` 和 `saveSell` 使用，`#btnSave` 按 `S.sheetMode` 分派（`:11330`）。如果正在编辑一条买入，用户切到「卖出」再保存，`saveSell` 会拿 `S.editing` 去 `S.cfg.sells` 里找，找不到就当成新增——**结果是凭空多出一笔卖出，而那笔买入没被修改**。

处理规则：

| 场景 | 行为 |
|---|---|
| 新增态（`S.editing === null`）切换 | 允许，直接切 |
| 编辑态切换 | **禁止切换**：分段控件置灰 + 顶部提示「修改中不能切换买卖，先保存或关闭」 |
| 编辑态点另一个入口 | 关闭当前表单再重开（保持既有 `openSheet` 语义） |

不选「切换时自动保存」：卖出表单的克重有上限校验，自动保存会在用户没看到报错时静默失败。

### 4.3 记录列表：改名 + 筛选 + 行内区分

**标题**：`买入记录` → `交易记录`；计数 `3 买 / 2 减` → `3 买 / 2 卖`。

**卡内筛选**（一行 chips，28px）：

```
[ 全部 5 ] [ 买入 3 ] [ 卖出 2 ]
```

默认「全部」。筛选只影响列表渲染，不影响 `#buyMeta` 的整体统计（统计永远是全账户口径，否则「剩 82g」会跟着筛选跳动，看着像持仓变了）。

**行内区分**（保留现有符号，补一个词）：

| | 现状 | 改后 |
|---|---|---|
| 克重 | `−20 g`（卖出）/ `100 g`（买入） | 不变 |
| 颜色 | `.cut` 类 | 不变 |
| 名称位 | `减仓` | `卖出` |
| 金额 | `+18,000`（卖出回笼） | 不变 |

**空态**：

- 全空：`还没有交易记录。点右侧「记一笔」填克重和单价（元/克），买和卖都在这里。`
- 筛到卖出且无记录：`还没有卖出记录。点上方「卖」记一笔减仓。`

### 4.4 档位面板：卖出后也能直达记账

`:8501` 现在把「改成记一笔」在卖出态隐藏。改后：

| 面板状态 | 按钮文案 | 点击行为 |
|---|---|---|
| 买入态 | 改成记一笔（留成交明细） | `openSheet(档名)`（不变） |
| 卖出态 | 改成记一笔（留成交明细） | `openSell(档名)` —— **带档名进来，克重预填该档净持** |

并在卖出面板底部把死路文案改掉：

```
旧  只释放计划额度，实际成交请到「持仓」记一笔。
新  只释放计划额度。要留成交明细（进交易记录 / 计算已实现盈亏）点上面那个按钮。
```

## 五、结算口径

**公式一行不改**，PRD 只把口径写清楚，供验收对照。

```js
// holdStats(acct)  index.html:5432
grams    = Σ买入克 − Σ卖出克            // 不为负，Math.max(0, …)
avg      = Σ买入金额 ÷ Σ买入总克         // 分母是买入总克，不是余额
realized = Σ卖出金额 − Σ卖出克 × avg     // 已实现盈亏
costLeft = grams × avg                  // 剩余成本
浮盈      = grams × 现价 − costLeft
```

| 规则 | 取值 | 理由 |
|---|---|---|
| 成本法 | 移动加权平均 | 与既有历史数据一致；改 FIFO 会让所有旧记录的已实现盈亏重算 |
| 卖出是否改均价 | **不改** | `avg` 的分母是买入总克。若用余额做分母，卖一半后均价会虚高（`acctStats` 注释 `:5494` 已写明这条） |
| 已实现盈亏基准 | 当前加权均价 | 即「按均价结转」，不是按某笔具体买入配对 |
| 清仓后 | `grams = 0`，记录保留，汇总卡显示「已全部减仓（累计减 X 克，实现盈亏 ±Y）」 | 已有实现（`:9688`） |

**验收算例**（写进测试，比看公式可靠）：

```
买 100g @ 800 元/g        → grams 100, avg 800, costLeft 80,000
卖  20g @ 900 元/g        → grams  80, avg 800（不变）
                            realized = 18,000 − 20×800 = +2,000
现价 950 元/g             → 浮盈 = 80×(950−800) = 12,000
                           总收益 = 2,000 + 12,000 = 14,000
再卖 80g @ 950            → grams 0, realized = 2,000 + (76,000 − 64,000) = 14,000
```

最后一步是全期校验：**清仓时 `realized` 必须等于「清仓回款 − 全部买入成本」**。这条能一次抓出均价口径错误。

## 六、数据模型

**不新增字段，不做迁移。**

```js
// S.cfg.sells[]（已存在，P16 起）
{ id:"s1720…", name:"减仓", gram:20, priceCny:900, time:"2026-11-09T…",
  note:"", acct:"a1", allot:{ "1":8, "2":12 } }
```

| 问题 | 结论 |
|---|---|
| 要不要加 `kind:"sell"`？ | 不加。买在 `buys[]`、卖在 `sells[]`，数组本身就是类型；再加字段会出现「数组说卖、字段说买」的自相矛盾态 |
| 要不要加 `fee`？ | 本期不加。加了要迁移、要改 `realized`、要改所有历史统计，收益与风险不成比例 |

| 多设备合并？ | 沿用 `mergeCfg` 按 id 取并集 + `S.cfg.del` 墓碑，不动（`:6885`） |

## 八、两条轨的关系（本期最大的坑）

同一个「卖出」在两处落地，写的是同一组字段 `gearMarks[k].sold`：

| 路径 | 入口 | 写什么 | 减持仓？ | 进交易记录？ |
|---|---|---|---|---|
| A · 档位标记卖出 | 档位面板「卖出」→ `markSell` | `gearMarks[k].sold/proceeds` | **否** | **否** |
| B · 记账卖出 | 记账表单 → `saveSell` → `allotSell` | 同上，按净持占比摊 | 是 | 是 |

两条路都能让档位 `sold` 变大。**用户如果同一笔卖出两边各做一次，档位会被扣两次**（持仓只扣一次，因为标记路径不碰账本），表现为「档位净持仓比实际少」。

本期不合并两条轨（合并要改 P20 单模式的核心假设，风险远大于收益），只做三件事：

1. 4.4 把卖出面板的文案改成「只释放计划额度」，不再指向「持仓记一笔」这条死路
2. 记账表单保存后，若该笔 `allot` 命中的档位与已有 `gearMarks.sold` 之和超过该档 `g`，toast 提示「第 N 档卖出量已超出该档持仓，请到档位面板核对」
3. 交易记录里卖出行第二行已有「已摊入：第1档 8g · 第2档 12g」（`allotLine`，`:10028`），补一句口径说明——这就是「摊派」的可视化，用户能自己对照

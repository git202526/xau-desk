# 产品需求文档 · 总览 / 建仓 / 持仓 / 设置

> 适用范围：XAU Desk v7.12.2 的四个核心页面（`panel-ov` / `panel-plan` / `panel-pos` / `panel-set`）。
> 本文是**规则说明书**，不是代码说明。目的是让另一个应用按同一套判据复现同样的数字与同样的提示。
> 结构页（`panel-struct`）与事件页（`panel-sig`）只作为本册的输入被引用，不在此定义。

## 1. 产品定位

这是一个**单账户视角的黄金建仓/减仓执行器**，不是行情软件，也不是交易终端。

它只做一件事：把「我想在什么价位、买多少、跌到哪算失效、涨到哪减多少」这套人工判断，变成一张**每天能照着执行的表**，并在价格穿越关键位时把人叫住。

因此产品有三条硬边界：

1. **不下单**。所有买入/卖出都是用户手动在券商或银行完成，回来记一笔。系统只负责算和提醒。
2. **不预测**。所有"方向"来自多周期结构判定，"目标价"来自用户自己填。系统不生成看涨看跌结论。
3. **不造数**。价格缺失就显示 `--`，汇率缺失就显示 `¥ —`，成本未填就显示「未填」。绝不用估算值冒充实测值。

### 1.1 核心闭环

```
总览（看现在）→ 建仓（算价位与克重）→ 持仓（记账、看盈亏）→ 设置（调参数）→ 回到总览
```

四个页面不是并列的四个功能，而是同一条链上的四段。任何一段的输入错了，后面全部偏。所以本文反复强调**单一写入口**与**口径唯一**。

## 2. 用户与场景

| 场景 | 用户动作 | 系统必须给出 |
|---|---|---|
| 每天开盘前扫一眼 | 打开总览 | 现价、涨跌、四周期方向、今天有没有到价、持仓浮盈 |
| 金价跌了 2% | 看建仓阶梯 | 第几档到了、该买多少克、买完均价落在哪 |
| 真的买了 | 记一笔买入 | 持仓克重/均价立刻变，档位标记同步，待补变小 |
| 涨到止盈位 | 看止盈阶梯 | 减多少克、减完均价与剩余多少、这笔赚多少 |
| 想在另一个账户也买 | 切账户 | 该账户独立的克重/均价/回本价 |
| 想调档位密度 | 设置页改 α 或目标均价 | 阶梯价立刻重排，已买标记不丢 |

### 2.1 一个必须尊重的心理事实

用户对「我买在多少、现在赚多少、还差多少回本」这四个数字的敏感度，远高于对「策略是否优雅」的敏感度。所以：

- 克重精确到 **0.1 g**，金额精确到 **元**，价格精确到 **0.01 美元**；
- 均价永远显示两位小数，回本价永远在均价**右侧**（因为它是"均价 + 加点"的派生量）；
- 任何一个数字算不出来，**必须显示占位符并说明原因**，不能显示 0。

## 4. 总览页（`panel-ov`）

### 4.1 报价区（hero）

**展示六项**：现价、涨跌额与涨跌幅、今开、昨收、振幅、最高、最低、ATR14。

**判据**

| 项 | 计算 | 缺失时 |
|---|---|---|
| 参考价 `ref` | 依次取「昨收」→「当日统计昨收」→「当日统计开盘」 | 涨跌显示 `--`，现价去掉涨跌色 |
| 涨跌额 | `现价 − ref` | `--` |
| 涨跌幅 | `(现价 − ref) / ref × 100` | `--` |
| 今开 / 最高 / 最低 | 当日（**纽约 17:00 换日**）第一根 1h 的开、区间最高最低 | `--` |
| 昨收 | 上一个交易日的最后一根 1h 收盘 | `null` |
| 振幅 | `(最高 − 最低) / max(昨收, 今开) × 100` | `--` |
| ATR14 | 日线 ATR14（美元） | `--` |

**当日边界（关键）**：日界**不是** UTC 零点，是国际现货盘的 **纽约 17:00 收盘换日**。

```
夏令时（3 月第二个周日 07:00 UTC 起 ～ 11 月第一个周日 06:00 UTC 止）：UTC 21:00
冬令时：UTC 22:00
```

实现要点：把每根 1h 的时间戳折算成「交易日序号」再分组，而不是按 UTC 日期切。这条错了，每天 21:00–24:00（夏令时）的「今开」会是错的。

**容错顺序**：1h 序列 ≥ 30 根 → 用 1h 聚合；否则退到 UTC 日线（开高低直接用、昨收取倒数第二根收盘）；再否则退到「近 24 小时」。三级都要能出数，不能白屏。

**颜色**：涨=红、跌=绿、平=灰。大价格与涨跌幅**必须同色**，不能一个大红一个白。

### 4.2 结论区（verdict）

展示四枚周期 chip（周线/日线/4小时/1小时 + 方向词）、一句主结论、一句副结论、一条置信/强度条。

**四周期语义分工**（不可互换）：

| 周期 | 作用 | 权重 |
|---|---|---|
| 周线 | 定背景（只确认或反对，不做触发） | 10% |
| 日线 | 定方向（主判据） | 50% |
| 4 小时 | 定节奏（状态与 ADX） | 40% |
| 1 小时 | 只做触发 | 0 |

**六种结构态**对应六套文案，不允许合并：

| 态 | 主结论 | 副结论要点 |
|---|---|---|
| `notrend` | 无趋势：日线 ADX x | 不做方向性判断，只执行回撤分档 |
| `veto` | 方向作废：日线与中长周期相反 | 多空各半，只按回撤分档执行 |
| `counter` | 逆周线：日线X、周线Y | 反弹/回调级别，**仓位按半档执行** |
| `diverge` | 回调中（日线上、4h 转弱）/ 反抽中（日线下、4h 转强） | 等 4h 重新转向再动手，不追 |
| `align` | 多头共振 / 空头共振 | `n/valid 同向 · 周线确认/未反对` |
| `mixed` | 方向待确认：日线X | 4h 无明确方向，按日线方向**轻仓** |

**分母口径**：`align` 必须写「同向票数 / **实际投票数**」，不能写死 `/3`。周线缺数据时只有两票，写 3 是凭空多一个没投票的周期。

**置信与强度是两个量**：方向为震荡时 `conf` 恒为 0，此时条长按「强度」给，文案写「强度 x」而不是「置信 0」。

**状态后缀必须常驻**：主结论右侧固定跟一段「（状态：xxx · 4H ADX a / 日线 ADX b）」。理由：4H 的 ADX 是状态判据，日线的 ADX 是方向判据，读者常拿错。这段不是给异常用的，是常驻。

### 4.3 宏观卡

两列：**10Y 实际利率（TIPS）**、**美元指数（DXY）**，各带一个变化量 badge 与一句对金的推演。

**死区（关键）**：`|Δbp| ≤ 2.00` 或 `|Δ%| ≤ 0.10` 判平盘，不写方向。1.5bp 在日频 TIPS 上属噪声，用噪声写方向会天天变。

**新鲜度（按数据日，不按抓取时刻）**：`as_of` 与今天的自然日差 `≤ 8 天` 算新鲜（覆盖周末、长周末、假日与 T-1 滞后）。只有 `as_of` 缺失时才退回「抓取时刻 90 分钟内」。

**单边缺失**：某一列过期，只把**那一列**写 `--`，状态写「数据不完整」，**不要整卡清空**。另一列仍然有效。

**页脚**：写「数据截至 {as_of}」，不写抓取时刻（抓取时刻放 `title`）。

**推演一句**（固定三选一）：死区 → 平盘震荡；两列方向相反 → 拉锯；同向 → 压制或支撑金银。

### 4.4 仓位条

一行三格：持仓克重 / 均价 / 浮动盈亏，整条可点，跳到持仓页。

```
浮动盈亏 = (现价人民币克价 − 持仓均价) × 持仓克重
现价人民币克价 = XAU/USD × USD/CNY ÷ 31.1035
```

零持仓时三格显示 `—`，点击提示「还没建仓，去持仓页记一笔」。**不要显示 0**——0 会被读成"不赚不亏"。

### 4.5 「今天要处理」（本页最重要的一块）

这是全应用唯一主动叫人的地方。列表必须**自动生成**，用户不配置。

**生成源与判据**

| 类型 | 触发条件 | 按钮 | 文案要点 |
|---|---|---|---|
| `fatal` | 现价 < 最低档 × 0.99 **且** 持仓为 0（= 全档跌破且本轮没建仓） | 重设高点 | 「N 档全部跌破，本轮未建仓」+ 现价与第 N 档价 |
| `buy` | 现价 ≤ 某档触发价，且该档未买、非预警档 | 已买入 | 「第 k 档 到价」+ 可买克重 + 触发价 |
| `warn` | 预警档（−10% / −12%）被跌破且未处理 | 无 | 「回撤 x%，尚未建仓」 |
| `take` | 止盈位命中（`role=hit`）且计划减仓克重 > 0 | 记减仓 | 现价 + 计划减 N 克 |
| `alert` | 用户自设价位被穿越且未确认 | 知道了 | 上破/下破/触及 + 价位 + 现价 |
| `ev` | 事件在 **未来 60 分钟内**，或 **已过去 15 分钟内** | 无 | 距公布 N 分钟 |

**排序**：`fatal(0) > take(1) > buy(2) > alert(3) > warn(4) > ev(5)`。

**条数上限 7**。超出不显示"更多"，直接截断——这是"今天要处理"，不是收件箱。

**空态文案**：「当前无动作。计划已就位，到价会出现在这里。」不许留白，也不许写"暂无数据"。

**不可省略的一条**：昨天到价但没处理的条目，今天**仍然出现**（因为判据是"现价 vs 档位价"，不是"今天新发生"）。这等价于"昨天没做完的自动滚到今天"。

### 4.6 底栏角标

| 角标 | 计数来源 | 挂在哪 |
|---|---|---|
| 建仓 | `buy` 类条目数 | plan Tab |
| 持仓 | `take` 类条目数 | pos Tab |
| 设置 | `fatal` 类条目数 | set Tab |
| 结构 | `alert` 类条目数 | struct Tab |

**口径是「到价档总数」，不是「未读」**。曾经改成已读制，用户要求改回：角标是**常驻提醒**，不是一次性回执。显示 `9+` 封顶。

### 4.7 页脚统计行

一行小字，三段：

```
K线 1h:1000 · 4h:1000 · 1d:1000 · 1w:220 · 自动高点 4211.7（D60）
```

用途是让用户/支持一眼看出"数据有没有到位"。自动高点后面必须带窗口名（`D60` / `D20`），因为降级时数字会变。

## 5. 建仓页（`panel-plan`）

### 5.1 三层分离（本页的骨架）

这是整个产品最核心的设计约束，**移植时不可打散**：

| 层 | 回答什么 | 由什么决定 | 允许读什么 |
|---|---|---|---|
| 价格层 | 每档触发价是多少 | 高点 H + 档距 d | 只读 H、startDrop、档距方式参数 |
| 计划层 | 每档该买多少克 | 权重 w + 可分配预算 B | 只读 w、TOTAL、未标档持仓 |
| 执行层 | 每档已买多少、待补多少 | 档位标记 / 买入记录 | 只读标记与记录 |

**层间禁止互相写**。价格层不许因"已买"而移动价位；计划层不许因"已买"而改权重；执行层不许改前两层。

### 5.2 价格层

**第 1 档**：

```
p₁ = H × (1 − startDrop / 100)          默认 startDrop = 13（即 0.87H）
```

**第 i 档**：

```
pᵢ = p₁ − (i − 1) × d                   i = 1..n
```

**高点 H 的取法（两选一）**

| 模式 | 值 | 说明 |
|---|---|---|
| 自动 | 近 **60 根日线收盘价**的最高值 | 窗口标 `D60` |
| 手动 | 用户填的数值 | 值域 1000–9000，留空即回自动 |

**自动高点的降级**：满足任一条件则改用「近 20 根日线收盘最高值 与 现价 的较大者」，窗口标 `D20`：

```
现价 < h60 × 0.8
或  h60 × 0.82 > 现价
```

理由：金价单边上涨时，60 日前的"高点"已经离现价 20% 以上，按它排档会把第 1 档排到天上，一档都触发不了。

**档距 d 三选一**（用户在设置页选，**默认 `target`**）

| 模式 | 公式 | 适用 |
|---|---|---|
| `alpha` 波动率 | `d = α × ATR14(美元)` | 想让档距跟波动率走 |
| `target` 目标均价 | `d = (p₁ − T) / c_front` | 想让"买完的均价"落在指定价 |
| `range` 区间 | `d = (endDrop − startDrop)/100 × H / (n − 1)` | 想让最后一档刚好落在终止跌幅 |

- `α` 值域 **0.6–3.5**，默认 **1.0**。
- `ATR14` 拿不到时，`base` 回退为 `1% × H`，并在界面标「（估）」。
- `c_front` = **前 1..k 档的权重重心**（见 §5.4），`k` = 锚定档位。

**终止跌幅是硬上限（只压不拉）**

```
capD = (endDrop − startDrop)/100 × H / (n − 1)
最终 d = min(名义 d, capD)
```

- 未越界时 `min` 取回名义值，**档位价一个字节都不改**。
- 越界时必须给两条**互不串改**的出口：①「目标改为可达值」（只改 T）②「放开终止」（只改 endDrop）。不允许一个按钮同时改两个参数。
- 界面必须常驻一行「最深档 −x% · 终止 y% · 余量 z pp」，让"改了终止但价格没动"这件事可见。

### 5.3 计划层

**可分配预算 B**

```
B = TOTAL − Σ(未标记到档位的买入克重)
```

- **只扣「未标档」的持仓**。已标档的持仓由各档 `bought` 自然扣减 `pending`，再扣一次就是双重扣减，会把已买满的档标成「已买超」。
- 开启「不设仓位上限」时 `B = TOTAL`（不做扣减）。

**各档计划克重**

```
plan_i = B × w_i / Σw
```

权重不强制合计 100%，按相对值归一化。但界面必须显示「合计 xx%（超 y% / 缺 z%）」并给「归一化到 100%」按钮（最大余数法，只按比例缩放，不改相对关系）。

**为什么计划层不能写死 `TOTAL`**：TOTAL=100、已有 60 克全未标档时，若 Σplan 仍等于 100，界面会显示"待补 100 克"，而真实剩余只有 40。

### 5.4 均价口径（三个，必须分清）

| 口径 | 定义 | 用途 |
|---|---|---|
| **锚定均价** `avgAnchor` | 只买 **1..k 档**的加权均价 `Σ(wᵢpᵢ)/Σwᵢ` | **第一对齐对象**，"命中目标"以它为准 |
| 选定档位试算均价 `avgSel` | **全部 n 档**买满的加权均价 | 只试算，不作对齐依据 |
| 整体均价 `mix.avg` | `(已持仓×已持均价 + 剩余额度×未买档加权均价) / 总仓` | 回答"我这套计划最终会落在哪" |

**锚定档位 k 的取法**：显式设 2..n 就用它；「自动」时取**全档权重重心最近档**：

```
c = Σ(wᵢ · i) / Σwᵢ        i 从 0 起
k = round(c) + 1，夹到 [1, n]
```

**命中判据**：`|均价 − 目标 T| ≤ 容差 band`（默认 **20 美元**）。

**已持仓折算**（"让手里已有的货 + 后续按计划买入"整体命中 T）：

```
T_eff = (T × TOTAL − 已持均价 × 已持克重) / (TOTAL − 已持克重)
```

- 剩余额度 ≤ 0 时，`T_eff = null`，档距退回 α 排法，提示「仓位已满」。
- 开启「不设仓位上限」= **跳过这段折算**，档距一律按名义 T 反解。但 `TOTAL` 本身不变（进度条、超上限判定、满仓成本仍按原口径）。

**为什么把锚定均价当第一对象**：用户真正的意图是"我把前几档买完，均价要落在 T"，而不是"第 k 档的单档价要等于 T"，更不是"全部 10 档买完的平均价要等于 T"。三者的数字差很远。

### 5.5 配额下沉（可选，默认关）

**要解决的问题**：价格跌破某档后，那档的待补额度"买不到"了（要等反弹）。这笔钱应当挪给现价附近、还没跌穿的档，否则钱就闲置。

**三条硬规则**

1. **只挪待补，不动已买**。已买是既成事实；超买档可捐额为 0，不产生负数。
2. **同角色内互挪**。建仓档 ↔ 建仓档，循环档 ↔ 循环档。活钱不许变死钱。
3. **同角色内无接收方 → 整组撤销**，额度留在原档等反弹。宁可不动，不硬塞。

**失效判定带滞回**

```
未失效 → 跌破 1%（px ≤ p × 0.99）才进入失效
已失效 → 涨回 0.3% 以上（px > p × 0.997）才退出
```

没有滞回，价格在档位价上下抖动时额度会来回搬，界面像抽风。

**转移量与落点**

```
可捐 = max(0, plan_i − bought_i) × ratio        ratio ∈ {0.5, 0.7, 1.0}
```

- `mode = near`（就近）：全部给现价最近的接收档。
- `mode = prop`（等比）：按各接收档的 `plan_i` 比例分。
- **兜底**：`near` 模式下若最近接收档比现价低超过 `maxDrop`（默认 **3%**），退化为等比。理由：把钱挪到一个"还得再跌 3%"的档，等于没挪。

**守恒约束（可测试）**：`Σ 有效计划 = Σ 基础计划`。这条必须写死断言。

### 5.6 建仓阶梯（展示）

每档一行，从高到低排列（第 1 档在上）。

**必须显示的字段**：触发价、档名、计划克重、实际/计划克重（或「待补 N g」）、档位状态标签、到价概率、操作按钮。

**档位三态标签**

| 状态 | 条件 | 标签 |
|---|---|---|
| 待补 | `bought ≤ 0.05` 且 `pending > 0.05` | 「未买」 |
| 已买满 | `bought > 0.05` 且 `pending ≤ 0.05` | 「已买入」 |
| 已买超 | `bought − plan > 0.05` | 「超预算」 |

**重要**：卖出后净持变小、`pending` 重新出现，标签必须**退回「待补」**。否则会出现「已买入 + 待补 8g」这种自相矛盾的状态。

**到价概率**：只在 `触发价 < 现价` 时显示，文案「40日触及 x%」。计算方式见 §5.7。

**操作按钮**

| 档类型 | 有净持 | 无净持 |
|---|---|---|
| 循环档 | 买入 + 卖出 | 买入 |
| 建仓档 | 撤销（取消已买标记） | 标记已买 |

循环档默认只有 **第 1、2 档**（深档买了不卖，否则削弱拉低均价的作用）。

**沉降标签**：`+2.2g 下沉入` / `−1.5g 下沉出`，单位是**克**不是百分比，点一下看明细。

**已买标记的撤销**：撤销只影响标记与推荐克重，**不碰买卖记录、不改持仓**。撤销后价格再回到该档会重新提示买入。

### 5.7 触及概率（四点实测表，不插值）

**只能用这四个点，一个都不补、不插值**：

| 回撤深度 | 10 日内 | 20 日内 | 40 日内 |
|---|---|---|---|
| ≥ 8% | 3.9% | 7.0% | 13.6% |
| ≥ 13% | 1.0% | 2.3% | 5.5% |
| ≥ 17% | 0.7% | 1.8% | 3.5% |
| ≥ 19% | 0.1% | 0.8% | 2.0% |

**取法**：`命中行 = 满足「band ≤ ddPct」的最深一行`；若 `ddPct < 8%`，直接返回 13.6% 并标 `below=true`（即"比表里最浅的一档还浅，概率按最浅档给下限"）。

**为什么要写"不插值"**：插值会造出"11% 回撤 40 日内 8.7% 概率"这种从未实测过的数字，而用户会拿它当依据。

### 5.8 深档兜底（默认开，30 天）

**要解决的问题**：第 4–6 档可能几个月都不触发，钱一直闲置，用户会怀疑"计划是不是坏了"。

**触发条件（全部满足）**

```
dripDays > 0                        （0 = 关闭）
该档非循环档
该档 pending > 0.05
该档是「最靠上的未买满档」（dripNext）
已等待 ≥ dripDays 天
现价存在
(现价 / 档位价 − 1) × 100 ≤ dripMaxPremium + 1e-9
```

**默认参数**：等待 **30** 天（值域 7–180，0=关）、买入比例 **0.5**（值域 0.1–1）、溢价容忍 **3%**（值域 0–20）。

**买入克重**

```
g = pending × dripPct
若 0 < g < 1 → g = pending        （不足 1g 一次清掉，避免 0.3g 反复触发）
```

**执行后**：计时重置为当下（下一个周期重新开始）。

**为什么只对「下一档」**：同时对 5 个档兜底，等于把分批建仓变成一次性梭哈，设计意图就没了。

### 5.9 到价与重算

- **到价判定**：`现价 ≤ 触发价` → 出条目 + 提示音（页面开着才响）+ 角标。
- **「重算档位」**：按当前持仓克重，从第 1 档往上填，填满一档算一档。买卖记录与持仓不变，只重排标记。用于整体减仓后重来。
- **「按高点」**：按当前生效高点重算触发价，已买标记保留。

## 6. 持仓页（`panel-pos`）

### 6.1 仓位进度（页首）

```
进度 = 当前持仓克重 / 目标总克重 × 100%
```

20 格进度条，每 5% 一格。文案三态：

| 条件 | 文案 |
|---|---|
| `剩余 > 0.05` | 还能买 x g |
| `剩余 < −0.05` | 超上限 x g（超上限时该段文字变警示色） |
| 否则 | 刚好到上限 |
| 开了「不设仓位上限」 | 已开不设上限（**不再报超上限**，两者说法互斥） |

**颜色与位置同源**：文字颜色取「最后点亮的格子落在第几阶」，段 `i` 落在第 `floor(i/4)` 阶。不允许出现"条是橙的、字是红的"。

### 6.2 持仓汇总（本页核心）

**统计口径（唯一）**

```
持仓克重 = Σ 买入记录.gram − Σ 卖出记录.gram          （下限 0）
持仓成本 = Σ (买入.gram × 买入.priceCny)              （人民币）
均价     = 持仓成本 / Σ 买入.gram                      ← 分母恒为「买入总克重」
```

**这一条最容易做错**：分母是**买入总克重**，不是卖出后的余额。

- 用余额当分母 → "卖过一半"的账户均价会虚高。
- 卖出**不改均价**，只减克重。

**已实现盈亏**

```
realized = Σ(卖出.gram × 卖出.priceCny) − Σ(卖出.gram) × 均价
```

**兼容旧数据**：若没有任何买入记录，但存在历史汇总（`GRAMS > 0` 且 `COST > 0`），用汇总值。**但只能在全账户视图生效**——否则筛一个空账户会把"历史汇总 100 克"显示出来。

**回本价**

```
回本价 = 均价 + comeback           默认 comeback = 10 元/克，值域 0–50
```

- 用户可填 0（= 回本价就是均价）。
- 负数必须夹到 0：输入框有 `min=0` 但手输能绕过；回本价低于均价会让"已盈利"算出负数。

**距回本**

```
gapPct = (现价克价 / 回本价 − 1) × 100
gapPct < 0 → 「还差 x%」绿色
gapPct ≥ 0 → 「已过 +x%」红色
```

方向不取反：低于回本价是"还差"，与收益率方向一致（负=绿）。

**六项读数**（固定顺序）：持仓克重、持仓成本、均价成本、回本价、现价、距回本、收益率；有卖出时追加第八项「已减 x g 实现 ±y」。

**三个空态必须都写清**

| 状态 | 文案 |
|---|---|
| 无买入也无卖出 | 「还没有买入记录。点右侧「买入」填克重和单价（元/克），这里会自动汇总总金额与均价。」 |
| 有卖出但已清仓 | 「已全部减仓（累计减 x 克，实现盈亏 ±y 元）。重新买入后这里会继续汇总。」 |
| 筛到空账户 | 「{账户名} 还没有买入记录。换一个账户看看，或点右侧「买入」。」 |

三个空态都**必须先渲染账户筛选条**，否则筛到空账户后连"全部"都点不回去。这是一个真实发生过的死锁。

### 6.3 盈利测算卡

六档：成本 **+5 / +10 / +15 / +20 / +25 / +30 %**，两行三列。

每格显示：`成本 +x%` → 赚多少钱（`持仓成本 × x%`）→ 对应价位（`均价 × (1 + x%)`）。

**金额基准只能是成本**，不是现价——说的是"盈利 5%"，基准只能是本金。

**只有当浮动收益率贴近某档（±2 个百分点）时才把那一格涂红闪动**，其余保持金色。六格全红等于没重点。

**首行**：未回本时写「距回本单价 · 还差 x 元/克 · 需涨 y%」；已回本写「回本后盈利 · 已盈利 x 元/克 · 较成本 +z%」。

**「已盈利」只能相对成本算**：拿现价减回本价当盈利，等于把用户自己设的目标利润算成了本金。

### 6.4 账户卡

每行一个账户：颜色点、名称、备注、占比、克重、均价、回本价、浮盈、占比条。

**各行口径独立**：每个账户的均价只由该账户的买卖记录算，**不按账户重摊成本**。所以「几行相加 ≠ 全账户持仓成本」。这条必须写在卡片脚注里，否则用户会拿计算器对账然后来质疑。

**筛选交互**：点行 → 只看该账户；再点一次 → 回到全部。筛选是**纯内存态**，不写配置（写配置 = 点一下筛一次云端 PUT）。

**只有一个账户时整条筛选栏不出**。多一条只有一个选项的筛选栏是纯噪音。

**「全部」按钮必须始终在**。

### 6.5 交易记录

标题必须是**交易记录**，不是「买入记录」——列表里本来就混着卖出。

**三个筛选**：全部 / 买入 / 卖出，各带条数。

**统计恒为全量**：筛选只作用于列表，标题右侧的「剩 xx g」不跟着筛选跳动。否则看着像持仓变了。

**每行内容**：方向色条、名称、克重、单价、金额、时间、账户徽标（仅多账户时）、备注、摊派信息。

**摊派信息两种文案，不能混**

| 情况 | 文案 |
|---|---|
| 各档本来就没有净持 | 「无需摊入（记账时各档都没有净持，只扣了持仓）」 |
| 有净持但记录没有快照（历史数据） | 「未记录（这笔记于分摊快照上线之前，改动时按比例近似退回）」 |

把第一种也说成"记于快照上线之前"，会让刚记的一笔看起来像报错。

### 6.6 卖出摊派（写入口，最易错）

**问题**：账本里一笔卖出只有一个总克重，但档位表需要知道"这一笔扣了哪几档、各多少"。

**规则**

1. 按各档**净持占比**把克重拆开（`g = bought_i`，`Σg` 为分母）。
2. 拆分单位 **0.1 g**，尾差补到**最后一个有量的档**。
3. 只改 `sold` / `proceeds` / `proceedsCny`，**`g` 与 `cost` 一律不动**。
4. 把「这次实际写进哪几档、各多少克」存成快照 `allot`，挂在这笔卖出记录上。
5. 改动/删除这笔记录时，按快照**精确退回**。
6. 没有快照（历史数据）时按当前 `sold` 占比**近似退回**：总量精确、分布近似。

**编辑时的顺序（关键）**：**先退旧的，再摊新的**。反过来就是双重累加。

**换账户时**：不能把原克重加回来——那笔属于旧账户。漏了这条，改账户同时调大克重，就能卖出超过新账户的持仓。

**卖出量校验**

```
卖出克重 > 该账户持仓 + 退回量 + 0.001 → 拒绝，提示「{账户}只剩 x 克，卖不了 y 克」
```

### 6.7 执行复盘（默认收起）

逐档对比：计划价 vs 实际成交均价、执行状态、每克拉低多少。

**四态**：未执行 / 部分执行 / 已执行 / 超额执行。

**默认收起**，不占首屏——它是复盘用的，不是每天看的。

### 6.8 止盈阶梯

**候选位（统一折算成元/克）**

| 来源 | 具体位 | 强度权重 |
|---|---|---|
| 成本 | 回本位（= 均价） | 1（只做标记，不参与减仓） |
| 计划盈利档 | +15% / +20% / +25% / +30% | 1 |
| 技术位 | 枢轴 / 斐波 / 均线 / 箱体 | 按指认数 |
| 前高 | 近 60 日最高 | 2 |
| 延伸目标 | 前高 + 量度 127.2% / 161.8% / 200% | 2 |
| PL90 / PL180 | 90 / 180 日最高收盘 | 2 |
| 摆动高 | 近 60 日摆动高点（取最近 3 个） | 1 |
| 52 周高点 | 周线区间高点 | 3 |
| 整数关口 | 步长按量级：>3000 用 100，>800 用 50，否则 10 | 1 |

**过滤**：只保留现价上方（`> 现价 × 0.975`，让"刚被穿过"的位仍留在表里并标「已到价」；成本位用 `≥ 现价 × 0.999`）。

**合并**：相距 **0.35%** 以内的位合并成一条，`count` 累加、`arms` 取最大。若其中一条是计划盈利档而目标条不是，则**名称与来源换成盈利档**（用户更容易理解"你设的 +15%"而不是"斐波 61.8%"）。

**强度**：`strength = min(4, count + (arms ≥ 2 ? 1 : 0))`。

**评分（0–100）五段**

| 段 | 分值 | 判据 |
|---|---|---|
| ① 位置强度 | `min(36, strength × 11)` | 3 源以上=「多重压力重合」，2=「两源指向」，1=「单一压力位」 |
| ② 空间 | `min(24, dist/8 × 24)` | 涨 8% 给满 |
| ③ 趋势配合 | 0–30 | 见下表 |
| ④ 位类型 | −6 ～ +12 | 计划盈利档 +10、趋势延伸 +12、整数关口 −6 |
| ⑤ 惩罚 | 负分 | 距现价 < 1.8% 扣 18；概率 < 12% 扣 10；空头且 dist > 20% 扣 12 |

**③ 趋势配合细分**

| 方向 | 条件 | 分 | 文案 |
|---|---|---|---|
| 上行 | ADX≥30 且是突破位 | 30 | 强趋势突破位，让利润跑 |
| 上行 | ADX≥30 | 24 | 趋势强，可持有 |
| 上行 | 其他 | 16 | 趋势向上，缓减 |
| 下行 | dist ≤ 6% | 28 | 趋势不支持，近位先落袋 |
| 下行 | dist ≤ 12% | 16 | 趋势偏弱，远位试减 |
| 下行 | 其他 | 4 | 过远，仅留观察 |
| 震荡 | dist ≤ 8% | 14 | 震荡区间，按位减 |
| 震荡 | 其他 | 8 | 同上 |

**选位（四步）**

1. 门槛：`score ≥ 50` **且** `dist ≥ 1.5%`。若关闭「允许在成本下方减仓」，再排除 `价格 < 成本 × 0.999` 的位。
2. 按分数降序排，逐个取，**与已选位相距 < 1.2% 的跳过**。
3. **断层截断**：若「上一选中 − 当前」≥ 18 分 **且** 当前 < 56 分，停止。最多 8 个。
4. **保底**：若不足 2 个，从落选里补到 2 个；若无「计划盈利档」，补 1 个（`prob ≥ 10%` 且 `dist ≤ 25%`）。

**分配克重**

```
可减总量 = 持仓 − 底仓 − 已到价待核销
权重 = 分数 × 可达性 × 空间
```

- 单位 0.1 g，**全程整数运算**，最后一位收口保证总和精确。
- **12% 首单保底只给「第一个成本上方位」**。止损位在成本之下，把最大份额压在那儿等于放大亏损。
- 份额不够每人一份时只分前几位。

**底仓**：主参数是**克重**（`底仓保留 x g`），百分比只是折算显示。

```
底仓 = min(持仓, 用户填的克重 或 持仓 × (1 − 减仓比例/100))
```

- 减仓比例默认 **70%**。
- **没有持仓时不夹到 0**——原来 `min(0, 20) = 0`，输入框却按用户填的 20 显示，脏值判定永远差一条，保存后刷新还提示「1 项未保存」。

**计划持久化**：每个执行位的分配克重存进 `takePlan`，**7 天过期**。

**已到价待核销**：价格冲过某位后它不再满足"现价上方"，但计划还在，需要提示核销。

- 先按现价**从高到低**核销。
- 每条**以剩余持仓封顶**。旧计划是按当时持仓算的，持仓缩水后整笔照搬会提示"减 28.3g"而实际只剩 5g，点开预填 28.3、保存必被拒。
- 剩余不足 0.1g 就不再提示。
- 关闭「允许在成本下方减仓」时，成本下方的旧计划条目也要一起过滤——否则开关关掉了，它们照样变成可点的「到价 · 减 X g」，一点就是亏损卖出。

**卡片四数**：本轮计划减 / 分几次 / 止盈均价 / 全部执行均价。

第四个数只在「止盈+止损同时在」或「还有到价待核销」时出现（此时它和第三个数不是同一个值，摆出来才有信息）。名字按实际卖出来说：卖光才叫「清仓均价」，留了底仓叫「计划均价」。

## 7. 设置页（`panel-set`）

### 7.1 结构

**速览条（5 枚 chip，页首）**：`n 档` / `档距方式值` / `锚定` / `合计 xx%` / `下沉开|关`。点一下滚到对应控件并闪一下。

存在理由：手机一屏 844px，靠滑动找「档位分布」要走 1.5 屏。

**三张主卡（顺序固定，标题右侧带只读摘要）**

| 卡 | 摘要 | 包含 |
|---|---|---|
| **仓位** | `目标 100g · 已持 60g` | 目标总克重（+不设上限开关）、底仓保留、回本加点、本轮计划减仓（只读）、允许成本下方减仓、持仓说明 |
| **档位形态** | `6 档 · 目标 · 3800→3200` | 建仓高点（+当前生效只读+跟随自动）、目标均价、容差、档距方式（三选一）、α、当前档距（只读）、起始跌幅、终止跌幅、锚定档位、深度摘要行 |
| **分布与执行** | `合计 100% · 循环 2 · 下沉开` | 档位数量（6–10）、档位分布（%）+归一化+恢复默认、循环档、到价预警档位、深档兜底（3 参数）、配额下沉（开关+模式+比例） |

**后续折叠卡**：提醒（声音开关+试听）、云端数据（GitHub）、数据备份与维护（导出/导入/重置）。

云端与维护**默认收起**：两块加起来约 1100px，接好之后几乎不再打开。

### 7.2 保存机制（两套，必须分清）

| 类型 | 有哪些 | 行为 |
|---|---|---|
| **改即存** | 档数、档距方式、α、起止跌幅、锚定、权重、循环档、预警档、兜底三参、下沉四参、各类开关 | 改动立刻写配置 + 重算 + 重渲染 |
| **需点「保存参数」** | 目标总克重、底仓保留、建仓高点、目标均价、容差、回本加点（共 **6 项**） | 只在点保存时写入 |

**为什么 6 项要单独保存**：这些值一改，整张阶梯会重排。用户边输边看会疯。

**但必须解决"假装生效"**：改了总仓切走再回来，输入框还显示 500，而引擎读的仍是 310——用户不会想到还要再点一次保存。

**脏值判定（三条）**

1. **只有用户真正碰过的输入框才算脏**。程序化赋值不算（`input`/`change` 事件只在真实输入时触发）。
2. 输入框为空 = 没填 = **不算脏**。
3. 容差 `0.001`。

**为什么要"碰过"这个条件**：六项里「底仓保留」是**派生显示**（按当前持仓算）。旧判据拿显示值和配置比，于是买一笔、卖一笔、甚至刷新后数据晚到，都会把"派生值漂移"判成"用户改了没保存"，浮条自己冒出来。

**派生值的基准也要一致**：底仓的基准取 `computedKeep(当前持仓)`（会被夹到持仓上限），不能取配置原值。用户设 20 而持仓只有 15 时，输入框显示 15、基准是 20，这条永远判脏。

**浮条行为**：脏了就出现，显示"N 项未保存"，带「保存」按钮（复用主按钮逻辑，不复制第二份校验）。**若已在设置页且保存按钮在视野内，浮条不出现**——按钮本身就是入口，别压两条。

| 字段 | 类型 | 值域 | 默认 | 非法值处理 |
|---|---|---|---|---|

| `avgBand` | num | > 0 | 20 | ≤ 0 → 20 |

| `H_BASE` | num | > 0（UI 层 1000–9000） | null | ≤ 0 → null |
| `comeback` | num | 0–50 | 10 | 空/非数 → 10；越界夹取 |
| `TOTAL` | num | > 0 | 100 | ≤ 0 → 100 |

### 7.4 预警档与循环档

**预警档（默认第 1、2 档 × −10% / −12%）**：只提示不买。全关是合法状态，**不自动回全开**。关闭全部时文案写「已关闭全部到价提示（深档兜底不受影响）」——因为兜底是另一条链路。

**循环档（默认 1、2）**：

- 空数组合法（= 关闭循环档），全垃圾值回默认。
- 卖出入口只对循环档开放，且**在计算层拒绝**，不只是 UI 置灰。

## 8. 全局口径与不变量

这一节是移植时最该先对齐的部分。数值算错往往不是公式错，是口径错。

### 8.1 单位与三个"事实"分离

| 事实 | 字段 | 单位 | 用途 |
|---|---|---|---|
| 克重 | `gram` | 克（g），精度 0.1 | 唯一统计口径 |
| 美元价 | `price` / `priceOz` | 美元/金衡盎司 | 档位、止盈位、结构 |
| 实付人民币 | `priceCny` / `costCny` | 元/克 | 成本、盈亏、回本价 |

**换算**：`1 金衡盎司 = 31.1035 克`。

```
人民币克价 = 美元盎司价 × USD/CNY ÷ 31.1035
```

**三者的关系必须承认是"估算"，除非用户填了实付**：

- 由美元价折出来的人民币成本 = **估算**（汇率随时变）。
- 用户填的 `priceCny` = **事实**。
- 界面必须能区分：估算值带「估」角标，未填显示 `¥ —`。

**汇率缺失时**：所有人民币派生的数一律 `null` → 显示 `--`，**不显示 0**。0 会被读成"不要钱"。

### 8.2 颜色

| 场景 | 涨/正 | 跌/负 | 平/无 |
|---|---|---|---|
| 价格、涨跌幅、浮盈 | 红 | 绿 | 灰 |
| 支出/买入 | 红 | — | — |
| 距回本 | 已过 = 红 | 还差 = 绿 | 灰 |
| 宏观对金影响 | 利多 = 红 | 利空 = 绿 | 平盘 = 灰 |

**注意最后两行不是"涨跌"，而是"方向"**：距回本取反过一次（低于回本价是"还差"=绿），宏观是"对金价的影响"而非"数值涨跌"。移植时不要统一成一套涨跌色。

### 8.3 数值显示

| 类型 | 规则 | 例 |
|---|---|---|
| 克重 | 最多 4 位小数，**去尾零**，整数不带小数点 | `8.4570 → 8.457`、`8.0000 → 8`、`0.1000 → 0.1` |
| 价格（$/oz） | 2 位 | `4211.67` |
| 人民币克价 | 2 位 | `931.42` |
| 金额 | 0 位（大额）/ 2 位（浮盈） | `¥58,320` / `+1,240.55` |
| 百分比 | 1–2 位 | `+2.35%` |
| 缺失 | `--` / `—` / `¥ —` | 按上下文三选一，**永不用 0 代替** |

**克重去尾零的理由**：强补 4 位会让「100.0000 克」看着像精度过剩；补 1 位又不够（0.1g × 930 元/克 ≈ 93 元，四舍五入看不出来）。

### 8.4 单一写入口（数据一致性）

| 数据 | 唯一写入口 | 禁止 |
|---|---|---|
| 买入记录 | `saveBuy` | 任何渲染函数直接改 `buys[]` |
| 卖出记录 | `saveSell`（内含摊派） | 直接改 `sells[]` 或直接改 `sold` |
| 档位标记 | `markBuy` / `markSell` / `markGear` / `unmarkGear` / `recalcGears` | 其他函数写 `gearMarks` |
| 配置 | `saveCfg` | 渲染层写 `cfg` 后不保存 |

**计划层与账本层严禁互写**：

- 计划层（`gearMarks`）只管"执行到哪一步"。
- 账本层（`buys[]` / `sells[]`）只管"真实持仓与成本"。
- 混写 = 双重计数。

**唯一的例外是「记账优先」的对账**：记账后立刻把该档的 `g` / `cost` 由买入记录重算（`syncMarksFromBuys`）。规则只有一条——**有记账的档以记账为准，没记账的档保留手工标记，`sold` 一律不动**（减仓没有档位归属）。

### 8.5 渲染层的单向调用（防死循环）

```
数据层（读写 storage）→ 计算层（过滤/排序/聚合）→ 渲染层（更新 DOM）
```

- 只允许上层调下层，或同层内单向调用。
- **渲染函数之间严禁互调**。需要联动时，由事件处理函数改数据后调统一的 `refreshAll()`，由它按固定顺序调用各渲染函数。
- 曾经出过的事故：日历渲染与当天列表渲染互调，栈溢出。这类 bug 语法正确、静态检查拦不住。

### 8.6 数字与状态的优先级

当多个状态同时成立时，按此优先级显示（只显示一个）：

```
事件冻结（前 30 分 / 后 45 分） > 数据不可用 > 正常 > 无数据
```

理由：事件窗口内价格会剧烈跳动，此时给出的任何"到价/触发"都是噪音。

## 9. 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 自动下单 | 不碰资金，只做执行辅助 |
| 多用户 / 账号体系 | 一个人用，靠导出导入与私有仓库迁移 |
| 后台推送通知 | 靠"打开就看见"的置顶区等价于提醒；浏览器推送到达率不可控 |
| K 线自绘全套指标 | 只保留结构判定需要的最小集 |
| 策略回测 | 方法论有前视偏差，结论恒为"跑输一次性买入"，反而误导（v6.49 已整块下线） |
| 用现价插值补缺失 K 线 | 等于造数据。只允许从真实源取根 |
| 前端持久化业务数据 | 只写私有仓库 `data.json`，浏览器不留业务数据 |

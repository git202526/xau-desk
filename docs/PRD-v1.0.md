## 一、背景：现有体系缺什么

你现在有两个每日任务，实际已经做到了「专业级日线定调」：

- **07:00**：D1/H4/H2/M30 多周期 MA 判定 → 前两日反转 → H_eff 六档建仓 → F1/F2/F3 风控
- **22:00**：美盘前盘中模式总览 → 前 3 日趋势演变 → 本周 4 星事件 → 建仓与止盈监测

问题不在分析深度，在**作用方式**。两个任务本质都是「定点快照 + 事后阅读」：

| 缺口 | 具体表现 | 后果 |
|---|---|---|
| **时点缺口** | 一天只有 07:00、22:00 两个判断点，中间 15 小时无人值守 | 欧盘急跌 40 美元、美盘假突破反抽，全部发生在两次报告的缝隙里 |
| **状态无记忆** | 每次重新分析，不知道「昨天说的 4050 空单触发过没有」 | 同一个位反复出现在报告里，分不清是「还没到」还是「已经走过又回来」 |
| **无触发闭环** | 报告里写「跌破 4042 转空」，但要你自己盯着看 | 结论有了，执行靠人肉监视，错过就变成下一份报告里的「已错过」 |
| **无优先级** | 六档建仓 + A/B/C 买卖点 + F1/F2/F3，一屏 20 个条件 | 真到关键位时，凭记忆判断「现在算哪个级别」，容易犹豫 |
| **无盘中结构** | 只有日线/4H 结构，没有盘中状态机 | 无法区分「趋势推进」和「区间磨盘」，同一套动作套用在两种行情上 |

**一句话**：现有体系在「定调」上已经够用，缺的是「**定调之后的 15 小时里，谁替我盯着、什么时候叫我**」。

## 二、产品定位

> **不是行情看板，是决策哨兵。**
> 平时安静，只在剧本被触发的那一刻响。

### 2.1 三种产品形态的分野

| 形态 | 特征 | 是否本产品 |
|---|---|---|
| 行情看板 | 价格一直跳，信息全给你，判断自己做 | 否（那是行情软件的活） |
| 分析报告 | 定时生成，深度够，但被动等你看 | 否（已有两个任务在做） |
| **决策哨兵** | 预设剧本 → 持续比对 → 状态转移才出声 → 每次出声都带动作 | **是** |

### 2.2 设计原则（三条，贯穿全部需求）

1. **剧本先行，盘中只做比对**
   盘中不重新「思考行情」，只回答一个问题：**预案里的哪个条件，现在成立了？**
   这样既稳定（不会每次给出不同结论），也省成本（不需要每 5 分钟重跑一遍完整分析）。

2. **状态转移才出声，价格跳动不出声**
   价格从 4052 跳到 4058 不是事件；「区间 → 向上突破」才是事件。所有提醒挂在**状态机**上，不挂在价格上。这是控制噪音的根本。

3. **没数据就说没数据，绝不拿旧值冒充实时**
   行情抓取失败时，页面必须明确显示「数据中断 N 分钟」，并降到只读模式，不给任何实时结论。

### 2.3 北极星指标

| 指标 | 定义 | 目标 |
|---|---|---|
| **信号有效率** | L2 以上信号触发后 2 小时内，价格按预期方向运行 ≥ 0.3% 的占比 | ≥ 55% |
| 噪音率 | 同一交易日内 L2 以上推送 > 8 条的交易日占比 | ≤ 10% |
| 响应率 | 推送后 30 分钟内用户打开工作台的比例 | ≥ 70% |

> 反目标：**不做「每条推送都很有道理」**。宁可少推，不可滥推。一天推 3 条准的，胜过推 15 条都对但没法执行的。

## 三、用户与典型时刻

**用户画像**：已有成熟交易框架（H_eff 滚动基准、多周期 MA、分级风控）的现货黄金交易者，非机构、非高频，日内到波段混合，主要精力在欧盘与美盘。

| 时刻 | 场景 | 现在的做法 | 期望的做法 |
|---|---|---|---|
| **15:30 欧盘开盘** | 价格从亚盘区间上沿启动 | 打开行情软件，回想早上报告写了什么 | 页面已在 14:50 标黄「逼近 4062 阻力，距 4 美元」 |
| **20:35 数据后** | 急跌 25 美元后 3 分钟拉回 | 事后才知道是假突破 | 收到一条：「向下扫单反抽，L2，建议回踩 4050 轻仓多，止损 4041」 |
| **凌晨 01:20** | 美盘尾段触到第二档建仓价 | 睡着了，第二天看到「已错过」 | 睡前把该档设为「仅页面记录」，不推送；或接受一条静音提醒 |

## 四、核心设计

### 4.1 双引擎架构（关键设计决策）

```
┌──────────────────────────────────────────────────────────┐
│  定调层（已有任务，保留）                                  │
│  07:00 D1 定调 ──┐                                        │
│  22:00 美盘总览 ─┴──► 产出【今日剧本 Playbook】            │
│                        方向偏好 / 关键位 / 六档 / 风控      │
└───────────────────────────┬──────────────────────────────┘
                            │ 剧本作为输入（不是每次重算）
┌───────────────────────────▼──────────────────────────────┐
│  执行层（新增盯盘引擎）                                    │
│  采样 → 状态机判定 → 触发比对 → 信号打分 → 分级输出        │
│  频率：亚盘 10min / 欧盘 5min / 美盘 5min / 深夜 30min     │
└───────────────────────────┬──────────────────────────────┘
                            │ 写入快照与信号
┌───────────────────────────▼──────────────────────────────┐
│  呈现层（本工作台页面）                                    │
│  状态卡 / 剧本阶梯 / 信号流 / 事件雷达                     │
│  打开即见，5-15 秒刷新价格，状态每 5 分钟同步               │
└──────────────────────────────────────────────────────────┘
```

**为什么这样分**：把「判断」和「监视」拆开。判断一天两次（贵、慢、但深），监视一天几百次（便宜、快、但浅）。混在一起会既贵又不稳。

### 4.2 盘中状态机（产品的智能内核）

盘中行情被归入 8 个有限状态，**只有状态转移才产生事件**：

| 状态 | 含义 | 进入条件（示例，最终由剧本参数化） |
|---|---|---|
| `CLOSED` | 休市 | 周六 05:00 – 周一 06:00（夏令时），含每日结算暂停 |
| `RANGE` | 区间震荡 | 现价距日内 VWAP ≤ 0.3%，且 30 分钟内未创日内新高/新低 |
| `TREND_UP` | 上行推进 | 现价 > H1 MA20，且连续 2 根 H1 收于前高之上 |
| `TREND_DOWN` | 下行推进 | 现价 < H1 MA20，且连续 2 根 H1 收于前低之下 |
| `BREAKOUT_UP` | 向上突破（待确认） | 突破日高或剧本阻力位 + 5 分钟内涨幅 > 0.15% |
| `BREAKOUT_DOWN` | 向下突破（待确认） | 跌破日低或剧本支撑位 + 5 分钟内跌幅 > 0.15% |
| `SWEEP_REVERSAL` | 假突破反抽 | 突破后 30 分钟内回落至突破位内侧 0.15% 以内 |
| `EVENT_LOCK` | 数据锁定 | 4 星及以上事件前 15 分钟至后 10 分钟 |

**转移规则举例**：
- `RANGE → BREAKOUT_UP`：上破区间上沿 → 记 L1，不推送
- `BREAKOUT_UP → TREND_UP`：突破后 30 分钟站稳（未回落）→ 升级 L2，推送
- `BREAKOUT_UP → SWEEP_REVERSAL`：30 分钟内回落 → 升级 L2，反向推送（这是最有价值的一类信号）
- 任何状态 → `EVENT_LOCK`：静默，暂停一切价格类信号

> 状态机的价值在于：**它让「假突破」这种最难人工判断的形态，变成一个可自动识别的状态转移**，而不是靠人盯。

### 4.3 信号分级与打分

不做单一 if-else，每个候选信号算一个可解释的总分（0-100）：

| 维度 | 权重 | 打分逻辑 |
|---|---|---|
| 位置分 | 30 | 是否落在剧本关键位 ±3 美元内；六档档位 > A/B/C 点 > 日内高低 |
| 结构分 | 25 | H4 / H1 / M30 同向共振 = 25；两周期同向 = 15；背离 = 5 |
| 动能分 | 20 | 突破时 5 分钟幅度与相对日均振幅的比值 |
| 时段分 | 15 | 美盘 20:00-24:00 = 15；欧盘 = 12；亚盘 = 6；凌晨 = 3 |
| 事件分 | 10 | 距 4 星事件 > 60 分钟 = 10；30-60 分钟 = 5；锁定窗口内 = 0（并抑制推送） |

| 总分 | 等级 | 呈现方式 |
|---|---|---|
| ≥ 70 | **L2 行动** | 顶部「今天要处理」+ 推送，带明确动作与止损 |
| 50-69 | **L1 提示** | 页面高亮 + 信号流，不推送 |
| 30-49 | **L0 观察** | 仅记录进信号流，默认折叠 |
| < 30 | — | 丢弃，不入库 |

每条信号必须能展开看到**五项得分明细**——这是「智能」与「黑箱」的分界线，用户要能质疑它。

### 4.4 去重与冷却（决定产品是否被用户关掉）

| 规则 | 参数 |
|---|---|
| 同一位 + 同方向冷却 | 4 小时内不重复推送（状态变化除外） |
| 同状态冷却 | 同一状态回切，2 小时内不重复推送 |
| 单日推送上限 | 8 条 L2，超出后降级为页面提示 |
| 静默时段 | 03:00-07:00 默认不推送（可配置为「仅 L3」） |
| 事件锁定 | 事件前后不推价格类信号，只推事件结论 |

## 五、功能需求（MVP 四模块）

> 严格控制在 4 个模块。持仓盈亏、多周期评分、命中率回测放在 P1，不塞进本期。

### 模块一：状态总览（Live Status）

**目标**：打开页面 3 秒内知道「现在什么状态、离关键位多远、数据新不新」。

| 元素 | 内容 |
|---|---|
| 主价格 | 现价大字（48px+），涨跌点数与百分比（涨红跌绿），今日高低 |
| 状态徽标 | 当前状态机状态 + 已持续时长（如「区间震荡 · 已 47 分钟」） |
| 状态解释 | 一句话说明「为什么是这个状态」，如「现价距 VWAP +0.12%，30 分钟未创新高」 |
| 关键距离 | 上方最近阻力、下方最近支撑，各显示价差（美元 + 百分比） |
| 数据新鲜度 | 「最后更新 19:42:03 · 延迟 6 秒」，三色：绿 <30s / 黄 30s-3min / 红 >10min |
| 今日区间条 | 横向条，标出今日低-高，以及现价所处百分位 |

**状态**：加载中（骨架屏）/ 正常 / 数据滞后（黄色横幅）/ 数据中断（红色横幅 + 禁用实时结论）/ 休市（灰显 + 「下个开盘 06:00」）

### 模块二：今日剧本与触发阶梯（Playbook Ladder）

**目标**：把 07:00 报告里的六档建仓 + 买卖点，变成一张「可勾选的状态清单」。

**核心交互**：纵向阶梯，从高到低排列所有关键位，每档显示：

```
┌─────────────────────────────────────┐
│ 4078  第①档 20%        ● 已触发      │
│       触发 14:32 · 入场 4078.4       │
├─────────────────────────────────────┤
│ 4062  阻力 / A 点       ◐ 逼近 (2.1) │
├─────────────────────────────────────┤
│ 4045  第②档 25%         ○ 待触发     │
├─────────────────────────────────────┤
│ 4031  第③档 25%         ○ 待触发     │
└─────────────────────────────────────┘
```

**每档四态**：`待触发` / `逼近`（距 ≤3 美元）/ `已触发`（锁定，含触发时间与成交价）/ `已失效`（剧本被推翻或当日作废）。

**关键规则**：
- **已触发必须锁定**，价格回落不重置、不重复计入，解决"同一个位反复报警"的老问题
- 失效需理由：日线跌破 MA200 或 22:00 报告改口径 → 整张剧本重算，旧档标记"作废（原因）"
- 每档可手动标记「仅记录不推送」（应对夜间档位）
- 顶部固定一行：`方向偏好：偏空 · 剧本来源 07:00 · 更新 07:03`

### 模块三：信号流（Signal Feed）

**目标**：一条可回溯的盘中时间轴，回答「今天到底发生了什么」。

| 字段 | 说明 |
|---|---|
| 时间 | HH:MM（当日），跨日显示日期 |
| 等级 | L0/L1/L2/L3 色块 |
| 类型 | 突破 / 假突破反抽 / 回踩确认 / 档位触发 / 风控触发 / 异常波动 |
| 一句话结论 | 「下破 4042 后 8 分钟收回，判定扫单」 |
| 动作建议 | 「回踩 4048-4052 轻仓多，止损 4041，目标 4068」 |
| 得分明细 | 折叠展开，五项得分 + 依据 |
| 状态 | 待处理 / 已处理 / 已忽略（一键，沉淀为当日统计） |

**筛选**：全部 / 仅 L2+ / 按类型。默认只显示 L1+，L0 折叠在「查看全部」。

### 模块四：事件雷达（Event Radar）

黄金对数据极度敏感，这一模块直接决定信号质量。

| 元素 | 内容 |
|---|---|
| 倒计时 | 最近一个 4 星事件：名称（中文）+ 剩余时间，<60 分钟变红 |
| 锁定窗口 | 事件前 15 分钟到后 10 分钟，页面顶部挂「数据锁定中，暂停价格信号」 |
| 本周列表 | 日期 / 时间 / 星级 / 事件名 / 影响品种，可折叠 |
| 历史反应 | 该事件上次公布后 30 分钟金价波动幅度（若有数据） |

**数据来源**：沿用现有任务的财经日历链路（TradingView → Investing → ForexFactory → FX678 降级），事件名强制中文。

## 六、数据与实时性方案

### 6.1 现实约束（必须先说清楚）

| 约束 | 说明 | 应对 |
|---|---|---|
| 调度最小粒度 1 分钟 | 且每次调度都是一次完整 agent 调用，成本高 | 后台采样 5-10 分钟一次，不做 1 分钟 |
| 抓取型数据源 | 现有金价技能是页面抓取，有失败率、有延迟 | 三级降级 + 新鲜度标识 |
| 网页无法主动推送 | 页面关掉就收不到提醒 | 推送由后台任务的输出承担，页面只负责"打开即见" |
| 跨域限制 | 页面直连行情接口可能被 CORS 拦截 | 双通道设计，接口不可用时退回快照 |
| 报价口径 | 需确认数据源给的是 XAU/USD 美元/盎司，还是人民币计价 | 进入待确认清单，页面必须标注口径 |

**诚实结论**：本产品是「**分钟级准实时**」，不是 tick 级。宣传口径必须一致，不承诺秒级。

### 6.2 双通道

| 通道 | 职责 | 频率 | 成本 |
|---|---|---|---|
| **A 页面直连** | 价格跳动体感、本地阈值提示 | 5-15 秒 | 零 token（纯前端 JS） |
| **B 后台引擎** | 状态判定、信号打分、推送、写快照 | 5-10 分钟 | 每次一次 agent 调用 |

页面优先用 A 的价格做显示，用 B 的状态做结论。**两条时间戳分别展示**，避免"价格是新的、判断是旧的"被误读。

### 6.3 数据降级链

```
主源（实时报价技能） 
  → 备源（第二行情技能） 
    → 最近快照（标注"快照 HH:MM"，不参与判定）
      → 中断（页面红色横幅，禁用一切实时结论）
```

连续 3 个采样周期取数失败 → 触发「数据异常」L3 通知，提示用户检查而非继续交易。

| 项 | 规定 |

## 八、告警与推送策略

| 等级 | 触发 | 通道 | 文案要求 |
|---|---|---|---|

## 十三、风险与待确认

### 13.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 行情源不稳定（抓取型） | 关键时刻没数据 | 三级降级 + 中断明确告警 + 不冒充实时 |
| 剧本无法自动解析 | 需手工录入关键位 | P0 支持手工填 6 个价位即可用，P2 再做自动解析 |
| 推送过多被无视 | 产品失效 | 冷却 + 单日上限 8 条 + 静默时段 |
| 状态机参数不适配当前波动率 | 误判频繁 | P0 参数可调（页面设置抽屉），P2 自校准 |
| 用户夜间无法响应 | 信号作废 | 支持"档位仅记录"模式 |

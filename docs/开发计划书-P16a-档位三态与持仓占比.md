## 一、两个需求

| 编号 | 需求 | 来源 |
|---|---|---|
| **P16a** | 档位标签拆成「已买 / 已买满 / 已买超」三种状态 | 用户：不能单独表示买满 |
| **P16b** | 持仓页新增「仓位进度」卡：总持仓 / 持仓上限 + 百分比 + 绿橙红渐进色块 | 用户：清晰展示当前占比 |

这是刻意的：v6.29 刚把摊派跑通，此时改口径会让「是显示错了还是算错了」分不清。

## 二、P16a：档位三态

### 2.1 现状的问题

`gearUI()` 现在只有两种持仓相关状态：

```
done = bought > 0.05 && pending <= 0.05   → 标签「已买入」
否则                                       → 按价格显示 未到 / 逼近 / 刚到价 / 已跌破
```

「已买入」这一个词背了两个意思：买满了、买过一部分。而「买超了」压根没有独立标签——
只在克重栏写「超买 8g」，另在行尾挂一枚「超预算」。

用户看到的结果：一档买了 8/16g 显示「已跌破」，一档买满 16g 显示「已买入」，
一档买了 24g（超 8g）显示「已买入」+「超买 8g」——三种完全不同的状态，标签只区分了两种。

### 2.2 状态定义

持仓维度**四态**（含「未买」），价格维度保持原样，两个维度同时可见：

| 持仓态 | 条件（容差 0.05g） | 标签 | pill 类 |
|---|---|---|---|
| 已买超 | `overG > 0.05` | 已买超 | `p-over` |
| 已买满 | `overG <= 0.05 && pending <= 0.05 && bought > 0.05` | 已买满 | `p-done` |
| 已买 | `bought > 0.05 && pending > 0.05` | 已买 | `p-part` |
| 未买 | `bought <= 0.05` | 沿用价格态 | 沿用 |

判断顺序必须是 **超 → 满 → 部分**，因为 `overG` 和 `pending` 互斥，但浮点下可能同时逼近 0，
先判超可以保证「超」不会因为 `pending` 恰好为 0 被误判成「满」。

### 2.3 两个维度怎么同时显示

`gearUI()` 返回的 `cls` 继续由**价格**决定（控制左侧圆点颜色、卡片描边、整行透明度），
`label` / `pill` 由**持仓**决定。这样：

- 买满的档如果价格还在上方 → 圆点灰、标签「已买满」（能看出「买过了但还没到价」是正常的）
- 部分买入的档如果已跌破 → 圆点红、标签「已买」+ 行尾「待补 8g」（能看出该补了）

⚠️ 唯一例外：买满时 `cls` 仍用 `s-done`（蓝色），因为「买满」在视觉上需要和「未到」区分，
这是 P6 就有的约定，不改。

### 2.4 克重文案跟着对齐

现在克重栏（`.pill.g`）的文案是：

```
overG > 0.05        → "超买 8g"
bought && pending   → "已买 8 / 待补 8g"
bought              → "已买 16g"
pending             → "待补 16g"
```

标签已经说了「已买超 / 已买满 / 已买」，克重栏就不要再重复「超买」「已买」：

| 状态 | 克重栏 |
|---|---|
| 已买超 | `24 / 16g`（实际 / 计划）+ 行尾「超预算」 |
| 已买满 | `16 / 16g` |
| 已买 | `8 / 16g` |
| 未买 | `待补 16g`（不变） |

用「实际 / 计划」一个格式贯穿三态，扫一眼就知道差多少，比「超买 8g」这种单一数字直观。

### 2.5 不动的部分

- `.pill.undo` 的点击撤销：仍然只在「已买满」时挂载（部分买入的档用行尾「撤销」按钮）
- 「估」角标：与持仓态完全解耦，四态都带（P13 + v6.30 已确立）
- 循环档的「买入 / 卖出」按钮：不动
- 账本模式的文案：只改标签，克重栏保持「已买 Xg / 待买 Xg」原样

## 三、P16b：仓位进度卡

### 3.1 位置

持仓页最上，`#posBox` 之前，新增 `<div class="card" id="posGauge"></div>`。

理由：先看「我现在几成仓」，再看「浮盈多少」。两者是不同层级的信息，
仓位是决策前提（还能买多少），盈亏是结果。

### 3.2 数据

```
current = holdStats().grams        账本实际持仓（Σ买入 − Σ卖出）
limit   = totalGrams()             设置页「目标总克重」
pct     = limit > 0 ? current/limit*100 : 0
```

**不取 `planSummary().bought`**——那是档位标记的合计，可能与账本不一致，
而这张卡要回答的是「账户里真有多少克」，必须以账本为准。

### 3.3 视觉规格

```
┌─────────────────────────────────────┐
│ 仓位进度                      62.5% │
│ ████████▓▓▓▓░░░░░░░░░░░  (20 段)   │
│ 125.0 g / 200.0 g      还能买 75.0 g│
└─────────────────────────────────────┘
```

- **百分比**：28px 等宽数字，颜色按区间（<60% 绿 / 60–85% 橙 / >85% 红）
- **进度条**：20 段等宽色块，`gap:2px`，高 10px，每段圆角 3px
  - 第 i 段颜色：`hsl(145 → 4)` 线性插值，即 145°(绿) → 85°(黄绿) → 42°(橙) → 4°(红)
  - 已达成段 `opacity:1`，未达成段 `opacity:.14`
  - 这样色块本身就从左到右由绿变红，「仓位越高越红」不需要额外图例
- **底行**：`125.0 g / 200.0 g`，右侧 `还能买 75.0 g`
- **超限**：`pct > 100` 时底行右侧换成红色「超上限 5.0 g」，百分比也标红

### 3.4 边界

| 情况 | 表现 |
|---|---|
| 无任何记录（0g） | 进度条全暗，百分比 0%，底行「0 / 200 g」，不显示「还能买」以外的提示 |
| 上限为 0 或未设 | `totalGrams()` 已兜底返回 100，按 100 算，不除零 |
| 超上限 | 20 段全亮 + 百分比红 + 「超上限 X g」 |
| 全部卖出 | 0%，与「无记录」同款展示（不显示空状态文案，卡还在） |

### 3.5 交互

点击卡片任意位置 → 跳到设置页「仓位」卡（复用已有 `jumpToSet("setHigh")` 或直接 `gotoTab("set")`），
让用户改上限。不加按钮，避免和「记一笔」抢视觉。

| # | 断言 |
|---|---|
| b1 | 0g / 200g → 显示 `0.0%`，20 段全暗 |

# PRD · P29 回测改同克重口径

> 版本目标：v6.47　｜　前置：P28（回测与设置联动，v6.45）
> 一句话：**回测不再问「这些钱能买多少」，改问「买这么多，三种方式各花多少钱」。**

---

## 1. 用户原话与四条需求

> 「区间天不可设置，看不出三种方式的模拟均价。预算也不能调整，到底是按总金额预算测算，还是按重量均价总价测算？让人一头雾水。」
>
> 「不限制总金额预算可行吗」
>
> 「1 不留，完全按克重买满，最后告诉你花了多少钱。3 我就是主要算策略，当然按档位价成交，如果按市价就没意义了。4 你的回测周期太长，我去年还没做这个软件，你回测出来有什么意思。所以最大区间周期要可设置或者自动获取。」
>
> 「同克重，三种方案比建仓成本和盎司均价。」

| # | 需求 | 现状 | 改后 |
|---|---|---|---|
| 1 | 预算上限 | 预算 = 配额克重 × 起点价，花完就跳过（740 天里跳过 949 次） | **取消**，按克重买满，产出「实际花了多少」 |
| 2 | 成交价 | 按档位价 | **不变**（用户明确要求，按市价就失去策略含义） |
| 3 | 区间 | 固定 740 天（800 根 − 60 预热） | 可设 90/180/365/全部/**自动**（首次建仓起） |
| 4 | 三组对照 | 同本金（都 $26,659） | **同克重**，比建仓成本与盎司均价 |

---

## 2. 为什么「同本金」必须让位

P19-2 起的对照逻辑是「三组都给同一笔钱，比期末谁多」。取消预算上限后这条自动失效：

```
本策略买满 300g 需要 $36,182
同本金只给 $26,659
→ 又回到「买不满」，正是需求 1 要废掉的方案
```

所以对照基准从「同样多的钱」换成「同样多的金子」。

**代价必须写在卡上**：三组克重相同时，期末市值必然相等（同一个克重 × 同一个期末价），
所以「谁的期末更值钱」不再成立，能比的只有 **建仓成本 / 盎司均价 / 收益率**。
收益率之所以还有差，是因为三组成本不同（`期末 ÷ 成本 − 1`）。

## 3. 口径定义

### 3.1 基准克重

以**本策略实际成交克重**为基准，三组都买这么多：

```
Gs = Σ 已触发档位的计划克重
```

- 十档全触发 → `Gs = 总克重配额`（300g）
- 只触发 7 档 → `Gs = 216g`，定投与一次性也只买 216g
- **一档未触发 → 对照表显示空态**（「本区间内没有档位被跌穿，无法对照」），不做除零

### 3.2 三组的成本

| 方案 | 买入节奏 | 成本 |
|---|---|---|
| 本策略 | 逐档，触及当日按**档位价**成交 | `Σ gram_i × p_i ÷ 31.1035` |
| 定投 | 每个交易日买 `Gs / 交易日数` 克 | `Σ 每日克重 × 当日收盘价 ÷ 31.1035` |
| 一次性 | 区间首日一次买满 `Gs` | `Gs × 首日收盘价 ÷ 31.1035` |

> 定投从「每天投固定金额」改为「每天买固定克重」—— 否则三组克重不同，就不是同克重了。
> 沿用现有「每天等额」的节奏，不改成每周，避免多一层周对齐逻辑。

### 3.3 盎司均价

```
均价($/oz) = 成本 × 31.1035 ÷ 克重
```

三组各一个，同列可比。一次性恒等于区间首日收盘价（用于自查口径是否算对）。

### 3.4 收益率

```
期末价值 = Gs × 末日收盘价 ÷ 31.1035     ← 三组相同
收益率   = 期末价值 ÷ 成本 − 1            ← 因成本不同而不同
```

## 4. 区间

### 4.1 选项

| 选项 | 含义 | `i0` |
|---|---|---|
| 90 天 | 最近 90 根 | `max(60, n − 90)` |
| 180 天 | 最近 180 根 | `max(60, n − 180)` |
| 365 天 | 最近 365 根 | `max(60, n − 365)` |
| 全部 | 数据源全部 | `60` |
| **自动** | 从首次建仓那天起 | `max(60, 首次建仓日对应索引)` |

- 预热 60 根始终保留：高点的计算窗口是 `bars[0, i0)`，区间只决定「从哪根开始交易」
- **自动**取 `S.cfg.buys` 里最早的 `time`；没有买入记录 → 退化为「全部」，并在卡上写明
- K 线不足所选区间时，取全部可用，不报错

### 4.2 周期与区间的关系

| 周期 | 区间控件 | 原因 |
|---|---|---|
| 日线 | 显示，按「天」 | 1 根 = 1 天 |
| 周线 | 显示，按「周」（90 天 ≈ 13 周） | 换算后取整 |
| 4 小时 | **隐藏**，固定全部 | 750 根只有约 125 天，按天设无意义 |
| 1 小时 | **隐藏**，固定全部 | 1000 根只有约 42 天 |

切换周期时区间设置保留在 `cfg` 里，但只在日线/周线生效。

## 5. 卡片信息变化

### 5.1 参数条

```
档位来源  [设置 $4,696] [当时 $2,760]
区间      [90天] [180天] [365天] [全部] [自动]
10 档 · 档距 $57.8 · 配额 300 g · 下沉 关
```

### 5.2 预算行 → 成本行

改前：`预算 $26,659 · 档位高点 H $4,696 · 区间 740 天`
改后：`满仓成本 $36,182 · 实际花费 $36,182 · 档位高点 H $4,696 · 区间 740 天`

- 「满仓成本」= 全部档位按档位价买满的金额（参考值，不再是约束）
- 「实际花费」= 实际成交的金额；未买满时两者不等，差额即未触发部分

### 5.3 对照表

```
方案      克重     建仓成本     盎司均价    收益率
本策略    300 g    $36,182     $3,751     +5.36%
定投      300 g    $36,712     $3,806     +3.84%
一次性    300 g    $26,659     $2,764     +42.99%
────────────── 期末 300 g 值 $38,121 ──────────────
```

- 表头下一行小字：`三组克重相同，期末价值相同；差异在成本`
- 移除「本金」「期末」「回撤」三列中的「本金」；「期末」提到表尾说明
- 回撤列保留（三组路径不同，回撤仍不同）

### 5.4 说明文案（三段）

1. 这张卡回答：**买同样多的金子，三种方式各花多少钱**
2. 档位来源：设置 / 当时（前视偏差说明，随 `heightSrc` 切换）
3. 口径：**按档位价成交 · 无预算上限 · 不折算汇率 · 不含盘中路径**

## 6. 已知偏差（必须写在卡上）

「设置高点」模式下，档位价可能整体高于区间市价，导致本策略比一次性贵：

```
档位 3,518–4,039（按今天高点 4,696 算）
2024-10 市价 2,756
→ 首日全部跌穿，按档位价成交
→ 本策略 $3,751/oz vs 一次性 $2,764/oz，贵 35.7%
```

这不是算错，是「用今天的高点套历史」的必然结果。三条措施：

1. 卡上显示 `区间内金价 $2,764 → $3,952（+43.0%）`，让用户自己判断档位是否合理
2. 区间可缩短后，该偏差自然减小（档位贴近当前价）
3. 说明段明写：`按今日档位回看历史，档位整体高于市价时，本策略成本会高于一次性`

## 7. 对既有字段的影响

| 字段 | 现状 | 改后 |
|---|---|---|
| `meta.budget` | 预算上限，约束买入 | **满仓理论成本**，仅显示 |
| `stats.cash` | 剩余现金 | **删除**（恒 0） |
| `stats.usage` | 投入 / 预算 | **删除**（失去意义） |
| `stats.skipped` | 预算不足次数 | **删除** |
| `stats.invest` | 实际投入 | 保留（= 实际花费） |
| `peers.*.invest` | 投入 | 改名 `cost` |
| `peers.*.gram` | 无 | **新增** |
| `peers.*.avgOz` | 无 | **新增** |
| `meta.range` | 无 | **新增**：`{kind:"90d"\|"180d"\|"365d"\|"all"\|"auto", roots:n, note?:string}` |

云端旧数据（`cfg.btOpts`）无需迁移：`btOpts` 只存 `loop / reallocOverride / fee / height`，
本次新增 `range` 字段，缺省 `"all"`，不影响老配置。

## 9. 不做

- 不做「按金额测算」的第二种模式（用户明确不留预算）
- 不做盘中逐笔成交（沿用日线高低点判定，`不含盘中路径` 保持）
- 不做自定义起止日期（本轮只给固定档位 + 自动）
- 不改「当时高点」模式的行为（保留作对照视角）

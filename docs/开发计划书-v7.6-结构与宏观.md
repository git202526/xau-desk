## 1. 目标与非目标

### 1.1 目标

1. **L0 数据管道**：Actions 定时抓 Dukascopy 原始分钟线，清洗、聚合出 1h/4h/1d，落同源 JSON。
2. **L1 清洗层**：识别并剔除休市填充根，记录缺口，供图表断开。
3. **L2 引擎**：`boxDetect` / `patternTags` / `arbitrateStructure` / `macroJudge`，输出一块快照。
4. **L3 融合**：宏观新开一张卡（全站唯一新卡）；结构结论只改文字，不新增结构卡。

### 1.2 非目标

- 不改 `channelOf` / `adxOf` / `atrOf` / `computeStruct` / `judgeOne` / `verdictText` / 事件雷达渲染。
- 不引入前端外部依赖，图表仍手写 SVG。
- 不做 tick 级回放、不做成交量分析（Dukascopy 的 `volume` 是 tick 计数，不是真实成交量）。

## 2. 数据源：Dukascopy 原始文件（已实测可用）

### 2.1 地址与格式

```
https://datafeed.dukascopy.com/datafeed/XAUUSD/{YYYY}/{MM}/{DD}/BID_candles_min_1.bi5
```

| 项 | 实测值 |
|---|---|
| 可用性 | Actions 200，LZMA 解压成功；沙箱超时（出口被拦，**不能在前端直连**） |
| 路径月份 | **0-based**（`08` = 9 月，`09` = 10 月） |
| 每条 | 24 字节，大端 `>IIIIIf`：`time, open, close, low, high, volume` |
| `time` | **当日秒偏移**（0–86340），不是 Unix 秒 |
| 价格 | 整数 ÷ 1000（XAUUSD digits=3） |
| 日容量 | 1440 条，**含休市填充根** |
| 日线/小时线文件 | **404**，只有分钟级，1h/4h/1d 必须自己聚合 |
| 价格类型 | **BID 买价**，与 spot 差 0.3–0.5 美元，页面标注 |

### 2.2 管道

```
Actions（*/15）→ fetch_xau.py
    ├─ 回填：近 100 天，串行 + 重试（并发会丢请求，本轮实测 3/7 返回空）
    ├─ 解压 → 清洗（丢填充根）→ 聚合 1h / 4h / 1d
    └─ 写 xau/klines.json（同源静态文件）
前端 fetchKlines()
    ├─ 优先 xau/klines.json（同源，无 CORS）
    ├─ 失败或 updated 超 30 分钟 → 降级 PAXG，并标注「K 线：PAXG 代用」
    └─ 保留 applyScale()，把 BID 序列缩放到实时 spot
```

**为什么必须走 Actions**：`datafeed.dukascopy.com` 无 CORS，浏览器直连必失败；沙箱出口也不通。这与金十日历是同一套中转模式，无新增基础设施。

### 2.3 聚合口径（写死）

| 周期 | 切分 | 依据 |
|---|---|---|
| `1h` | UTC 整点，60 根/根 | 行业惯例 |
| `4h` | UTC 00/04/08/12/16/20 | 与现有 PERIODS 对齐 |
| `1d` | **纽约 17:00 收盘** = UTC 22:00（冬令时）/ 21:00（夏令时） | 黄金交易日以纽约收盘为界；按 UTC 零点切会把一个交易日劈成两根 |

聚合前必须先清洗，否则填充根会把当根 `h/l` 拉平。

### 2.4 实测结果（2026-11-08，已落盘）

| 周期 | 根数 | 区间 | 真缺口 |
|---|---|---|---|
| `1d` | **100** | 2026-06-21 → 11-05 | 0 |
| `4h` | **654** | 2026-06-12 → 11-06 20:00 | 0 |
| `1h` | **2424** | 2026-06-12 → 11-06 21:00 | 1（4 小时，源侧缺失） |

- 回填 150 天：146 天成功、1 天休市空、3 天失败（其中 2 天是周六，本无文件）
- **`synthetic = 66214`**：150 天里被剔除的填充根数量，证明清洗层确实在工作
- 首次回填耗时约 17 分钟（并发 4 + 补漏轮）；日常 4 天增量 < 30 秒

两条踩坑记录，写进代码注释，别再犯：

1. **周末返回 403 而非 404**。只认 404 会把每个周末当网络故障重试 6 次，110 天回填跑满 40 分钟超时；改成 `403/404` 都视为无文件后，150 天 17 分钟跑完。
2. **`gaps` 必须区分 `session` 与 `missing`**。150 天里 105 个间隔全标成 gap，其中 21 个周末 + 84 个每日结算停盘都是正常休市，真正的缺日（1 天）被淹没。现在按「间隔中点是否落在闭市区间」判 kind。

## 4. L1 清洗层（XAU 版，与 PAXG 稿相反）

### 4.1 三条规则

| 规则 | 判据 | 动作 |
|---|---|---|
| 合成填充根 | `v === 0 && o === h && h === l && l === c` | **丢弃**，计入 `synthetic` |
| 重复时间戳 | 同 `t` 只留最后一根 | 丢弃，计入 `dup` |
| 缺口 | 相邻 `t` 差 `> 1.6 × 周期` | **不删**，写 `gaps:[{i,from,to,ms}]` |

判据要**同时满足四条**才丢：只看 `v=0` 会误杀低流动性时段的真实窄幅根；只看四价相等会误杀有量的十字星。

### 4.2 休市双保险

Dukascopy 的填充根不可能 100% 靠数值识别（有的时段 `v` 是 0.01 而非 0）。再加一层日历判定：

```js
isClosedAt(ts)   // UTC：周五 ≥22:00、周六全天、周日 <22:00
```

- 闭市时段的根：即使数值不像填充根，也**不计入触碰计数**
- 闭市时段仍然画图（用户要看周五最后的价格），只是标记为休市

### 4.3 `lastT` 必须取**清洗后**的真实末根（与 PAXG 稿相反）

PAXG 没有填充根，所以上一稿要求 `lastT` 取 raw；**XAU 相反**：raw 末根在周日可能是 23:59 的填充根，若记成 `lastT`，周一开盘的增量会从周日 23:59 续，把整段假数据当成已覆盖。

```js
S.klMeta[key] = { at: now, lastT: clean.bars[clean.bars.length-1].t, mode: r.mode };
```

### 4.4 缺口豁免（否则每个周一都会回退全量）

`fetchKlines:1879` 现在判定「增量首根 - lastT > 周期 → 有洞 → full」。周末 48 小时天然超周期，不改会**每周一必回全量**。

```js
function gapIsWeekend(fromT, toT){
  return isClosedAt(fromT + 1000) && isClosedAt(toT - 1000);
}
if (bars[0].t - lastT > pm && !gapIsWeekend(lastT, bars[0].t)) return full();
```

### 4.5 与 `patchFormingBar` 的顺序

固定：`抓取 → S.kl(raw) → sanitize(副本) → patchFormingBar(只改未收盘的真实根) → 计算`。

`patchFormingBar:1898` 要加一道判断：末根若是填充根（`v=0 && 四价相等`），**不 patch**，否则它会被实时价改成一根“看起来真实”的假根，清洗层再也认不出来。

## 5. L2 引擎（保留上一稿，仅会话口径按 XAU 修正）

### 5.1 会话判定

```js
marketOpenAt(ts) → { open, label }
```

| 时段 | 判定 | 说明 |
|---|---|---|
| 周末 | 周五 22:00 UTC → 周日 22:00 UTC 闭市 | 冬令时开盘顺延 1 小时，只影响标签 |
| 每日结算 | 纽约 17:00–18:00（UTC 22:00–23:00 冬 / 21:00–22:00 夏） | 用户口径「北京 05:00–06:00」即此段 |
| 其余 | 开市 | — |

`open=false` 时：`box.frozen=true`、`evaluated=false`、闭市根不计触碰；**结构照常显示**，`warning` 写「休市中 · 结构停留在 MM-DD HH:mm」。不隐藏蜡烛、不清空 `#chLine`。

### 5.2 `boxDetect`

```js
boxDetect(bars, opt) → { valid, upper, lower, touch_up, touch_dn, width,
                         width_atr, atr, adx, slope_atr, breakout,
                         frozen, evaluated, reason }
```

| 项 | 判据 |
|---|---|
| 窗口 | 最近 30 根（不足用 20） |
| 水平 | `|slope_atr| < 0.05` |
| 触碰 | `|h−upper| ≤ tol`，`tol = min(0.25×ATR, 宽度×8%)` |
| 持续 | 首末触碰间隔 ≥ 10 根 |
| 宽度 | `(upper−lower) > 2×ATR14`，字段带周期：`width_atr_1d` / `width_atr_4h` |
| 突破 | 收盘破边 + 0.5×ATR = 真突破；盘中刺破后收回 = 假突破 |
| 闭市 | 闭市根不计触碰；`frozen=true` 时沿用上一有效快照 |

### 5.3 `patternTags`：六形态，只出标签

| 形态 | 判据（30 根，ATR 归一） |
|---|---|
| 对称三角 | 高点斜率 < −0.02、低点 > +0.02、末段振幅 < 首段×0.6 |
| 上升三角 | `|s_h| < 0.02`、`s_l > +0.02`、末段收窄 |
| 下降三角 | `|s_l| < 0.02`、`s_h < −0.02`、末段收窄 |
| 喇叭形 | `s_h > +0.02`、`s_l < −0.02`、末段振幅 > 首段×1.4 |
| 旗形 | 旗杆 ≥5 根同向、位移 >3×ATR；旗面 8–20 根、振幅 <1.5×ATR、回撤 <50% |
| 头肩顶/底 | 5 摆动点、头最高、两肩差 <15%；未破颈线「待确认」，破线「已破颈线」 |

最多输 2 个；`dominant` 计算**不读**其返回值（T108 反向证明）。

### 5.4 `arbitrateStructure`

| 条件 | `state` | `dominant` | `confidence` |
|---|---|---|---|
| 日线开盘缺口 > 0.8×ATR14 | `跳空` | `事件跳空` | High |
| 日线 ADX > 25 | `通道` | `通道为主` | High |
| 日线 ADX < 20 且 `box.valid` | `箱体` | `水平箱体` | High |
| 日线 ADX 20–25 且 `box.valid` | `双结构` | `双结构并存` | **Low** |
| 日线 ADX 20–25 且 `!box.valid` | `过渡` | `通道为主` | Low |
| 日线 ADX < 20 且 `!box.valid` | `无结构` | `无结构` | Low |

`state` 答形态，`dominant` 答谁主导，两者不互相兜底；`trend_state` 用 **4H ADX**，`dominant` 用**日线 ADX**，JSON 分 `adx_4h` / `adx_1d`，文案必须带周期。

### 5.5 `macroJudge`

```js
macroJudge(raw) → { tips_10y:{value,change_bp,trend_5d,as_of},
                    dxy:{value,change_pct,trend_5d,as_of,src},
                    macro_status, exceptions, confidence, note, stale }
```

| 场景 | 处理 |
|---|---|
| `fetched_at` > 90 分钟 或 抓取失败 | `macro_status="数据延迟"`，数值 `--`，不参与方向 |
| `as_of` 是上一交易日 | 正常，卡片写「数据截至 MM-DD」 |
| TIPS `|Δbp| ≥ 1.5` / DXY `|Δ%| ≥ 0.10`（广义美元 0.08） | 才算有方向 |
| `DXY↑` 且金价日涨 | `exceptions=["背离：美元与金同涨，可能是避险或流动性因素"]`，置信降 Medium |

不接 VIX/SPX，其余情形一律「无」，**不猜**。

## 7. 图表：等距索引 + 真缺口断开

**不做时间映射**。理由：时间映射会把 48 小时周末压成半屏空白，且 `channelOf` 是索引回归，改映射后通道线要逐根取 `X(d[i].t)`，改动面从 3 行变 30 行。

做法：X 仍按索引等距，只在 `gaps` 处把通道带与均线切成多段，段间 `M` 重新起笔。蜡烛逐根画，天然不跨界。

验收：`gaps.length = k` → 通道带 `<polygon>` 数 = `k+1`，无跨 gap 的连续 path。

### 18.2 三处取舍

1. **结构结论永远标「日线」**：`#chLine` 会随周期切换显示 4H / 1H 的通道，
   但仲裁只看日线。结论行固定写「日线 · 主导：…」，切周期时读者不会误以为是当前周期的判断。
2. **趋势中箱体一律作废**：ADX > 25 时即使数据本身满足箱体条件，也写
   「日线 ADX > 25，趋势中不判箱体」。两套结论同时成立等于自相矛盾。
3. **宏观卡不做隐藏**：404 时卡片仍在原位，显示 `--` 与「数据延迟」。
   藏起来会让人以为「本来就没有这个模块」，显示 `--` 才知道是数据没到。

## 21. P108 部署流程优化（2026-11-09 · 已部署）

§20.2 和 §20.3 记了两件事：一次性的 API 推送脚本，和它把 `klines.json` 覆盖回退的失误。
这一期把这两件事收成一条可复用的部署链路，而不是每次上线现场写代码、每次都靠人盯。

### 21.1 改了什么

| 项 | 之前 | 之后 |
|---|---|---|
| 推送 | 临时脚本 `push_api.py`，commit sha 与文件列表硬编码 | `tools/deploy.py`，参数化、可重复执行 |
| 差异 | `git diff --name-only <a> <b>` 手工给两个 sha | 本地算 git blob sha，与远端 tree 逐条比 |
| 数据回退 | 靠人推完后对比 `updated` 字段 | 推前自动比对，旧于远端直接拦下 |
| 空提交 | 可能产生 | 无差异不提交（Actions 每小时跑，空提交会刷满历史） |
| 部署后校验 | 手工拉线上看版本串 | `--verify` / `--wait` 自动比 sha256 |
| 门禁 d2 | `远端 sha == 本地 HEAD`，API 部署下**恒红** | `远端 index.html blob == HEAD:index.html blob` |

### 21.2 两道闸的判据

**闸一 · 内容差异**。`git_blob_sha(raw) = sha1("blob <len>\0" + raw)` 与 GitHub tree 里的
sha 是同一算法，所以本地不需要下载远端文件就能判「变没变」。远端独有文件默认保留
（`--prune` 才删）——Pages 产物、Actions 刚写的数据都在远端，本地缺失不等于该删。

**闸二 · 数据新鲜度**。`DATA_STAMPS` 声明每个数据产物的时间戳字段：

| 文件 | 字段 | 形态 |
|---|---|---|
| `xau/klines.json` | `updated` | 毫秒 epoch |
| `calendar.json` | `updatedAt` | ISO |
| `macro.json` | `fetched_at` | 毫秒 epoch |
| `jin10/calendar.json` | `updatedAt` | ISO |
| `jin10/state.json` | `cache["calendar.json"].at`，退 `day` | 秒 epoch / 日期 |

本地 `<` 远端（1 秒容差）→ 记 `stale`，跳过该文件、其它照推。
读不出时间戳记 `unknown` 且**不拦**：代码文件天然落在这里，瞎拦比放行更危险。

### 21.3 实测：闸门确实在工作

首次 `--dry-run` 就把四个数据文件同时拦下（本地副本都比 Actions 新写的那份旧）：

```
远端 HEAD c264c220 ｜ 工作区 241 个文件 ｜ 相同 235 ｜ 待处理 6
  add    tests/test_p108_deploy_tool.py  (非数据文件)
  add    tools/deploy.py  (非数据文件)
  拦下 calendar.json：本地 11-08 20:31 旧于远端 11-09 11:51（线上数据不倒退）
  拦下 jin10/calendar.json：本地 11-08 23:32 旧于远端 11-09 10:39
  拦下 jin10/state.json：本地 11-08 23:32 旧于远端 11-09 10:39
  拦下 macro.json：本地 11-09 10:01 旧于远端 11-09 11:36
dry-run：以上 2 个文件会被推送，未写远端
```

§20.3 那次事故正是「四个里推了一个」的后果；现在同一场景下四个全拦，无需人工判断。

### 21.4 门禁 d2 为什么必须改判据

API 部署的 commit 以远端 head 为 parent、tree 与本地一致，但 **sha 与本地 HEAD 必然不同**
（commit 对象内容不同）。旧 d2 断言 `remote_sha == local_sha`，在这种部署方式下
**永远红**——红得没有信息量，久了就会被 skip 掉，等于门禁失效。

新判据分两级：

1. `ls-remote` 拿远端 sha，等于本地 HEAD → 过（普通 `git push` 路径，最快）
2. 不等 → API 取远端 tree 里 `index.html` 的 blob sha，与 `git rev-parse HEAD:index.html` 比
   - 相同 → 过，并说明「远端 commit 与本地不同，内容一致」
   - 不同 → 红，提示 `python3 tools/deploy.py`

只比 `index.html`：它是线上唯一入口，Actions 不会碰它，所以不会因为云端数据更新而误报。

### 21.5 验收

| 项 | 结果 |
|---|---|
| 新增单测 | `tests/test_p108_deploy_tool.py` 25 条（sha 算法 / 时间戳三种写法 / 忽略规则 / 三分类 / 四类闸门 / dry-run 不写远端 / 无差异不提交） |
| 全量回归 | `pytest -n 8` **1132 条 0 失败** |
| 上线门禁 | `-m deploy` 5 条：d2 在 API 部署的既有状态下**通过**（旧版必红） |
| 真实部署 | 本次即用 `tools/deploy.py` 推上去，`--wait` 校验字节一致 |

### 21.6 已知限制

- 本地 `origin/main` 引用不随 API 部署更新，`git status` 可能提示 ahead —— 引用陈旧，非未上线。
  恢复普通 git 流程需在网络好时 `git fetch` 一次。
- 远端 tree 用 recursive 一次取完，超 10 万文件会被截断；本项目 240 余文件，不构成问题。

### 23.5 结算口径与全期校验

公式一行没改，但把口径写进了用例，防止后续「顺手优化」改坏：

```
avg      = Σ买入金额 ÷ Σ买入总克      // 分母是买入总克，不是余额
grams    = Σ买入克 − Σ卖出克
realized = Σ卖出金额 − Σ卖出克 × avg
```

T135 走单步：买 100@800、卖 20@900 → `avg` 恒 800、`realized` +2000。
T136 走全期：再卖 80@950 → 清仓后 `realized` 必须等于 `94000 − 80000 = 14000`。
后者比前者难糊弄 —— 任何「卖出改了均价」「realized 用卖出均价算」的错误都会在这里露馅。

### 23.6 两条轨没有合并

`markSell`（档位标记卖出）与 `saveSell → allotSell`（记账卖出）写的是同一组字段
`gearMarks[k].sold`。两条都做一次，档位会双扣（持仓只扣一次，因为标记路径不碰账本）。
合并要动 P20 单模式的核心假设，风险大于收益，本期只改文案、不合并，并在 PRD §8 记了这笔账。

## 24. P111 多周期依据可点开 + 判定链修复（2026-11-09 · v7.8）

### 24.1 判定链（从 K 线到一句话结论）

```
S.kl[1w/1d/4h/1h]              Actions 落盘的 XAU/USD（失败降级 PAXG）
      ↓ scaled(k)              汇率缩放（只改数值，不改五条条件的真假）
judgeOne(bars)                 单周期：5 条 / 4 维，≥60 根才判
      ↓ 四份 {state, upN, dnN, upC, dnC, adx, rsi, bars}
structCore(p)                  合成：方向 / 形态 / 置信 / 触发
      ↓
#pgrid 四卡 · #reasons 依据 · #vMain 结论 · #chLine + .pnote 融合
```

**单周期 5 条（一维一票，反向五条是镜像）**

| 维度 | 条件 | 判据 |
|---|---|---|
| 趋势（排列） | 价格站上 MA20 且 MA20 > MA60 | 纯大小关系 |
| 趋势（斜率） | MA20 日变动 > 0.05 ATR | 用 ATR 归一，跨品种可比 |
| 结构（摆点） | 高低点同步抬高 / 下移 | 需各 2 个摆点 |
| 动量 | MACD 柱在零轴上方 / 下方 | 符号 |
| 强度 | ADX ≥ 25 且 +DI 占优 / −DI 占优 | 趋势有没有力气 |

≥3 条成方向，两侧都不到 3 判震荡。**预热 60 根**取三者最大值：MA60、摆点回看 39、ADX(14) 双平滑 28。

**合成（`structCore`）**

| 项 | 规则 |
|---|---|
| 权重 | 周 0.10 / 日 0.50 / 4h 0.40 / **1h 0** |
| 方向 | 日线定；日线缺判定时才退回合力分（±0.18） |
| 二对一否决 | 周线与 4h **同时**反向才作废；单周期反向只降级 |
| 形态（顺序判定） | nodata → notrend → veto → counter → diverge → align → mixed |
| 置信 | 方向置信 = 同向占比，强度 = 日线 ADX/40；`conf = base×62 + str×38` |
| 置信上限 | 投票者 <2 → 40；counter → 60；日线 ADX <20 → 55 |
| 触发 | 1h 与日线同向 → on（不参与方向与置信） |
| 回溯 | `btRun` 对每根历史 K 线跑 `judgeOne(slice)`，与当前判定同源 |

### 24.3 两个实现细节

**事件绑容器不绑卡片。** `renderStruct` 每次 `innerHTML =` 重建四张卡，绑在卡片上的
监听器第一次自动刷新（15 秒）就没了。绑 `#pgrid` 用事件委托，`closest(".pcard")` 取
`data-k`，重绘多少次都有效。

**`sanitizeHtml` 会吃掉属性。** 它按白名单逐属性过滤，原白名单只有
`class|value|data-*|title|aria-label`。`role` / `tabindex` / `aria-pressed` 会被删掉，
读屏器和键盘都读不到「这是一张可以按的卡」。补进白名单后再渲染。

### 24.4 选择只存内存

`S.reasonK` 不落盘，刷新回日线。理由是数据源按天更新：上次停在周线、当天周线恰好
没拉到，一进来就是「周线数据不足」，用户会以为整个模块坏了。日线是唯一必定有数据的周期。

### 24.5 顺手对齐的一处展示

1 小时自己震荡时，卡片小字从「—」改成「2/5 · 不投票」。「—」只该表示「触发无从
谈起」（日线震荡 / 方向被否决）；它自己震荡时，条件数才是读者要的信息，写「—」
等于把这一格清零。T157 锁住。

### 24.6 看过但没动的

- `structCore` 的「反向条件满足 3/5 → 已构成反向信号」是死分支：`state` 优先正向，
  `state=up` 时 `dnN` 必然 <3。只影响一句文案，不影响判定，本期不动。
- `judgeOne` 算了 RSI 但只写描述、不进 5 条条件。这是设计（RSI 与动量维度重复），非 bug。
- 1 小时权重 0 但仍算完整 5 条，只为展示与回溯，不改。

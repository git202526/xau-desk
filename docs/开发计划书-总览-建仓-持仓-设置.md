> 对应版本：XAU Desk v7.12.2（单文件 `index.html`，13209 行）
> 配套文档：`PRD-总览-建仓-持仓-设置.md`（规则口径）、`README-规则适配.md`（移植契约）

## 1. 目标与约束

### 1.1 目标

在不引入构建工具、不引入外部依赖的前提下，实现一条「看价 → 算档位 → 记账 → 算减仓」的完整闭环，并保证：

1. **数字可对账**：任意时刻，界面上的每个数都能由「配置 + 买卖记录 + 档位标记」重算出来，没有隐藏状态。
2. **口径唯一**：同一个概念（均价、持仓、成本）全站只有一个公式，任何两处显示同数。
3. **可离线**：断网后仍能看（只读快照），联网后自动回到云端版本。
4. **规则可移植**：计算层不依赖 DOM，可整段搬到别的运行时（见 README 的移植边界）。

### 1.2 硬约束

| 约束 | 具体要求 | 原因 |
|---|---|---|
| 单文件 | 全部 CSS/JS 内联，一个 `index.html` | 用户只会保存一个文件；CDN 404 会让功能全废 |
| 零依赖 | 不引任何框架、字体、图表库 | 同上 |
| 图表手写 | 内联 SVG | 同上 |
| 图标内联 | SVG path，**禁用 emoji** | emoji 在不同系统渲染差异大，且无法着色 |
| 移动优先 | 窄屏 < 768px 单列；按钮 ≥ 44×44；输入框字号 ≥ 16px | iOS 会在 < 16px 时自动放大页面 |
| 数据单一来源 | GitHub 私有仓库 `data.json`；浏览器只存令牌与只读快照 | 多设备一致 |
| 不造数 | 缺数据一律 `--` | 估算值冒充事实会误导决策 |

### 1.3 规模控制

单文件已 1.3 万行，继续增量必须遵守：

- 新增功能前先估算行数；单次改动 > 400 行时拆成多次提交，每次保持可运行。
- 新增卡片不得让 `refreshAll()` 单次耗时超过 30ms（144Hz 屏幕上 8ms 才不掉帧，务实目标 30ms）。
- 页面模块数控制在 6 个 Tab 内，不再增加 Tab。

## 3. 数据模型

### 3.1 顶层状态 `S`（内存态，不落盘）

```js
var S = {
  price, prev, prevClose, fx, fxAt,       // 行情
  kl: {"1w":[], "1d":[], "4h":[], "1h":[]}, // K 线（已按缩放系数处理）
  struct, verdict, levels, gears, takes,   // 计算产物
  reasonK: "1d",                           // 结构页当前看哪个周期（只存内存）
  setTouch: {},                            // 设置页哪些输入被真实碰过（只存内存）
  chPeriod, chan, levelWin,                // 图表与关键位
  cal: {ok, events, updatedAt},            // 日历
  cfg: { /* 见 3.2，唯一持久化载体 */ },
  tab, acctFilter, tradeFilter,            // 界面态（acctFilter 不写配置）
  reallocDead: {},                         // 配额下沉滞回（内存，不落盘）
  gearMeta: {},                            // computeGears 的 meta 挂载点
};
```

**关键取舍**：`setTouch` 与 `reallocDead` 放内存不落盘。

- `setTouch`：刷新后应重新开始计数，否则"上次碰过但没保存"会永久挂着一个脏标记。
- `reallocDead`：滞回状态依赖"上一刻的价格"，落盘后隔夜重开会把昨天的失效态带进来。

### 3.3 三类记录的字段

**买入记录 `buys[]`**

```js
{
  id: "b" + Date.now(),
  name: "第2档",
  gram: 8,                 // 克（唯一统计口径）
  priceCny: 931.42,        // 元/克（用户填的实付）
  time: "2026-11-16T05:00:00.000Z",
  note: "",
  gear: "第2档" | null,    // 档位归属；null = 未标档
  acct: "a0",
  up: 1750000000000        // 合并用的编辑时间戳
}
```

**卖出记录 `sells[]`**：同上，另加

```js
{
  id: "s…",
  allot: {"2": 12.0, "3": 8.0}   // 这次实际摊到哪几档、各多少克（快照）
}
```

**档位标记 `gearMarks{}`**

```js
"2": {
  g: 16.0,            // 累计买入克重（毛）
  cost: 21600.00,     // 累计买入成本（美元，估算用途）
  costCny: 14890.50,  // 累计实付人民币（唯一主口径）
  sold: 4.0,          // 累计卖出克重
  proceeds: 8880.00,  // 累计卖出所得（美元）
  proceedsCny: 6120.00,
  at: 1750000000000,
  fromBuys?: true,    // 由买入记录重算得来
  fromReset?: true    // 由「重算档位」得来
}
```

**净持仓 = `g − sold`**。所有"已买多少"的判定都用净持仓，不用 `g`。

### 3.4 版本迁移

```js
var SCHEMA = 3;
function runMigrations(){ /* 依次跑 v7 / v8 / v9 三段，幂等 */ }
```

| 版本 | 迁移内容 |
|---|---|
| v7 | `gearsDone` 字符串数组 → `gearMarks` 对象；旧 `at` 保留 |
| v8 | 标记补齐 `costCny` / `proceedsCny`（缺则 0，不猜） |
| v9 | 引入 `accounts`；所有记录补 `acct`，缺省归 `a0` |

**约束**

- 迁移入口**只允许一处**（`runMigrations`），不允许散落在各读取点。
- `schemaVersion > SCHEMA`（未来版本）时**只读不写**，不自动降级。
- 归一化（`normCfg`）必须在**读入、保存前、迁移后**三处都跑。

## 4. 分层架构

### 4.1 三层

```
┌─────────────────────────────────────────┐
│ 渲染层  renderXxx()  —— 只读 S，只写 DOM │
├─────────────────────────────────────────┤
│ 计算层  computeXxx() —— 纯函数，不碰 DOM │
├─────────────────────────────────────────┤
│ 数据层  loadCfg/saveCfg/markXxx/buy      │
└─────────────────────────────────────────┘
```

**调用方向只能自上而下**（渲染 → 计算 → 数据）。数据层不回调渲染层。

### 4.2 统一刷新入口

```js
function refreshAll(){
  renderHero(); renderVerdict(); renderOv(); renderTodo(); renderBadges();
  renderStruct(); renderChart(); renderEventCard(); renderBoxCard();
  renderMacroCard(); renderFusion(); renderBt(); renderKL();
  renderMarks(); renderLadder(); renderGearSrc(); renderAvgCard();
  renderSetGear(); syncKeepDisplay(); renderGauge(); renderPos();
  renderAcctCard(); renderReview(); renderBuys(); renderTake();
  renderEvents(); renderFeed(); renderStat(); renderDirtyBar(); setConn();
}
```

**顺序有依赖**：`renderSetGear` 必须在 `compute()` 之后（读 `S.gearMeta`）；`renderPos` 在 `renderGauge` 之后（同屏上下关系，避免数字跳）。

**唯一计算入口**

```js
function compute(){
  S.struct = computeStruct();
  S.levels = buildLevels(12);
  S.levelWin = levelWindow();
  S.gears  = computeGears();     // 内部写 S.gearMeta
  S.takes  = computeTakes();
  S.prevClose = prevDayClose();
  trackChanges();
  if(tickDrip()) saveCfg();      // 兜底计时变了才落盘（价格 tick 不产生写入）
}
```

**事件处理的标准三段式**

```
用户操作 → 改数据（saveCfg / markXxx） → compute() → refreshAll()
```

**禁止**：在 `renderXxx()` 内部调用另一个 `renderYyy()`。需要联动时在事件处理里调 `refreshAll()`。

### 4.3 计算层的纯函数边界（可移植）

| 纯函数（无副作用、可整段搬走） | 非纯（依赖 DOM / 存储 / 全局 S） |
|---|---|
| `gearPrices` `spanForTarget` `spanRange` `spanUsd` `p1Of` `wCenter` `frontCenter` `anchorCenter` `anchorKOf` | `gearBase`（读 `S.cfg` + `computeHEff`） |
| `planBase` `planOf` `reallocPlan` `splitByGram` `allotSell` `allocUnits` | `computeGears` / `computeTakes`（写 `S.gearMeta` / `S.takes`） |
| `planAvgOf` `avgOfFront` `hitProb` `gearRealized` `gearTurns` `computedKeep` | `markBuy` `markSell` `saveCfg`（写存储） |
| `normW` `normSwing` `normAlertGears` `cleanGearMarks` | `normCfg`（读写 `S`） |
| `takeProb` `scoreTake` `takeSummary` | `renderXxx` |

移植时优先搬左列；右列需要自己实现一层适配（把 `S.cfg` 换成入参、把 `saveCfg` 换成回调）。

## 6. 关键算法（伪代码）

### 6.1 档位价与档距

```js
function gearBase(){
  H  = cfg.H_BASE || computeHEff().h          // 手动优先
  T  = cfg.avgTarget
  w  = normW(cfg.wPct)

  // ① 已持仓折算（noCap 时跳过）
  T_eff = T
  if (T && !cfg.noCap && heldG > 0.01 && fx > 0):
      rest = TOTAL − heldG
      T_eff = rest > 0.01 ? (T*TOTAL − avgUsd*heldG) / rest : null   // null = 仓位满

  // ② 名义档距
  switch cfg.spanMode:
    "range":  d0 = (endDrop − startDrop)/100 * H / (n−1)
    "alpha" 或 !T_eff: d0 = α * ATR14
    "target": d0 = (p1 − T_eff) / frontCenter(w, anchorKOf(w))
              // frontCenter = 0 → 公式失效（权重全压第 1 档），退回 α 并提示

  // ③ 终止跌幅硬上限（只压不拉）
  capD = (endDrop − startDrop)/100 * H / (n−1)
  d = (d0 − capD > 0.005) ? capD : d0         // 未越界时字节级不变
  clamped = (d !== d0)
}
```

**三条不变量**

1. `p1` 只由 `H` 与 `startDrop` 决定，与 `T`、权重、α 全无关。
2. `d ≥ 0`。
3. `clamped` 为真时，必须同时提供 `d0`（用户"要"的档距）与 `capD`，UI 才能说清"你要 −27%，被压到 −25%"。

### 6.2 计划与下沉

```js
function planBudget(){
  if (cfg.noCap) return TOTAL
  unmarked = Σ buys.filter(b => !b.gear).gram
  return max(0, TOTAL − unmarked)
}

function planBase(){
  B = planBudget(); s = Σw
  return w.map(wi => s > 0 ? B*wi/s : 0)
}

function planOf(){
  base = planBase()
  return cfg.realloc.on ? reallocPlan(base) : base
}

function reallocPlan(base){
  if (!cfg.realloc.on || !price) return base
  // ① 失效判定（带滞回）
  dead = idx where (wasDead ? px < p*(1−0.003) : px <= p*(1−0.01))
  if (!dead.length) return base

  // ② 按角色分组互挪
  for role of [建仓档, 循环档]:
      pool = Σ max(0, base[i] − bought[i]) * ratio   for i in dead ∩ role
      recv = role.filter(i => !dead.has(i) && base[i]−bought[i] > 0.05)
      if (!pool || !recv.length) continue            // 无接收方 → 整组撤销

      // ③ 落点
      t = recv[0]                                     // 最接近现价
      drop = (p[t]/px − 1) * 100
      if (mode === "near" && drop < −maxDrop):
          distribute pool by base[i]/Σbase            // 太深 → 退化等比
      else if (mode === "near"):
          eff[t] += pool
      else:
          distribute pool by base[i]/Σbase
  return eff
}
```

**可测试断言**：`Σ eff === Σ base`（浮点容差 1e-6）。

### 6.3 卖出摊派

```js
function allotSell(gram, priceOz, cnyTotal){
  nets = [1..n].map(i => max(0, boughtOf(i)))
  sum  = Σ nets;  if (!sum) return null
  q    = min(gram, sum)

  // ① 拆克重（0.1g 单位，尾差补最后一个有量档）
  parts = splitByGram(q, nets)

  // ② 逐档写 sold / proceeds，g 与 cost 不动
  for j, d of parts where d > 0.05:
      m = gearMarks[j+1];  if (!m) continue
      ns = min(m.g, m.sold + d)
      addG = ns − m.sold
      addCny = cnyTotal ? cnyTotal * addG/q
                        : (m.costCny > 0 ? addG * m.costCny/m.g : 0)
      m.sold      += addG
      m.proceeds  += gramToUsd(addG, priceOz)
      m.proceedsCny += addCny
      lot[j+1] = addG

  return { lot, hit }      // 快照，存到这笔卖出记录上
}
```

**编辑路径的顺序（不可反）**：`unallotSell(旧快照, 旧克重)` → 改字段 → `allotSell(新克重)`。

```js
function computeTakes(){
  // ① 候选位
  raw = [回本位, +15/20/25/30%]
        .concat(技术位, 前高, 延伸 127.2/161.8/200, PL90, PL180, 摆动高×3, 52周高, 整数关口)

  // ② 合并（0.35% 内），强度 = min(4, count + (arms≥2 ? 1 : 0))

  // ③ 过滤现价上方（> 现价×0.975，让"刚穿过"的位留下并标已到价）

  // ④ 评分：强度(36) + 空间(24) + 趋势(30) + 类型(±) − 惩罚

  // ⑤ 选位
  cand = 上方位.filter(score ≥ 50 && dist ≥ 1.5 && (stopMode || cny ≥ cost×0.999))
  picked = []
  for it of cand.sort(按分数降序):
      if (picked.any(p => |p−it|/it < 0.012)) continue       // 间距 1.2%
      if (picked.length ≥ 2 && 上一选中 − it ≥ 18 && it.score < 56) break   // 断层
      picked.push(it);  if (picked.length ≥ 8) break
  if (picked.length < 2) 从落选补到 2
  if (无 profit 位) 补 1 个（prob ≥ 10 且 dist ≤ 25）

  // ⑥ 分配
  keepG = computedKeep(grams)                                // 底仓
  avail = grams − keepG − 已到价待核销
  units = allocUnits(avail*10, weights, firstProfitIdx)       // 整数 0.1g
}
```

## 9. 风险与已踩的坑

### 9.1 高频坑（都在真实事故里出现过）

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | 均价分母用了「卖出后余额」 | 卖过一半的账户均价虚高 | 分母恒为 Σ买入克重 |
| 2 | `costCny = 0` 当 0 处理 | "不知道赚多少"显示成"不赚不亏" | 返回 `null`，界面 `¥ —` |
| 3 | 空仓时 `min(0, keepG)` | 输入框显示 20、引擎算 0，永远判脏 | 空仓时只 `max(0, v)`，不夹上限 |
| 4 | 派生显示参与脏值判定 | 买入一笔就冒"未保存" | 加 `setTouch`，只认真实输入 |
| 5 | 回本价 < 均价 | "已盈利"算出负数 | 夹 `comeback ≥ 0` |
| 6 | 计划层写死 TOTAL | 待补凭空多一截 | `planBudget` 扣未标档持仓 |
| 7 | 已标档持仓再扣一次预算 | 已买满的档被标"已买超" | 只扣未标档 |
| 8 | 下沉不加滞回 | 价格抖动时额度来回搬 | 跌破 1% 进、回 0.3% 出 |
| 9 | 六格盈利测算全红 | 看不出现在站在哪 | 只 ±2pp 内那格红 |
| 10 | 摊派先摊新后退旧 | 双重累加 | 先退旧再摊新 |
| 11 | 卖出换账户时把原克重加回 | 可卖出超过新账户持仓 | 换账户时 `back = 0` |
| 12 | 到价待核销整笔照搬 | 提示减 28.3g 而实际只剩 5g | 以剩余持仓封顶 |
| 13 | 关闭"成本下方减仓"只改选位 | 旧计划条目仍变成可点的亏损卖出 | 核销路径也要过滤 |
| 14 | 渲染函数互调 | 栈溢出 | 统一 `refreshAll` |
| 15 | 筛选写进配置 | 点一下筛一次云端 PUT | 筛选只改内存 |
| 16 | 空态分支不绑筛选条 | 筛到空账户后回不到"全部" | 三个空态都先渲染筛选条 |

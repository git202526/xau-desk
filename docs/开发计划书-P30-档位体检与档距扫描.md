### 1.3 `btScan(k, opts)`（新增）

```js
/* 返回 { base:{scale, r}, rows:[{scale, r}] }。
   rows 固定 5 项，base 指向 scale===1 那一项（引用同一对象，不深拷贝）。
   任一组 err 时该行 r 为 {err, n}，其余组照常返回，不整表失败。 */
function btScan(k, opts){
  var o = opts || (S.cfg && S.cfg.btOpts) || {};
  var SC = [0.6, 0.8, 1.0, 1.2, 1.4];
  var rows = SC.map(function(s){
    return { scale:s, r: btBack(k, Object.assign({}, o, { pitchScale:s })) };
  });
  return { rows:rows, base: rows[2] };
}
```

> 不用 `Object.assign` 的话要手写浅拷贝 —— 项目里已在用 ES5 风格，改为手写循环更稳。

## 2 P30 三批

### 批一 · 计算层（无 UI）

在 `computeGears()` 末尾追加，不改任何既有字段：

```js
/* P30：满仓成本与逐档累计均价。用 g.plan（已含下沉后的实际克重），
   不能用 planBase —— 否则和阶梯行显示的克重对不上。
   warn 档（pct 为负向预警、无克重）不参与累计。 */
function gearCostOf(rows){
  var cost = 0, gram = 0, cumAvg = [], cumGram = [];
  for(var i = 0; i < rows.length; i++){
    var g = rows[i];
    if(g.warn) continue;
    var gm = Number(g.plan) || 0;
    var px = Number(g.price) || 0;
    if(!(gm > 0) || !(px > 0)) continue;
    cost += gm * px / OZ_PER_G;
    gram += gm;
    cumGram.push(Math.round(gram * 100) / 100);
    cumAvg.push(gram > 0 ? cost / (gram / OZ_PER_G) : null);
  }
  var fx = Number(S.fx);
  return {
    fullCost: Math.round(cost * 100) / 100,
    fullCostCny: fx > 0 ? Math.round(cost * fx * 100) / 100 : null,
    cumAvg: cumAvg, cumGram: cumGram
  };
}
```

挂到 meta：

```js
var gc = gearCostOf(rows);
S.gearMeta = Object.assign(meta, gc);   // 或逐个赋值，与 P28 风格一致
```

**校验点**（写进测试，不写进代码）：
- `cumAvg[0] === rows[0].price`（第 1 档均价 = 第 1 档价）
- `cumAvg[last] ≈ avgAll`（末项 = 均价卡的「全部买满」）

若两者不等，说明 `avgAll` 与 `g.plan` 的克重口径不一致 —— 这正是这次要抓出来的东西。

### 批二 · 区间

```js
function btRangeRoots(bars){
  var r = (S.cfg.btOpts || {}).range || "all";
  var k = bbPeriod();
  if(k !== "1d" && k !== "1w") return { i0:BTB_WARM, kind:"all", note:"小时线固定全量" };
  var n = bars.length, i0 = BTB_WARM;
  if(r === "90d")  i0 = Math.max(BTB_WARM, n - 90);
  if(r === "180d") i0 = Math.max(BTB_WARM, n - 180);
  if(r === "365d") i0 = Math.max(BTB_WARM, n - 365);
  if(r === "auto") i0 = Math.max(BTB_WARM, firstBuyIdx(bars));
  return { i0:i0, kind:r, roots:n - i0, note: r === "auto" && i0 === BTB_WARM ? "没有买入记录，已改为全部" : "" };
}
```

`firstBuyIdx(bars)`：取 `S.cfg.buys` 里最早 `time`（ISO 字符串），`new Date(time).getTime()` 与 `bars[i].t` 比对，找到第一个 `bars[i].t >= ts` 的下标；解析失败或无记录 → 返回 `BTB_WARM`。

`btBack` 里 `var i0 = BTB_WARM` 改为从 `btRangeRoots(bars)` 取，并把 `{kind, roots, note}` 塞进 `meta.range`。

**高点窗口不变**：`btHeight(bars, i0, o)` 仍用 `bars[0, i0)` —— 区间只决定「从哪根开始交易」，不改变「用哪段算高点」。

## 5 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| `avgAll` 与 `cumAvg` 末项不等 | **高**（说明两个口径的克重来源不同） | 这正是 m3 要抓的。若不等，先查 `avgAll` 用的是 `planBase` 还是 `plan`，统一到 `plan` |
| 曲线改百分比，P19-2 的 `c4` 与图例断言连带失败 | 中 | 批四后立刻跑 `test_p19_2_back.py` 全量，逐条改 |
| 开启循环档后「同克重」不成立 | 中 | 扫描表加提示「已开启循环档，卖出后各组克重不同」；本轮不对齐 |
| `pitchScale=1.4` 时深档价可能跌破 0（高点很低时） | 低 | `gearPrices` 已有下限保护；再加断言「所有档位价 > 0」 |
| `auto` 区间依赖 `buys.time` 格式 | 低 | 解析失败一律退化为 `all`，不抛错 |
| 云端老 `btOpts` 无 `range` / `pitchScale` | 低 | 缺省 `"all"` / `1`，行为与改前一致，不升 `schemaVersion` |

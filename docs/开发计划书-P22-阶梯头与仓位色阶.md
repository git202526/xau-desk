## 零、本期为什么插队，以及为什么先改后写

用户在看盘时连发两张图：

1. 建仓阶梯头部三行里，高点、手动、待补各出现两次，标题还被截成「待补…」
2. 仓位进度卡整条是绿的，而绿在本页是「跌」

两条都属于「看着别扭、不改会一直别扭」的读图问题，不是功能缺口。用户的指令是**先修、再写计划书**。
本期照办，并在此把契约补齐；P20 及之后的功能期次仍按「PRD → 计划书 → 开发」三步走，不拿本期当先例。

## 一、批一：建仓阶梯标题行去重

### 1.1 三行里到底哪几处是重复的

按 390 宽实测（`高点 4696`、`上限 300 克`、`下沉 25.9g`）：

| 行 | 实测原文 | 判定 |
|---|---|---|
| 标题行（`#ladderMeta`） | `高点 4696 · 手动高点 · 待补 300 克` | **三处全删** |
| 档位来源（`#gearSrcBox`） | `高点 4696 · 手动 · 档距 46 美元（α 1.00）` | 留，唯一权威源 |
| 档位执行（`#ammoTxt`） | `0 / 300 克 · 下沉 25.9g` | 留，唯一执行口径 |

逐条对：

- **`高点 4696`**：下一行已有，且下一行还带档距与 α —— 标题行这一份是纯冗余
- **`手动高点` / `手动`**：同一个信息，两行两种写法，读者要在脑子里对齐一次才知道是一回事
- **`待补 300 克`**：`300 − 0 = 300`，与「档位执行 0 / 300 克」是同一个数。`planSummary().pending` 就是它

### 1.2 根因：`sech` 只有一行宽，装不下第三段信息

`renderLadder()` 里 P8 留过一条注释：

> 下沉汇总放弹药进度行 —— sech 标题宽度不够，390 下会被 ellipsis 吃掉

同一个坑这次踩了第二遍。`sech` 是 `flex` 单行：左边 `h2`（`flex:1 1 auto`）+ 右边按钮组（`flex:0 0 auto`）。
390 宽下按钮组吃掉约 130px，标题区只剩 150px 左右，「建仓阶梯」54px 之后只剩不到 100px，
`高点 4696 · 手动高点 · 待补 300 克` 大约 200px —— 必然截断，实测就截在「待补…」，最该看的数字没了。

所以结论不是「换个更短的写法」，而是：**标题行只放状态标签，任何数值都不放**。
数值归它该在的行：高点归「档位来源」，克重归「档位执行」。

### 1.3 改动

`renderLadder()` 中删掉 `tailTxt` 与 `head` 两段拼装，换成异常标签：

```js
/* 改前 */
var m = S.gearMeta || {};
var tailTxt = "";
if(planOnly){
  if(sub.overBudget > 0.05) tailTxt = " · 已超预算 " + gnum(sub.overBudget) + " 克";
  else if(sub.pending < 0.05) tailTxt = " · 计划已执行完毕";
  else tailTxt = " · 待补 " + gnum(sub.pending) + " 克";
} else if(bt > total + 0.05) tailTxt = " · 已超目标 " + num(bt - total, 1) + " 克";
else if(total - bt < 0.1) tailTxt = " · 已建满";
else tailTxt = " · 待建 " + num(total - bt, 1) + " 克";

var head = "";
if(m.he){
  var how = m.highManual ? "手动高点" : ("自动 " + ((m.auto && m.auto.win) || ""));
  head = "高点 " + num(m.he, 0) + " · " + how;
}
$("ladderMeta").innerHTML = escapeHtml(head + tailTxt) +
  (planOnly ? '<span class="planTag">计划模式</span>' : "");

/* 改后 */
var mtxt = "", mcls = "";
if(planOnly){
  if(sub.overBudget > 0.05){ mtxt = "已超预算 " + gnum(sub.overBudget) + "g"; mcls = " warn"; }
} else if(bt > total + 0.05){
  mtxt = "已超目标 " + num(bt - total, 1) + "g"; mcls = " warn";
}
$("ladderMeta").innerHTML =
  (mtxt ? '<span class="mtag' + mcls + '">' + escapeHtml(mtxt) + '</span>' : "") +
  (planOnly ? '<span class="planTag">计划模式</span>' : "");
```

保留的只有两种状态，都是**行三行看不出异常**的：

| 条件 | 标签 | 为什么留 |
|---|---|---|
| `overBudget > 0.05` | `已超预算 10g` | 行三只显示 `210 / 200 克`，要心算才知道超了多少 |
| `bt > total + 0.05`（账本模式） | `已超目标 12g` | 同上 |
| 其余 | 不显示 | 数字行已经说清楚了 |

「计划已执行完毕 / 已建满」也一并删掉 —— `300 / 300 克` 本身就是最直白的"建满"，再加一句是第三次重复。

### 1.4 新增样式

```css
/* P22 标题行的异常标签：只在「超预算 / 超目标」时出现 */
.sech .mtag{display:inline-block;flex:0 0 auto;font-size:10.5px;line-height:1.6;padding:0 6px;
  border-radius:5px;background:rgba(224,145,63,.16);color:#E0913F;font-weight:500;margin-left:6px}
```

`flex:0 0 auto` 是关键：`.sech .cnt`（`#ladderMeta` 的 class）是 `flex:1 1 auto`，标签若允许收缩，
窄屏会被压成 0 宽 —— 和标题被 ellipsis 吃掉是同一类事故。

### 1.5 契约变化（必须写进提交说明）

| 谁 | 旧契约 | 新契约 |
|---|---|---|
| `#ladderMeta` | 含「高点 XXXX」「待补 X 克」 | **不含**高点、手动、待补；正常态只有「计划模式」 |
| `test_p47_marks.py::test_ammo_uses_plan_not_ledger` | 断言 `"待补 190" in ladderMeta` | 断言 `ladderMeta` 不含「待补 / 高点」，且 `planSummary().pending` 仍为 190 |

数没有丢，只是搬到该在的位置 —— 断言跟着搬，判据不放宽（反而多锁了一条"标题行不许出现高点"）。

## 二、批二：两枚重操作改成实体按钮

### 2.1 现状

`.sech .act` 是**全站通用**的无边框纯文字样式（`background:none;border:none;color:gold`）。
用在「记一笔」「+ 记一笔」这种高频轻操作上没问题 —— 旁边就是内容，位置够明显。

但「重算档位 / 按高点」不是轻操作：

- 两个都会**重排整张档位表**，前者按当前持仓重排，后者按 D60 高点重算，各自有 `confirm`
- 它们在标题行最右侧，与「建仓阶梯」之间隔着一整段空白，读起来像两个行内文字标签
- 390 下两枚之间只有 2px 间距，纯文字又都靠得紧，漏点/误点都常见

### 2.2 改动

不动全站 `.act`（会波及 8 处按钮），只给这两枚加 `btn-st`：

```html
<div class="sact">
  <button class="act btn-st solid" id="btnRecalc">重算档位</button>
  <button class="act btn-st" id="btnRebuild">按高点</button>
</div>
```

```css
/* P22 建仓阶梯的两枚重操作：原来是无边框纯文字，看起来像行内标签而不是按钮 */
.sact .btn-st{font-size:11.5px;font-weight:600;line-height:1;padding:0 11px;min-height:36px;
  border-radius:8px;border:1px solid rgba(212,162,76,.42);background:rgba(212,162,76,.12);
  color:var(--gold);white-space:nowrap;-webkit-tap-highlight-color:transparent}
.sact .btn-st.solid{background:rgba(212,162,76,.9);border-color:rgba(212,162,76,.9);color:#1B1409}
.sact .btn-st:active{transform:scale(.97)}
```

三条具体选择：

- **主次靠"实心 / 描边"分，不靠字号**：`重算档位` 实心（金底深字），`按高点` 描边。两枚字号一样，避免读者以为小的那个不重要
- **`min-height:36px`**：原 `.sech .act` 是 40px，这里是标题行内嵌按钮，36 是"能点准"与"不把标题行撑高"的折中。宽度实测 70 / 58px，都超过 44px 触控宽度下限
- **`color:#1B1409` 而不是 `#000`**：金底上用纯黑对比过硬，用深棕更贴暗色主题

### 2.3 320 宽实测

标题 54 + 标签 46 + 按钮组 130 + 两处 gap ≈ 240px，可用 292px，单行放得下、标题不被压。
`test_h6` 锁住：`sact` 不溢出、`h2` 不截断、两按钮同一行、单个宽度 ≥ 54px。

## 三、批三：仓位色阶去绿

### 3.1 为什么绿色必须拿掉

`--dn:#2FA36B` 在本项目里只有一个语义：**跌**（`--up:#E5484D` 是涨）。
仓位进度卡拿同一个绿表示「仓位还低 = 安全」，同一屏里两个绿意思相反 —— 用户第一眼就读反。

### 3.2 新色阶：冷 → 暖单向走，五阶等分

| 阶 | 覆盖 | 段 | 色值 | 语义 |
|---|---|---|---|---|
| 1 | 0–20% | 1–4 | `#446A8C` 深钢蓝 | 刚建仓，冷静 |
| 2 | 20–40% | 5–8 | `#6B9FC6` 亮蓝 | 建仓中 |
| 3 | 40–60% | 9–12 | `#C9A24F` 金 | 过半，进入主仓 |
| 4 | 60–80% | 13–16 | `#E08A45` 橙 | 偏重 |
| 5 | 80–100% | 17–20 | `#D8514B` 红 | 满仓 |

选这套的理由：

- **色相单向**：蓝 → 金 → 橙 → 红，只往暖走，不回冷；明度与饱和度同向递增，所以"越往后越紧张"不需要看数字也能感到
- **金色接得住**：第 3 阶用主色 `--gold` 一系的 `#C9A24F`，蓝到红之间不会跳成"紫 / 青"这种主题外的色
- **红只留给满仓**：和顶部报价的涨红不冲突 —— 一个是价格、一个是仓位，两处红都在"极端"位置，不抢戏

### 3.3 百分比文字：跟着条走，不是另一套阈值

改前是四条独立阈值（`ok / warm / hot / over`），条按位置分色、字按百分比分色，两套各算各的，
53.3% 会出现"条走到金色、字还是绿的"这种错位。改后统一成一个来源：

```js
/* 段 i 落在第 floor(i/4) 阶，所以最后一格亮到哪、字就是哪一阶的颜色 */
var cls;
if(pct > 100) cls = "over";
else if(!(pct > 0)) cls = "";
else cls = "p" + Math.min(4, Math.floor((Math.max(on, 1) - 1) / 4));
```

| 仓位 | 点亮段 | 最后一格所在阶 | class | 字色 |
|---|---|---|---|---|
| 0% | 0 | — | （无） | `var(--tx)` 中性白 |
| 20% | 4 | 1 | `p0` | `#7FA3C0` |
| 50% | 10 | 3 | `p2` | `#DDB469` |
| 75% | 15 | 4 | `p3` | `#EE9A55` |
| 90% | 18 | 5 | `p4` | `#E5645E` |
| 125% | 20（满） | — | `over` | `#F2685F` |

0% 特意不给色：空仓是"还没开始"，不是一种状态，给个蓝字反而让人找含义。

### 3.4 不改的部分

- 20 段段数与 `on = round(pct/100*20)` 的算法不变（`test_p16b` 的 b2 / b3 / b5 全依赖它）
- 未点亮段仍是 `opacity:.14`，压暗后五阶看起来一致，不会出现"低阶暗段比高阶暗段亮"
- `over` 这个 class 名保留（`test_b4` 断言它），语义从"红"扩成"超限"，颜色更深一档

## 六、交付前自查（铁律 9 + 10）

1. **调用链无环**：本期只改 `renderLadder`（内联计算）与 `renderGauge`（纯计算），未新增函数调用关系
2. **DOM 存在性**：`#ladderMeta` / `#posGauge` 都在静态 HTML 里，`mtag` 是纯 innerHTML
3. **空数据不崩**：`pct = 0` 时 `cls` 为空串，不发 `p-1`；无 `gearMeta` 时 `mtxt` 空，标题只余「计划模式」
4. **除零**：`lim = 0` 时 `pct = 0`，走 g5 分支
5. **`sanitizeHtml` 白名单**：`span` 放行，class 保留，无 inline style
6. **模块数**：本期 3 项均为单点修改，不涉及新模块
7. **不改数据**：`cfg` 未加任何字段，P17 的脏值比对不受影响

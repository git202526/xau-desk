## 0. 一句话改动

`btBack()` 从「给一笔钱，看能买多少」改成「买固定克重，看花多少钱」。
`cash` 从「剩余预算」变成「净现金流」，初始值 `budget` → `0`。

---

## 1. 契约变化表

### 1.1 `btBack(k, opts)` 返回结构

| 字段 | 现状 | 改后 | 说明 |
|---|---|---|---|
| `meta.budget` | 预算上限，约束买入 | `fullCost` 语义：十档买满的理论成本 | 仅显示，不约束 |
| `meta.range` | — | `{kind, roots, note}` | 新增 |
| `stats.cash` | 剩余现金 | **删除** | 改名 `flow`，内部用 |
| `stats.usage` | `invest / budget` | **删除** | 失去意义 |
| `stats.skipped` | 预算不足次数 | **删除** | 不再有预算不足 |
| `stats.invest` | 实际投入 | 不变 | = 实际花费 |
| `stats.avgCost` | `invest / heldGram`（$/g） | 保留 | 卡片新增展示 |
| `stats.pnl` | `endV − budget` | `endV`（净值即盈亏） | cash 初值 0 后二者等价 |
| `peers.dca.invest` | 投入 | 改名 `cost` | |
| `peers.dca.gram` | — | 新增 | = 基准克重 |
| `peers.dca.avgOz` | — | 新增 | `$/oz` |
| `peers.lump.*` | 同上 | 同上 | |
| `flags.realloc` | 有效下沉 | 不变 | |

### 1.2 内部变量

```js
// 改前
var budget = totalGrams() * btPxG(bars[i0].c);
var cash = budget, hold = 0, realized = 0, invest = 0, skipped = 0;
if(cash >= out - 1e-6){ cash -= out; ... } else { skipped++; }

// 改后
var fullCost = totalGrams() * btPxG(bars[i0].c);   // 只做展示
var flow = 0, hold = 0, realized = 0, invest = 0;  // flow = 卖出回款 − 买入成本
// 直接买，无判定
flow -= out; hold += gram; invest += out;
```

> `flow` 名字必须改：它已经不是「现金」，是「净现金流」。留着 `cash` 会让下一个人以为还有余额。

## 2. 分批任务

### 批一 · 计算层（无 UI）

1. `btBack()` 去掉预算判定，`cash` → `flow`，初值 0
2. `meta.budget` 保留字段名但改注释为「满仓理论成本」；新增 `meta.fullCost`（同值，供新代码读）
3. 三组改同克重：
   ```js
   var baseGram = heldGram;                 // 本策略买入克重（含已卖出档）
   var days = n - i0;
   var perGram = days > 0 ? baseGram / days : 0;
   var dcaHold = 0, dcaCost = 0;
   for(i = i0; i < n; i++){
     var c1 = Number(bars[i].c) || 0;
     if(!(c1 > 0)) continue;
     dcaHold += perGram; dcaCost += perGram * btPxG(c1);
   }
   var lumpCost = baseGram * btPxG(bars[i0].c);
   ```
4. `peers` 补 `gram / cost / avgOz`
5. 删 `stats.cash / usage / skipped`，`pnl` 改 `= endV`
6. 边际：`baseGram === 0` 时三组 cost 与 avgOz 全为 `null`，不做除法

### 批二 · 区间

1. `S.cfg.btOpts.range = "90d" | "180d" | "365d" | "all" | "auto"`，缺省 `"all"`
2. 新增 `btRangeRoots(bars)`：
   ```js
   function btRangeRoots(bars){
     var r = (S.cfg.btOpts || {}).range || "all";
     var k = bbPeriod();                       // 1w / 1d / 4h / 1h
     if(k !== "1d" && k !== "1w") return { i0:BTB_WARM, kind:"all", note:"小时线固定全量" };
     var n = bars.length, i0 = BTB_WARM;
     if(r === "90d")  i0 = Math.max(BTB_WARM, n - 90);
     if(r === "180d") i0 = Math.max(BTB_WARM, n - 180);
     if(r === "365d") i0 = Math.max(BTB_WARM, n - 365);
     if(r === "auto") i0 = Math.max(BTB_WARM, firstBuyIdx(bars));
     return { i0:i0, kind:r, roots:n - i0 };
   }
   ```
3. `firstBuyIdx(bars)`：取 `S.cfg.buys` 最早 `time`，映射到 `bars` 的索引；
   无记录或早于首根 → 返回 `BTB_WARM`，`note:"没有买入记录，已改为全部"`
4. 控件：`bbParamHtml` 里新增一行 chips `[90天][180天][365天][全部][自动]`，
   4h/1h 时整行隐藏
5. 高点窗口不变：`btHeight(bars, i0, o)` 仍用 `bars[0, i0)`，因为区间只决定「从哪根开始交易」

### 批三 · 对照表 / 曲线 / 文案

1. 对照表列改为 `方案 / 克重 / 建仓成本 / 盎司均价 / 收益率`，`#bbPeers` 的 `.pr` 仍是 3 行
2. 表尾一行 `期末 300 g 值 $38,121（三组相同）`
3. **曲线改收益率口径**：
   ```js
   // 改前：eq 存 {t, v:绝对值}
   // 改后：eq 存 {t, v:(净值 / invest − 1) * 100}
   ```
   理由：同克重下三组期末价值必然相同，绝对值曲线会在右端重合，看不出差异。
   图例从 `本策略 $27,631` 改为 `本策略 +5.36%`
4. 预算行改成本行：`满仓成本 $36,182 · 实际花费 $36,182 · 档位高点 H $4,696 · 区间 740 天`
5. 说明三段重写（PRD §5.4），第 3 段明写「无预算上限 · 按档位价成交」
6. 新增偏差提示：`区间内金价 $2,764 → $3,952（+43.0%）`，放在曲线下方小字

### 计算层（g1–g8）

| # | 用例 |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 曲线改百分比，P19-2 的 `c4`、图例断言可能连带失败 | 中 | 批三后立刻跑 `test_p19_2_back.py` 全量，按失败逐条改 |
| 开启循环档时，期末持仓 < 买入克重，"同克重"名不副实 | 中 | 对照表加提示「已开启循环档，卖出后三组不再同克重」；本轮不强行对齐 |
| `auto` 区间依赖 `buys` 的 `time` 格式 | 低 | 解析失败一律退化为 `all`，不抛错 |
| 云端老 `btOpts` 无 `range` | 低 | 缺省 `"all"`，与改前行为一致，无需迁移版本 |
| 「设置高点」下档位整体高于市价，本策略必然贵于一次性 | **已知** | 不是 bug，卡上显示区间涨跌幅 + 说明段提示；区间缩短后偏差减小 |

# P15 · 计划模式记账 + 账本模式下沉（缺陷收口）

> 版本 v6.28 · 依据 v6.27 实际代码与 390×844 实测
> 起因：两处「功能被一句条件挡住」的缺陷，都是用户能直接感知的不一致。

---

## 1. 缺陷一：计划模式不能记录持仓、不能记一笔

### 1.1 症状

| 位置 | 现象 |
|---|---|
| 持仓页「记一笔」 | 弹一句「计划模式不记账，先关闭计划模式」，什么都不发生 |
| 持仓汇总 | 永远显示「还没有买入记录」 |
| 买入记录 | 永远空列表 |
| 建仓页说明 | 又写着「买了要到「持仓」页记一笔，弹药进度才会累加」 |

### 1.2 根因

`openSheet()` 开头一段硬拦截：

```js
if(S.cfg && S.cfg.planOnly){
  if(gearName) openMarkSheet(gearName);
  else toast("计划模式不记账，先关闭计划模式");
  return;
}
```

计划模式只留了「标记已买」这条路：`gearMarks{i:{g,cost,sold,proceeds,at}}`。
标记只回答「这一档买了多少克」，不写 `buys[]`，所以持仓汇总（读 `buys/sells`）
和买入记录永远拿不到数据。而建仓页那句说明是按账本模式写的，两种模式共用一份文案，
就出现了「让你去记，去了不让记」。

### 1.3 方案：记账为准，标记为辅，一次对账

1. **放开记账**：`openSheet()` 去掉拦截。计划模式下「记一笔」照常开表单。
2. **表单加「关联档位」下拉**（`#gearLinkFld` / `#gGear`，只在计划模式显示）：
   选项是各档 + 「不关联（只记持仓）」，每项带当前待补克重。
3. **保存后对账** `syncMarksFromBuys()`：

| 档位情况 | 处理 |
|---|---|
| 有记账（`buys[].gear` 指向该档） | `g` / `cost` 完全由记录重算 → 改一笔、删一笔、改克重都会跟着变 |
| 没记账 | 手工标记原样保留，一个字段都不碰 |
| 标记来自记录、记录全删了 | 按 `fromBuys` 标记把残留清掉 |
| `sold` / `proceeds` | 不动 —— 账本里的减仓没有档位归属，卖出仍走标记面板 |

「记账优先」是唯一规则：同一档既有手工标记又有记账时，以记账为准。
标记面板的脚注写明「同一档别两边都填」，避免两条轨同时喂一个格子。

4. **面板互通**：标记面板加一枚「改成记一笔（留成交明细）」，
   已经把克重点好、档位选好的那次操作可以直接转成记账，不用重打。

### 1.4 数据兼容

- `gearMarks` 多一个可选字段 `fromBuys`（这档的克重来自几笔记录）。
  `cleanGearMarks()` 会保留它 —— 否则云端同步一轮就被洗掉，删记录时认不出来源，
  档位上会留一份撤不掉的「幽灵持仓」。
- 老数据没有 `fromBuys`：行为与以前完全一致（纯标记）。
- 切进计划模式时（设置页保存或 `setPlanOnly(true)`）跑一次对账：
  账本模式下记过、且带档位的老记录会自动折成档位状态，不用重新标一遍。
- `buys[].gear` 早就有（账本模式记账时会写），新增的下拉只是把它显式化。

### 1.5 不改的部分

- 标记面板「确认买入」**仍然不写账本**（P4 的契约，`test_mark_does_not_write_ledger` 守着）。
- 计划模式下点档位行仍进标记面板（既有习惯，一行两下就标完）。
- 账本模式完全不碰 `gearMarks`。

## 2. 缺陷二：账本模式不能配额下沉

### 2.1 症状

账本模式（非计划模式）下，价格跌破的档位不会把待补额度让给现价附近的档；
设置页那句说明直接写「账本模式下不生效」。

### 2.2 根因

`planOf()` 多了一个条件：

```js
if(!r || !r.on || !(S.cfg && S.cfg.planOnly)) return base;
```

注释给的理由是「账本记的是已发生的事实，没有『计划待补』可挪」。
但 `planBase()` 本来就是「按权重应该买多少」，账本模式下同样存在待补
（`pending = plan − 已买`），买不到的理由也一样：价格已经跌穿这一档。

### 2.3 方案

去掉 `planOnly` 条件，其余一行不动：

| 位置 | 改动 |
|---|---|
| `planOf()` | 两种模式都走 `reallocPlan()` |
| `renderLadder()` | 行内「下沉入/出」标签不限模式 |
| 弹药进度行 | `· 下沉 Xg` 不限模式 |
| `renderReallocSet()` | 删掉「账本模式下不生效」分支 |
| 设置页摘要 / 速览 chip | 显示「下沉 开/关」，不再显示「—」 |

`reallocPlan()` 内部本来就通过 `boughtOf()` 取数，天然支持两种数据源：
计划模式读 `gearMarks`，账本模式读 `buys[]` 汇总（还会遵守 `gearCleared` 清除线）。

### 2.4 三条老断言的反转

需求变了，对应的断言方向也跟着反转 —— 这是**契约变更**，不是为了让失败变绿：

| 原测试 | 新测试 | 新契约 |
|---|---|---|
| `test_r18_ledger_mode_ignores` | `test_r18_ledger_mode_reallocs` | 真的重分配 + 总量守恒 + 跌破档归零 |
| `test_v14_ledger_mode_hides_everything` | `test_v14_ledger_mode_shows_too` | 两枚标签都在 + 设置页给明细 |
| `test_n6_ledger_realloc_dash` | `test_n6_ledger_realloc_on` | chip 显示「下沉开」 |

改写后的断言比原来更严：原来只断言「等于原始计划」，现在要求
「不等于原始计划」「总量守恒」「跌破档为 0」三条同时成立。

## 3. 缺陷三：「重置档位状态」漏清 gearMarks

### 3.1 症状

弹窗写「清空全部买卖记录与档位状态？」，点完回到建仓页，档位还标着「已买入」。
实测重置前后 `gearMarks` 键数 1 → 1。

### 3.2 根因

```js
S.cfg.gearsDone = []; S.cfg.gearHit = {}; S.cfg.gearCleared = {};
S.cfg.feed = []; S.cfg.buys = []; S.cfg.sells = [];
S.cfg.swingGears = DEFAULT_SWING.slice();
S.cfg.dripAt = {};
/* gearMarks 漏了 */
```

P6 引入 `gearMarks` 时没回头改重置按钮，这条从那时挂到现在。
本期新增 `fromBuys` 后它更要命：残留的标记会被当成「从记录对账来的」，删无可删。

### 3.3 方案

一行：`S.cfg.gearMarks = {};`。

## 5. 实施记录

- `openSheet()` 去掉拦截；`openBuyEdit()` 补 `setSheetMode("buy")`
  （原来从「编辑减仓」切到「编辑买入」时，按钮文案还留在「保存这笔减仓」）。
- 新增 `cnyToUsd()`（元/克 → $/oz），与既有 `gramToUsd()` 配对。
- 新增 `syncMarksFromBuys()`，在 `saveBuy` / `delBuy` / 切入计划模式三处调用。
- 新增 `fillGearLink()`，`openSheet` / `openBuyEdit` / `openSell` 三处调用。
- 档位行点击：计划模式仍进标记面板（`planOnly` 分支），账本模式进记账表单。
- 重置按钮补 `S.cfg.gearMarks = {}`。

## 6. 遗留

- 计划模式的「记一笔减仓」目前只写 `sells[]`，不回写 `gearMarks.sold`：
  账本里的减仓没有档位归属，混着算会重复扣。要做得先给 `sells` 加 `gear` 字段。
- 循环档、深档兜底仍只在计划模式生效（本期未动）。

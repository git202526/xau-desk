## 一、问题

结构页现在只回答「此刻是上行、震荡还是下行」。用户没法回答：

| 问题 | 现状 |
|---|---|
| 过去一个月，判定改过几次口？ | 无入口，只能每天自己记 |
| 每次切换是哪天？切之前是什么状态？ | 无入口 |
| 这套判定是不是老在上行 / 震荡之间来回跳？ | 无入口，而这直接决定要不要信它 |

一句话：**页面给的是快照，用户要的是轨迹。**

---

## 二、目标与非目标

### 2.1 目标（P19-1）

把历史每一天的判定重跑一遍，给三样东西：

1. **方向色带** —— 一条横向时间轴，每天一格，颜色表示当天判定
2. **分布统计** —— 上行 / 震荡 / 下行 各占多少天
3. **切换记录** —— 哪一天从什么变成了什么

### 2.2 非目标

| 不做 | 原因 |
|---|---|
| 「判定准确率」 | 见 §2.3 |
| 收益预测、策略回测 | 那是 P19-2 |
| 自定义区间选择 | 先给「尽可能长」，用户想截区间是下一层需求 |
| 多周期叠加对比 | 一次看一个周期，避免一张图四种颜色 |
| 逐日完整指标明细 | 本期只给「命中几条」，见 §4.4 |

### 2.3 为什么不做「准确率」

「准确率」听起来最有用，但它需要一个「正确」的定义，而这个定义怎么取都站不住：

- 判定上行后 5 根涨了算对？那 6 根才涨算不算？10 根呢？
- 判定震荡，后来涨了 —— 算错还是算「区间内正常突破」？
- 同一个判定，取 5 根和取 20 根，准确率能差 20 个百分点。

定义不同结论完全不同，给一个数反而误导。

**方向改成**：只陈述判定序列本身（什么时候说什么），把「准不准」交给 P19-2 用收益口径回答——「按这套判定做，赚不赚钱」比「方向猜对几成」实在。

## 三、硬约束：能回溯多久，取决于数据根数

判定要用到 200 根均线，前 210 根只能用来「预热」，出不了结论。所以每个周期能回溯的长度不一样：

| 周期 | 现有数据 | 预热占用 | 可回溯 | 大致折算 |
|---|---|---|---|---|
| 周线 | 220 根 | 210 | **10 根** | 约 10 周 |
| 日线 | 800 根 | 210 | **590 根** | 约 590 天 |
| 4 小时 | 750 根 | 210 | **540 根** | 约 90 天 |
| 1 小时 | 1000 根 | 210 | **790 根** | 约 33 天 |
| 四周期共振 | — | — | 受 1 小时卡住 | **约 33 天** |

**这条必须显示在页面上，不能装作能看全部历史。**

用户看到「日线能看 590 天、共振只能看 33 天」会有点意外，但比「以为能看两年、结果只有一个月」好。

## 四、界面设计

### 4.1 位置

结构页，「多周期共振」卡之后、「通道」之前。

```
多周期共振（现在）
  ↓
判定依据（现在）
  ↓
判定回溯   ← 新增
  ↓
通道
  ↓
关键位
```

理由：先看「现在怎么说」，再看「过去怎么说」，然后才是图形和关键位。顺下来是一条时间逻辑。

### 4.2 周期切换

四个 chip：**周线 / 日线 / 4 小时 / 1 小时**，默认日线（回溯最长）。

切换后立即重算并重绘，不整页刷新。

### 4.3 主体结构

```
┌─ 判定回溯 ────────────────────────────┐
│  [周线] [日线] [4小时] [1小时]         │
│                                       │
│  可回溯 2025-03-20 ~ 2026-10-31       │
│  共 590 天（前 210 根用于指标预热）    │
│                                       │
│  ▓▓▓▓▓▓▒▒▒▒▒▓▓▓▓▒▒▒▒▒▒▓▓▓▓▓▓▓▒▒▒▒   │  ← 方向色带
│  └─ 左右拖动可看更早 ─┘                │
│                                       │
│  上行 312 天 · 53%                     │
│  震荡 198 天 · 34%                     │
│  下行  80 天 · 14%                     │
│                                       │
│  方向切换 23 次（最近 5 次）           │
│  10-28  震荡 → 上行                    │
│  10-12  上行 → 震荡                    │
│  09-30  震荡 → 下行                    │
│  …                                    │
└───────────────────────────────────────┘
```

### 4.4 方向色带

- 横向铺满卡片宽度，**每个数据点一格**（日线 590 格）
- 屏幕放不下时横向滚动，默认滚到最右（最近）
- 颜色（国内习惯，与整站一致）：

| 判定 | 颜色 | 语义 |
|---|---|---|
| 上行 | 红 | 涨的方向 |
| 震荡 | 灰 | 无方向 |
| 下行 | 绿 | 跌的方向 |

> 这里的红色只表示「当时判定为上行」，不表示赚钱。卡片内不出现金额，不会混淆。

- **轻量交互**：点某一格，色带下方出一行：
  `2026-05-12 · 下行 · 命中 4 / 5 条（收盘跌破 MA20、MA20 拐头向下…）`
  只给三态 + 命中条数 + 命中的条件名，不给完整指标值。想看完整依据回上面的「日线判定依据」卡（那是当日）。

### 4.5 分布统计

三行，每行：状态 + 天数 + 占比。占比按可回溯的总天数算，三者合计 100%（尾差归到天数最多的一档，避免出现 99.9%）。

### 4.6 切换记录

- 只列「状态发生变化」的日期，同一天多次变化算一次（一天只有一个收盘判定，本身不会多次）
- 默认显示最近 5 次，点「展开」看全部
- 每条：`日期 · 原状态 → 新状态`
- 一条都没有时显示「区间内方向未发生切换」

### 4.7 共振提示

切到「周线 / 日线 / 4 小时 / 1 小时」时，卡片底部固定一行：

> 四周期共振的回溯受 1 小时数据限制，最多看 33 天。想看更长的方向轨迹，请用日线。

这行**只在周期为日线 / 4 小时 / 1 小时时出现**；选周线时改写为「周线数据只有 220 根，可回溯约 10 周」。

## 五、口径

### 5.1 什么叫「某一天的判定」

用截至那一天的收盘数据，跑与当天页面上完全相同的判定规则（五条做多条件命中 ≥ 3 判上行，五条做空条件命中 ≥ 3 判下行，其余震荡）。

**不能用「今天的数据回头看」** —— 那样等于用未来信息，序列会失真。必须每天只看到当天及以前的数据。

### 5.2 用哪个价格

用**未复权、未换算**的原始报价序列（与结构页当前判定同源）。

页面上若有「按汇率折算克价」之类开关，回溯**不受其影响**，避免同一天因开关不同得出两种结论。

### 5.3 预热段怎么处理

前 210 个点不出结论，色带从第 211 个点开始画，日期标注也从这个点起。预热段不画灰条、不留空白，直接不显示——避免用户以为「那段时间判定是震荡」。

### 5.4 数据不足

不足 211 个点时（首次打开、数据源返回异常、缓存被清），整卡显示：

> 数据不足，暂时无法回溯。需要至少 211 根历史数据，当前只有 {n} 根。

不给半张图。

## 六、P19-2 策略回测（需求存档，本期不做）

写在这里是为了把「回测」的边界一次说清，避免下一期又从头讨论。

### 6.1 它回答什么

「按我现在这套档位参数，如果在过去一年一直这么买，大概是什么体验？」

不是「能赚多少」，是「体感如何」——触发频次、资金占用、最深浮亏。

### 6.2 粗略做法

从区间起点开始逐日推进：

- 当日最低价触及某档档位价，就按该档计划克重记一笔买入（成交价取档位价）
- 记录累计投入、持仓克重、当日市值（用收盘价）
- 区间结束算：触发次数、总投入、平均成本、期末浮盈（%、$）、最大回撤

### 6.3 三个对照

同一区间、同一本金口径下，给三个结果：

| 对象 | 含义 |
|---|---|
| 本策略 | 按当前档位参数逐档买入 |
| 等额定投 | 把同样的钱平均分成同样份数，按同样节奏买 |
| 期初一次性 | 第一天全买 |

三个数放一起才有意义：「跑赢定投」是这套档位唯一值得存在的理由。

### 6.4 必须写在页面上的五个简化

不写清楚就等于假装精确：

1. 只看每日最低价是否触及，不看盘中路径（先跌后涨和先涨后跌结果一样）
2. 不扣手续费、点差、滑点
3. 不模拟循环档卖出（只算建仓档；循环档的买卖规则另立）
4. 成交价取档位价，不取当日最低（偏保守，不会高估收益）
5. 不参与配额下沉（P8 的失效重分配不进回测，否则状态机复杂度失控）

> 这五条不是免责声明，是这套回测的**能力边界**：它只能说「这套档位在历史波动里大概什么体感」，不能说「明年能赚 X%」。

### 6.5 排期

P19-1 上线后看体感再定。如果 P19-1 已经能回答「方向判定稳不稳」，P19-2 的优先级可以往后放。

## 七、空态与异常

| 情形 | 表现 |
|---|---|
| 数据不足 211 根 | 整卡提示缺多少根，不出色带 |
| 回溯区间内从未切换方向 | 色带单色，切换记录区「区间内方向未发生切换」 |
| 单格点击后无依据（不该发生） | 只显示日期与三态，不显示空括号 |
| 切换周期时数据未就绪 | 显示「加载中」，不用上一次的图顶上 |
| 极窄屏（320） | 色带仍横向滚动，统计与记录改单列，不出现横向撑破 |

## 八、验收标准

- [ ] 结构页能看到「判定回溯」卡，位置在「多周期共振」之后、「通道」之前
- [ ] 默认日线，显示可回溯起止日期，天数约 590（±1 天，取决于数据更新时间）
- [ ] 色带颜色符合：上行红、震荡灰、下行绿
- [ ] 色带相邻颜色变化的位置，与切换记录里的日期一一对应
- [ ] 分布统计三项合计 100%
- [ ] 点某一格，显示该日三态 + 命中条数 + 命中条件名
- [ ] 切到 1 小时 / 4 小时 / 日线，底部出现「共振回溯最多 33 天」提示；切到周线，提示改为「约 10 周」
- [ ] 同一天的数据跑两次，序列逐值相同（可复现）
- [ ] 数据不足时给明确提示，不崩、不出半张图
- [ ] 320px 宽不横向撑破页面

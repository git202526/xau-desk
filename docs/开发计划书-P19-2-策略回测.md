## 一、计算层设计

### 1.1 主函数

```
btBack(k, opts) -> {
  meta:  { from, to, n, budget, he, unit },
  gear:  [{ name, price, plan, hits, lastHit }],
  stats: { trigGears, trigCount, invest, holdGram, avgCost, endMV, pnl, pnlPct,
           maxDD, goldDD, usage, skipped },
  equip: [{ t, v }],                 // 本策略权益
  dcaEq: [{ t, v }],                 // 定投权益
  peers: { dca:{…}, lump:{…} },
  flags: { loop, realloc, fee }
}
```

`opts = { loop:false, realloc:false, fee:0 }`，三个开关的默认值来自 `S.cfg.btOpts`。

### 1.2 初始化

```
bars = S.kl[k]                       // 原始报价，不缩放（与 P19-1 同一原则）
若 bars.length < 60 + 10 → 返回 { err:"no-data" }

起点下标 i0 = 60                      // 前 60 根只用来算 H
he = max(bars[0..59].c)              // 与 computeHEff 同口径：60 日收盘最高
降级：若 bars[i0].c < he*0.82 → he = max(bars[i0-20..i0-1].c, bars[i0].c)

gearPrices → 各档价（全程固定）
plan        → 各档计划克重（全程固定）
budget = totalGrams() * bars[i0].c   // 美元
cash = budget, hold = 0
trig = 各档 { done:false, gram:0, cost:0 }
```

**为什么用 `bars[0..59].c` 而不是 `computeHEff()`**：`computeHEff` 取的是「最近 60 根」，回测要取「起点前 60 根」。两者口径相同、窗口不同。

### 1.3 逐日推进

```
for i = i0 … n-1:
  bar = bars[i]

  // ① 下沉（可选）
  if(opts.realloc){
     eff = reallocForBacktest(plan, trig, bar.c)     // 见 1.4
  } else {
     eff = plan
  }

  // ② 建仓触发
  for k = 1…gears:
     若 trig[k].done → 跳过
     若 档位价[k] <= 0 → 跳过（无效档，不计入分母）
     若 bar.l <= 档位价[k]:
         amt = eff[k] * 档位价[k]
         if(cash >= amt){
            hold += eff[k]; cash -= amt
            trig[k] = { done:true, gram:eff[k], cost:amt, t:bar.t }
            trigCount++
         } else {
            skipped++                       // 预算不足计数
         }

  // ③ 循环档卖出（可选）
  if(opts.loop && k > 1):
     for 每个循环档 j:
        若 trig[j].done 且 !trig[j].sold 且 bar.h >= 档位价[j-1]:
           收 = trig[j].gram * 档位价[j-1]
           cash += 收; hold -= trig[j].gram
           realized += 收 - trig[j].cost
           trig[j].sold = true              // 一轮只卖一次（可扩展多轮）

  // ④ 记权益
  total = cash + hold * bar.c
  equip.push({ t: bar.t, v: total })
```

**循环档「一轮只卖一次」**：PRD 写的是「卖出该档全部持仓」，卖完触发状态保留（不重置），避免同一天反复买卖。若以后要多轮，把 `sold` 置回 false 即可。

### 1.4 下沉在回测里的复用方式

**问题**：现有 `reallocPlan(base)` 内部调 `boughtOf(i)` 读真实标记。回测没有标记，直接调会把每一档都当成「没买过」，全额可捐。

**改法**：给 `reallocPlan` 加一个可选的第二参数，注入「已买量」的取数函数：

```js
function reallocPlan(base, ctx){
  var buyOf = (ctx && ctx.buyOf) || function(i){ return boughtOf(i, base); };
  // 内部三处 boughtOf(i+1, base) → buyOf(i+1)
  // 状态容器：ctx && ctx.dead ? ctx.dead : S.reallocDead
}
```

回测调用：

```js
var dead = {};
function reallocForBacktest(plan, trig, px){
  return reallocPlan(plan, {
    buyOf: function(i){ return trig[i].done ? trig[i].gram : 0; },
    dead: dead,
    price: px
  });
}
```

**同时**：`reallocPlan` 内部现在读 `S.price`，也要支持 `ctx.price` 覆盖。

**这是本期唯一改动存量函数的点**，改动很小（三处替换 + 一处价格来源），但不改默认行为，现有调用点不传 `ctx` 时完全等价。用一条回归测试锁住。

### 1.5 指标计算

| 指标 | 公式 |
|---|---|
| `trigGears` / 分母 | `trig` 里 `done` 的个数 / `档位价 > 0` 的档数 |
| `trigCount` | 买入笔数（含循环档重复，本期一轮只卖一次，故等于 `trigGears`） |
| `invest` | `Σ trig[k].cost` + `Σ(卖出后又买回的成本，本期无)` |
| `holdGram` | `hold` 终值 |
| `avgCost` | `invest ÷ Σ trig[k].gram`（**注意分母是净买入，不是 hold**，卖出不改成本口径与现有系统一致） |
| `endMV` | `hold × bars[n-1].c` |
| `pnl` | `endMV + 已回笼 − invest` |
| `maxDD` | `max((peak − v) / peak)` over `equip` |
| `goldDD` | 同区间「收盘价序列」的最大回撤，作参照 |
| `usage` | `invest ÷ budget` |
| `skipped` | 因预算不足未买入的次数 |

### 1.6 对照组

```
定投：
  per = budget / (n - i0)
  每天买 per / bar.c 克（余额清零后停止）
  末值 = 累计克重 × 最后收盘价

一次性：
  第一天 buy = budget / bars[i0].c
  末值 = buy × 最后收盘价
```

两者的 `maxDD` 用各自的权益曲线算，口径与主策略一致（现金 + 持仓市值）。

### 1.7 档位触及统计（D2）

在逐日循环里顺带记：

```
触及：bar.l <= 档位价[k]  →  hits[k]++，lastHit[k] = bar.t
（无论是否已 done、是否买入）
```

**买满的档照样计数** —— 这正是 PRD 第 4 点的锁定项。

> **不另写扫描函数**：单档触价扫描 `touchScan(px)` / `touchScanIn(bars, px)` 已由 P18 批一实现并导出（`__xt.touchScan`），返回 `{hit, lastT, low, from, to, n}`，判定口径与本表完全一致（`bar.l <= px`，按根计数，记最后一次时间）。
>
> 本表的「触及次数」需要在逐日模拟循环里累积（跟买入判定同一次遍历），所以主循环仍然自己记 `hits[k]`；但**模拟区间之外的静态触及查询**（切换区间、只看不做回测时）一律调 `touchScanIn`，避免出现两套「触及」定义。P18 的 b9 锁的是「必须用 `scaled("1d")`」，本期若用原始报价扫描，两边会差一个 `S.scale`，测试 c5 要加一条「与 `touchScan` 同数」的交叉断言。

### 2.1 卡片结构

放在 `#btCard`（判定回溯）之后、`#chChips`（通道）之前，id 用 `#btBackCard`。

```
sech  策略回测  + 周期芯片 #bbChips
card
  ├ 头部：#bbMeta（"740 天 · 2024-10-22 → 2026-10-31"）、#bbBudget
  ├ 指标区：#bbStats（5 行，两列布局）
  ├ 权益曲线：#bbEquip（内联 SVG 折线，两条）
  ├ 对照表：#bbPeers（3 行 × 4 列）
  ├ 触及表：#bbGears（横向 chip，每档一枚）
  ├ 开关：#bbOpts（3 个 switch）
  └ 说明：#bbNote（固定文案）
```

### 2.2 权益曲线

- 宽 = 容器宽，高 120px
- 两条折线：本策略（主色）、定投（灰虚线）
- **降采样**：点数 > 200 时按 `step = ceil(n/200)` 抽点，避免 740 个 `<path>` 节点
- y 轴只标最大值与最小值两个刻度，不画网格

### 2.3 触及表

每档一枚 chip：`第1档 12次 08-14`。零次显示 `第1档 0次 —`。窄屏横向滚动，不换行。

## 三、批三：交互与边界

### 3.1 周期切换

四个芯片（周 / 日 / 4h / 1h），切换后整卡重算。**不缓存跨周期结果** —— 每个周期只算一次，切回来重算 50ms 级别，没必要缓存。

单位按周期取：周 → 周、日 → 天、4h / 1h → 根（与 P19-1 一致）。

### 3.2 三个开关

| 开关 | 字段 | 切换后 |
|---|---|---|
| 循环档卖出 | `btOpts.loop` | 整卡重算 |
| 配额下沉 | `btOpts.realloc` | 整卡重算 |
| 手续费 | `btOpts.fee`（0 / 0.02% / 0.05%） | 整卡重算，从每次买卖金额中扣 |

开关状态写进 `S.cfg.btOpts`，持久化。

### 3.3 边界提示

| 场景 | 文案 |
|---|---|
| 一档未触发 | 「区间内未触及任何档位 —— 可能是档位设得比历史波动更浅，或区间内金价单边上涨」 |
| 预算不足 | 「有 N 次触发因预算不足未买入」 |
| 数据不足 | 「数据不足，无法回测」 |
| 恒显示 | 「固定档位 · 不含盘中路径 · 数据为 PAXG，按美元计」 |

### 3.4 批三测试（6 条）

| # | 用例 | 断言 |
|---|---|---|
| d1 | 切到 1h | 单位变「根」，`#bbMeta` 含「根」 |
| d2 | 切到周线 | 单位变「周」 |
| d3 | 开关循环档 | 结果与「直接以该配置启动」一致（不依赖历史状态） |
| d4 | 开关持久化 | 刷新后仍保持 |
| d5 | 预算不足提示 | 出现「因预算不足」 |
| d6 | 恒显示说明 | `#bbNote` 含「PAXG」「美元」 |

## 七、风险

| 风险 | 概率 | 应对 |
|---|---|---|
| 下沉在回测里的语义与实盘不一致（回测按日、实盘按实时） | 高 | 页面说明「下沉按日收盘价判定」；开关默认关 |
| 循环档卖出规则被当成「系统推荐卖点」 | 中 | 开关旁常驻文案：「这是回测假设的规则，不是系统给的卖点」 |
| 固定档位在长牛区间内全部失效，结论为空 | 中 | 边界提示写清楚原因 |
| 权益曲线节点过多导致移动端卡顿 | 低 | 降采样到 200 点以内 |
| `reallocPlan` 加参数后有人误传 ctx | 低 | `b12` 锁默认路径 |

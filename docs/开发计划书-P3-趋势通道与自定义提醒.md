## 0. 一页结论

v6.5 把「关键位」从 13 个扩到 20+ 个，解决了**「有什么位」**。但它仍然是一串数字：

- 用户看不出**这些位排在一起是什么形状**——是上升通道里的回踩，还是下跌中继的反抽；
- 用户没法**把自己看到的位加进去**——软件算 300 个位，也不如他自己记住的那个前高；
- 用户没法**让软件盯着某个位**——只能每 15 秒自己刷一眼。

所以 P3 只做三件事，一件一期：

| 期 | 版本 | 模块 | 一句话 | 依赖 |
|---|---|---|---|---|
| P3-1 | v6.6 | 趋势线与通道 | 用一张 90 根的迷你 K 线，把回归通道画出来，并给出「在通道什么位置」 | 无 |
| P3-2 | v6.7 | 自定义位 | 自己加价、命名、备注，与系统位并排显示，重合时提示 | 无（与 P3-1 独立） |
| P3-3 | v6.8 | 到价提醒 | 对任意价位设「上破 / 下破 / 双向」，命中进待办 + 响铃 + 挂角标 | 复用 P3-2 的价位对象 |

**关键取舍（本期锁定）**：

1. **不做手绘趋势线**。手机屏幕拖两根线，手指就是 44px 宽，画出来的线精度比不上算法；而且没有撤销、没有吸附，用户体验是负的。改为**统计回归通道 + 触轨次数**，可复现、可测试。
2. **不做后台推送**。GitHub Pages 是纯静态，没有服务端，关闭页面就收不到提醒。这一点在 P3 里仍然是硬边界，文案要说清楚，不能给用户「关了也会响」的错觉。
3. **不改 `buildLevels()` 的输出**。通道线与自定义位都在**渲染层叠加**，不进入 `S.levels`。这样存量 109 项断言一条都不用改，回归面为零。
4. **每期可单独回退**。三期分别存档，回退任一期都不丢数据（v6.5 会原样保留不认识的 `marks` / `alerts` 字段）。

### 1.3 为什么这次必须画图

「趋势线 / 通道」本质上是一个**几何对象**，用文字描述（「上升通道，上轨 4128，下轨 4053，斜率 +2.1 美元/根」）用户要在脑子里重建图形，认知成本比看一张 180px 高的图高一个数量级。

同时，一张图能顺带解决另外两个问题：自定义位可以「在图右侧打标记」，提醒可以「点图上的位置直接设」。所以图不是炫技，是后两个模块的**承载体**。这也是把 P3-1 排在最前面的原因。

## 4. P3-1 · 趋势线与通道（v6.6）

### 4.1 要解决什么

给出一句能直接用于决策的话：

> 日线上升通道，现价在 72% 位，贴上轨；通道宽 3.2 ATR，近 90 根触碰上轨 3 次。

而不是给一堆数字让用户自己拼。

### 4.2 算法：最小二乘回归通道

选回归通道而不是「两点连线」，理由写在 4.2.4。

#### 4.2.1 输入

```js
channelOf(bars, n)   // bars: scaled(k) 的 OHLC 数组；n 默认 90
```

- `n = 90`：日线约 4.5 个月，4 小时约 15 天，既能包住一段完整波段，又不至于把半年前的行情算进来。
- 数据不足 40 根返回 `null`（渲染层显示占位）。

#### 4.2.2 计算

```
x_i = i,  y_i = close_i,  i = 0 .. m-1

分母 den = m·Σx² − (Σx)²
斜率 b = (m·Σxy − Σx·Σy) / den          // 单位：美元/根
截距 a = (Σy − b·Σx) / m
中轨 mid_i = a + b·i
```

残差用**影线**而不是收盘价，通道要包住高低点：

```
上残差 ru_i = high_i − mid_i
下残差 rl_i = low_i  − mid_i
UP = P90(ru)          // 90 分位，不用极值，避免一根插针把通道撑爆
DN = P10(rl)          // 10 分位，为负
```

强制最小半宽，防止窄幅盘整时通道退化成一条线：

```
half = 0.6 × ATR14
UP = max(UP,  half)
DN = min(DN, −half)
```

在「现在」（i = m−1）：

```
mid  = a + b(m−1)
up   = mid + UP
dn   = mid + DN
pos  = (price − dn) / (up − dn)          // 0 = 贴下轨，1 = 贴上轨
slopeAtr  = b / ATR14                     // 每根走多少 ATR
widthAtr  = (up − dn) / ATR14
```

拟合质量（决定文案强弱）：

```
R² = 1 − SSres/SStot     // 用收盘价算，SSres = Σ(c_i − mid_i)²
```

#### 4.2.3 判定阈值

| 指标 | 阈值 | 结论 |
|---|---|---|
| `slopeAtr` | > +0.015 | 上行通道 |
| | < −0.015 | 下行通道 |
| | 其余 | 横盘通道 |
| `\|slopeAtr\|` | 0.015–0.04 / 0.04–0.08 / > 0.08 | 缓 / 中 / 陡 |
| `pos` | ≥0.9 / 0.65–0.9 / 0.35–0.65 / 0.1–0.35 / ≤0.1 | 贴上轨 / 偏上 / 中轨附近 / 偏下 / 贴下轨 |
| `widthAtr` | < 2.0 / 2.0–4.0 / > 4.0 | 收窄 / 正常 / 扩张 |
| `R²` | < 0.35 | 趋势不明显（文案降权，灰色） |
| 触轨次数 | `\|high−up\| ≤ 0.25·ATR` 计上轨；`\|low−dn\| ≤ 0.25·ATR` 计下轨 | ≥3 次标「有效」 |

**突破判定**用**收盘**，不用盘中价：最近 3 根日线收盘都在 `up` 之上（或都在 `dn` 之下）→ `broken = true`，通道线转灰虚线，文案改「通道已破，仅作参考」。这样 15 秒一次的盘中抖动不会来回改标签。

#### 4.2.4 为什么不用两点连线

| 维度 | 两点连线 | 回归通道 |
|---|---|---|
| 稳定性 | 换一个锚点，结论就变；同一段行情两个人都能画出不同的线 | 同一段数据只有一个结果 |
| 可测试 | 难以写出稳定断言（锚点选择本身就是启发式） | 给定序列，斜率/通道位/宽度全部可精确断言 |
| 移动端 | 无法手工微调，也没有意义 | 无需交互 |
| 表达力 | 能画出「精确的趋势线」 | 表达「趋势 + 波动带」，对交易决策更实用 |

结论：回归通道做**主**，两点连线不做。计划书里写死，避免后期反复。

#### 4.3.5 周期切换

- 切换只重算 `channelOf(scaled(k), 90)` 并重绘，不动其它区块；
- `chMeta` 同步显示「日线 · 90 根 / 4小时 · 90 根」。

### 4.5 数据结构变化

**无**。`channelOf()` 是纯函数，结果只进内存 `S.chan`，不写云端、不进 `data.json`。

## 5. P3-2 · 自定义位（v6.7）

### 5.1 数据模型

```json
"marks": [
  {
    "id": "mk_lq2k9x",
    "price": 4100,
    "name": "前高压力",
    "kind": "auto",              // auto | sup | res
    "note": "8 月两次冲高失败",
    "at": 1761700000000,         // 创建时间
    "up": 1761700000000          // 最后修改时间（合并时用它仲裁）
  }
]
```

| 字段 | 约束 |
|---|---|
| `id` | `mk_` + `Date.now().toString(36)` + 3 位随机；全局唯一 |
| `price` | 数字，`500 ≤ price ≤ 50000`，保留 2 位小数 |
| `name` | ≤ 16 字，空则自动「我的位 $4100」 |
| `kind` | `auto` 表示按现价动态显示支撑/阻力（默认），`sup`/`res` 为手工锁定 |
| `note` | ≤ 60 字，可空 |
| `at` / `up` | 毫秒时间戳 |

上限 **50 条**，超出时保存动作被拒并 toast「最多 50 个位置，先删几个」。

### 5.2 与系统位的关系（关键设计）

自定义位**不进入** `buildLevels()`：

- `buildLevels()` 输出的 `S.levels` 保持纯净，聚类、强度、窗口全部不变 → 存量断言零改动；
- 自定义位在 `renderKL` **之前**由 `renderMarks()` 渲染成独立区块 `.mklist`，与 `#klist` 上下相邻；
- 重合提示在渲染时计算：`S.levels` 中存在 `|L.price − m.price|/m.price < 0.35%` → 行尾显示 `≈ 整数 $4100`（取该簇 `label` 首个名称）；
- 视觉区分：自定义行左侧 2px 金色竖条 + 「我的」小标签；系统行保持原样。

这样做的代价是「自定义位不参与强位计数」，收益是**两套逻辑互不污染**，回退和排障都简单。

### 5.3 UI 规格

#### 5.3.1 区块

```

────────────────────────────────────────
4100.00  前高压力        我的      +0.7%   🔔
4052.30  整数关下方      我的      -0.5%   —
```

### 5.4 云端合并（本期的最大风险点）

现有 `mergeRemote()` 只对 `buys` / `sells` 做并集，其它字段走 `Object.assign`（整体覆盖，本地优先）。`marks` 若照此处理，**两台设备会互相覆盖**。必须显式并集：

```js
function unionById(remoteArr, localArr, del){
  var out = [], seen = {};
  (remoteArr || []).concat(localArr || []).forEach(function(x){
    if(!x || !x.id || del[x.id]) return;
    if(seen[x.id]){
      // 同 id 冲突：取 up 更新的一条
      var i = out.findIndex(function(y){ return y.id === x.id; });
      if(i >= 0 && (x.up || x.at || 0) > (out[i].up || out[i].at || 0)) out[i] = x;
      return;
    }
    seen[x.id] = 1; out.push(x);
  });
  return out;
}
```

同时必须补三处，否则会出现「数据看不见了」这类隐蔽 bug：

| 函数 | 现状 | 改法 | 不改的后果 |
|---|---|---|---|
| `mergeRemote` | 只并集 buys/sells | 增加 `out.marks = unionById(...)` | 双设备互相覆盖自定义位 |
| `isEmptyCfg` | 只看 buys/sells/H_BASE | 增加 `marks.length`、`alerts.length` 判断 | 远端**只有**自定义位时被判为空，推送时直接覆盖 → 丢数据 |
| `countCfg` | buys + sells | 加上 marks + alerts | 「有没有数据」判断失真 |
| `pruneCfg` | 只裁 feed / takePlan | `marks` / `alerts` 各保留最新 50 | `data.json` 无限膨胀 |

### 5.5 数据结构变化

`data.json` 新增 `marks`（数组）、`schema: 3`。读取侧全部容错：缺字段即视为空数组。

```json
"alerts": [
```

### 6.2 状态机

只在 `refreshPrice()` 拿到新价格后调用一次：

```js
function checkAlerts(prevP, p){
  if(prevP === null || p === null) return [];
  var fired = [], dirty = false, now = Date.now();
  (S.cfg.alerts || []).forEach(function(a){
    if(!a.on) return;
    var side = p >= a.price ? 1 : -1;
    var old  = S.alertSide[a.id];
    S.alertSide[a.id] = side;
    if(old === undefined) return;                  // 首次观测只记录，不触发
    if(old === side) return;                       // 没有穿越

    // 重复模式的重新武装：必须离开 ±0.15% 缓冲区
    if(S.armed[a.id] === false){
      if(Math.abs(p - a.price)/a.price > 0.0015) S.armed[a.id] = true;
      return;
    }
    var isUp = side === 1;
    if(isUp && a.dir === "down") return;
    if(!isUp && a.dir === "up") return;
    if(a.firedAt && now - a.firedAt < 60000) return;   // 60 秒去抖

    a.firedAt = now; a.firedP = p; a.ackAt = 0;
    if(a.mode === "once") a.on = false;
    S.armed[a.id] = false;
    fired.push(a);
    dirty = true;
  });
  if(dirty) saveCfg();          // 一次 tick 多个命中，只写一次云端
  return fired;
}
```

内存态两个 `Map`（`S.alertSide`、`S.armed`），**不写云端**，页面刷新后重新建立基线，天然实现「首次打开不响」。

### 6.3 触发后的四处联动

| 落点 | 行为 |
|---|---|
| **今天要处理** | 新增 `kind:"alert"`，优先级排在 `buy` 之后、`warn` 之前（`fatal:0 → take:1 → buy:2 → alert:3 → warn:4 → ev:5`），按钮「知道了」→ `ack` |
| **底栏角标** | 结构 Tab 新增 `#bdStruct`，计数 = `firedAt && !ackAt` 的条数；沿用现有规则「当前 Tab 不显示自己角标」 |
| **声音** | `playSnd("alert")`，复用 `warn` 的下行两音（659.3 → 493.9），不新增合成参数；`setSnd` 关闭时静默 |
| **信号页** | `pushFeed("alert", "提醒命中 · 前高压力", "上破 4100.00 · 现价 4101.2")`，进现有动态流 |

**确认（ack）语义**：`ackAt = Date.now()`。`mode:"once"` 命中后已自动 `on=false`，ack 只是清角标；`mode:"repeat"` 保持 `on=true`，ack 后等下一次穿越。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| `mergeRemote` 漏加 `marks` | 双设备互相覆盖自定义位 | MK6/MK7 守门；先在数据层跑通再接 UI |

### E.2 开发中定位并修掉的问题

1. **通道覆盖率的断言写错了**：第一版拿「现价处的上下轨」当水平线去比历史每根 K 线，
   结果斜通道下只有 1 根落在里面。改成「每根跟它自己那一根时间的轨比」，
   分侧覆盖率 ≥88%、两侧同时覆盖 ≥78%。这是测试的错，不是算法的错，但暴露了
   `up` / `dn` 语义（现价处的轨）容易被误用，已在代码注释里写明。
2. **`env.goto()` 会丢掉 `?xt=1`**：MK2 想验证「刷新后数据还在」，用 `env.goto()` 重载后
   `window.__xt` 不再挂载，等待超时。改为显式 `page.goto(BASE + "/index.html?xt=1")`。
3. **列表显示精度**：自定义位列表沿用关键位的 1 位小数（4120.25 显示 4120.3），
   原断言按 2 位小数比对失败。确认这是既有显示约定后，把断言改成精确等于 4120.3，
   比放宽容差更严格。
4. **空态示例价写死 $4100**：`Math.round(4072.4/50)*50` 实际是 4050，按钮文案与实际
   添加的价位不一致。改成按现价动态计算。

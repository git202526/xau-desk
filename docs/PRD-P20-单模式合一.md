## 一、问题：账本模式下的档位表是一张死表

实测（总仓 200g、建仓 48g、现价 4030、六档）：

| 场景 | 档位表六档 | 操作按钮 | 总持仓 |
|---|---|---|---|
| 计划模式 | 第 1 档 `16 / 16g`，标「已买满」 | **7 个** | — |
| 账本模式 | 六档全部 `0 / 16g`，全显示「待补满额」 | **0 个** | 48g |
| 账本模式卖 24g 后 | 六档**一个数都没变** | 0 个 | 24g |

三个入口同时关闭，且互相堵死：

| 入口 | 现状 | 后果 |
|---|---|---|
| 记账时选档 | 只有计划模式显示「关联档位」下拉，且**卖出永远不显示** | 账本模式的记录永远没有档位归属 |
| 档位卡标记按钮 | 整块只在计划模式渲染 | 账本模式连「标记已买」都没有 |
| 唯一兜底「重算档位」 | 从第 1 档往上填，且会清掉所有手工标记 | 粒度粗，一用就抹掉细节 |

结果：**账本模式的档位表只是一张静态计划表，跟持仓零关联。** 卖出减仓，档位纹丝不动。

---

## 二、目标

删掉「计划模式 / 账本模式」这个二分，全站只有一套档位数据源、一套操作入口。

统一后，无论过去叫哪种模式，行为完全一致：

- 档位卡永远有「买入 / 卖出 / 标记已买 / 撤销」按钮
- 记账表单永远能选「关联档位」（买入、卖出都能）
- 手动标记照样可用，且不产生任何记账
- 卖出减仓会按净持占比摊到各档，「释放的额度重新参与配额」自动成立

---

## 三、什么是「一个模式」

```
累计买入ᵢ = 标记里这档买过多少（含记账反写的部分）
累计卖出ᵢ = 标记里这档卖过多少（含减仓摊派的部分）
净持仓ᵢ   = max(0, 累计买入ᵢ − 累计卖出ᵢ)
待补ᵢ     = 计划ᵢ − 净持仓ᵢ
```

三条来源规则（P15 已定的「记账优先」继续用）：

1. **记账选了档 → 自动写标记**，省一次手动
2. **手动标记 → 只写标记**，绝不产生记账记录
3. **同一档既有记录又有标记 → 以记录为准**（记录改了删了，标记跟着重算）

## 四、原来那个开关其实扛了三件事，现在各归各位

`planOnly` 不只是「数据源开关」，它同时控制了三件互不相关的事。整体删掉会误伤，必须拆开：

| 职责 | 原来怎么判 | 统一后怎么判 | 为什么 |
|---|---|---|---|
| **档位数据从哪读** | 计划模式读标记，账本模式读记录 | 一律读标记；记录只负责反写标记 | 只有一个真相，不会两边打架 |
| **已持仓是否折算目标价** | 计划模式跳过折算 | 看**有没有真实持仓**（> 0.01g） | 这是「我已经有 100g，还要买多少才能到目标均价」的问题，与模式无关。没持仓时折算无意义，自动跳过 |
| **操作入口显不显示** | 计划模式才显示 | 永远显示 | 档位卡就是操作台，没有理由藏起来 |

同理，另外三处原来挂在模式开关上的限制，也换成更准确的判据：

| 功能 | 原来 | 统一后 |
|---|---|---|
| 循环档卖出 | 计划模式 + 必须是循环档 | 只看**是不是循环档** |
| 深档兜底（到期提示） | 计划模式 | 只看**这一档还有没有待补、价格到没到** |
| 减仓摊派 | 计划模式 | 一律执行（只要有标记可摊） |

## 五、老数据怎么处理

升级后老用户有三种数据形态，必须都能用：

| 形态 | 现状 | 升级后 |
|---|---|---|
| **A. 记录带档位** | 每笔买入记了「第 2 档」 | 启动时自动反写标记，档位表立刻有数 |
| **B. 只靠「重算档位」** | 记录没档位，靠一个「哪些档买满了」的名单 | 按该档计划克重写一次标记，名单保留只读 |
| **C. 全新用户** | 什么都没标 | 档位表显示待补，等你标记，符合预期 |

**迁移只跑一次**，跑完留一个标记防止重复。迁移不改任何记账记录，只补标记。

一个必须接受的代价：迁移后如果用户后来又删了老记录，档位标记不会自动回退（因为老记录本来就没有档位归属）。页面在迁移完成时提示一次：「历史记录已折算为档位标记，后续请用标记面板调整」。

## 六、界面变化

| 位置 | 变化 |
|---|---|
| 设置页 | **删除「计划模式」开关**（它已经没有意义了） |
| 计划页档位卡 | 所有档位恒显示操作按钮；原来账本模式下的「已买 X g」文案改为统一的「净持 / 计划」 |
| 持仓页记账表单 | 「关联档位」下拉恒显示；**卖出也能选**（选「不关联」则按净持比例分摊） |
| 计划页 | 模式差异消失，不再有「账本模式不显示某些标签」的分支 |

## 七、非目标

| 不做 | 原因 |
|---|---|
| 把卖出记录拆成多条（每档一条） | 账本列表会从 1 行变 6 行，用户看不懂；摊派只写标记即可 |
| 自动对账（档位表与账本持仓不一致时报警） | 两层本来就允许不一致：档位管计划进度，账本管真实持仓。这是设计，不是 bug |
| 迁移时改写老记录 | 动用户数据的风险远大于收益 |
| 保留「计划模式」作为可选模式 | 这正是本期要根除的东西 |

## 八、边界与异常

| 场景 | 处理 |
|---|---|
| 同一档既手动标了 8g，又记了 4g | 以记录为准 → 标记变 4g。这是 P15 已定规则，本期不变 |
| 迁移时某档计划克重为 0 | 跳过该档，不写空标记 |
| 用户的「重算档位」名单里有不存在的档名 | 忽略，迁移时按档名匹配不到就跳过 |
| 卖出摊派时某档净持为 0 | 跳过该档，不产生 0 克标记 |
| 账本模式从未记过账 | 标记为空，档位表全待补，与全新用户一致 |

## 九、验收标准

1. 同一套数据，升级前后**档位表的净持、待补完全一致**（对能迁移的形态）
2. 账本模式（升级后已无此概念）的档位卡必须出现操作按钮，数量与计划模式相同
3. 记账表单在买入、卖出两种情境下都能选档位
4. 手动标记不产生任何记账记录（记账条数不变）
5. 记账选了档之后，档位表的净持自动等于该档累计买入
6. 卖出不选档时，按各档净持占比摊派，合计等于卖出克重
7. 已持仓折算目标价：有持仓时生效、无持仓时跳过，与模式无关
8. 深档兜底在两种历史数据形态下都能触发
9. 「计划模式」开关从设置页消失，且老配置里的该字段被忽略（读到时丢弃，不报错）
10. 迁移只执行一次，重复启动不重复写标记

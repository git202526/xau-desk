## 零、开工前的三条纪律

1. **每批先跑基线**：动代码前先确认该批涉及的测试文件当前全绿，否则改完分不清是谁弄挂的
2. **只改契约真的变了的断言**：任何一条断言要改，必须在提交说明里写明「旧契约是什么、新契约是什么、为什么必须变」。不许为了变绿改断言
3. **迁移只写标记、不碰记录**：迁移过程中任何对 `buys` / `sells` 的写入都属于越界

## 一、批一：取数统一 + 老数据迁移

### 1.1 `boughtOf` 去掉双分支

**位置**：`boughtOf(i, planArr)`，现为 if/else 两套取数。

```js
// 改前
if(cfg.planOnly){
  var m = (cfg.gearMarks || {})[String(i)];
  if(!m) return 0;
  return Math.max(0, (Number(m.g) || 0) - (Number(m.sold) || 0));
}
var nm = gearSeq()[i - 1];
... gearBought(nm) ... gearsDone 兜底 ...

// 改后：只剩一套
var m = (cfg.gearMarks || {})[String(i)];
if(!m) return 0;
return Math.max(0, (Number(m.g) || 0) - (Number(m.sold) || 0));
```

`gearsDone` 的兜底逻辑**不删除**，但移到迁移里一次性折成标记，运行时不再读它。保留 `boughtOf` 的 `planArr` 形参签名，避免调用点连锁改动。

### 1.2 `syncMarksFromBuys` 去掉模式前缀

**位置**：函数首行 `if(!(S.cfg && S.cfg.planOnly)) return false;`

直接删除该行。函数内部逻辑不变（它本来就只按 `buys[].gear` 聚合，与模式无关）。

### 1.3 新增 `migrateGearsDone()`

放在 `normCfg()` 之后、首次 `compute()` 之前执行一次。

```
若 S.cfg.migratedV7 为真 → 直接返回
遍历 gearsDone 里的每个档名：
    找到对应的档号 k
    若 gearMarks[k] 已存在 → 跳过（不覆盖用户已有标记）
    plan = planOf()[k-1]
    若 plan <= 0.05 → 跳过
    写 gearMarks[k] = { g: plan, cost: plan × 该档档位价, sold: 0, at: Date.now(), migrated: true }
置 S.cfg.migratedV7 = true
saveCfg()
```

**注意**：`planOf()` 依赖 `S.gears`，迁移必须在 `compute()` 之后跑，否则拿到的是空计划。因此实际挂载点是「首帧渲染完成后」。

迁移后用 toast 提示一次（见 PRD §5），提示文案走 `toast`，不做弹窗。

### 1.4 `allotSell` 去掉模式条件

**位置**：`saveSell` 内 `if(S.cfg.planOnly) allotted = allotSell(...)`

去掉条件，直接调用。`allotSell` 内部已有 `sum > 0` 保护，无标记时自然返回 0。

### 1.5 批一测试

| # | 用例 | 断言 |
|---|---|---|
| m1 | 记录带档位的账本数据（48g 记在第 2 档） | 升级后第 2 档净持 24g（计划克重，若记录克重不同则以记录为准） |
| m2 | 只有 gearsDone 名单 | 迁移后对应档净持 = 计划克重 |
| m3 | 既有标记又有 gearsDone | 标记不被覆盖，`migrated` 字段不存在 |
| m4 | 迁移跑两次 | 第二次不写任何标记，`gearMarks` 不变 |
| m5 | 全新用户（空数据） | 不报错，档位表全待补 |
| m6 | 净持公式 | 标 16g、卖 8g → 净持 8g、待补 8g |
| m7 | `gearsDone` 里含非法档名 | 跳过，不产生空标记 |
| m8 | 记账带档后反写 | 档位净持 = 该档累计买入 |

## 二、批二：入口开放

### 2.1 `markSell` 去掉模式拦截

**位置**：`if(!(S.cfg && S.cfg.planOnly)) return false;`

删除该行。**保留** `if(!isSwingGear(i))` —— 那是业务规则（建仓档不卖），不是模式限制。

### 2.2 `renderLadder` 合并两套渲染

**位置**：`var planOnly = !!(S.cfg && S.cfg.planOnly);` 及其下游 4 处。

- 克重栏统一为「净持 / 计划g」，删除「已买 X g」「待超目标」那套账本文案
- 操作按钮恒显示：循环档给「买入 / 卖出」；建仓档给「标记已买 / 撤销」
- `if(planOnly && !g.warn && g.boughtG > 0.05) ui.cls += " markDone"` → 去掉条件
- 深档兜底的 `if(planOnly && ...)` → 去掉条件

### 2.3 `fillGearLink` 放开买卖两种情境

```js
// 改前
var on = !!(S.cfg && S.cfg.planOnly) && S.sheetMode !== "sell";

// 改后
var on = true;                      // 买入、卖出都能选档
```

「不关联（只记持仓）」选项保留，且卖出时作为默认值（因为减仓通常是整体降仓，不是单档）。

### 2.4 `computesGears` 清理模式分支

**位置**：`var planOnly = !!cfg.planOnly;` 及 5 处下游。

| 原代码 | 改为 |
|---|---|
| `var held = planOnly ? 0 : (hs.grams \|\| 0)` | `var held = hs.grams \|\| 0` |
| `var mk = planOnly ? (...) : null` | `var mk = (cfg.gearMarks \|\| {})[String(k)] \|\| null` |
| `realized = (planOnly && soldG > 0) ? ...` | `realized = soldG > 0 ? ...` |
| `turns = planOnly ? gearTurns(...) : 0` | `turns = gearTurns(...)` |
| `swing: planOnly && isSwingGear(k)` | `swing: isSwingGear(k)` |
| `planOnly: planOnly`（meta 里） | 删除该字段，同时检查无读取方 |

### 2.5 删除设置页开关

| 位置 | 动作 |
|---|---|
| HTML `<input id="setPlanOnly">` 及其 `<label>` 整块 | 删除 |
| `renderSet()` 里 `var po = $("setPlanOnly"); ...` | 删除 |
| 保存时 `S.cfg.planOnly = !!($("setPlanOnly")...)` | 删除 |
| `__xt.setPlanOnly` 导出 | 保留一个空实现（`function(b){}`），避免老测试整体报错；或用它强制迁移测试数据 |

## 三、批三：均价口径改用持仓判据

### 3.1 `gearBase` 里的已持仓折算

**位置**：`if(T && !cfg.planOnly){ ... heldG > 0.01 ... }`

改为：

```js
if(T){
  var hs = holdStats();
  var heldG = hs.grams || 0;
  if(heldG > 0.01){ ... }
}
```

即去掉模式条件，保留持仓判断。**这是行为变化最大的一处**：以前账本模式才折算，现在只要真有持仓就折算。

### 3.2 `computesGears` 里的整体均价 `mix`

**位置**：`if(T && !planOnly){ ... }`

同样改为 `if(T){ ... }`，内部已有 `heldG` 判断。

### 3.3 批三测试

| # | 用例 | 断言 |
|---|---|---|
| o1 | 有持仓 100g、目标均价 T | 折算后的剩余均价使「持仓 + 补满」整体命中 T |
| o2 | 无持仓 | 折算跳过，档位价与 `T` 直接反解一致 |
| o3 | 有持仓但目标价为空 | 不折算、不报错 |
| o4 | P10 双口径均价 | 锚定均价 < 全档试算均价 的关系不变 |
| o5 | 持仓为 0.5g（< 阈值） | 视为无持仓，跳过折算 |

## 五、老测试影响面：21 文件 38 处

不预判、不广撒网，按文件逐个跑、逐条定位根因。

### 5.1 预计会挂、且属于**契约真的变了**的

| 文件 | 预计冲突 | 处理 |
|---|---|---|
| `test_p15_ledger_realloc.py` | 账本模式现在也读标记，`boughtOf` 结果变 | 补前置数据（写标记），断言不改 |
| `test_p61_swing_engine.py` / `p62_swing_ui.py` | `markSell` 不再要求模式 | 断言不变，去掉测试里的模式设置 |
| `test_p71_drip_engine.py` / `p72_drip_ui.py` | 兜底不再要求模式 | 同上 |
| `test_p10_dual_avg.py` | 均价折算现在按持仓判断 | 若测试用「有持仓 + 计划模式」构造，结果会变 → 按新契约修前置数据 |
| `test_p15_plan_record.py`（20 条） | 大量用模式切换构造场景 | 预期大部分仍绿（统一后行为更宽松） |

### 5.2 处理原则

- **只补前置数据**（写 `gearMarks`、去掉 `planOnly` 设置）：不改断言
- **契约真变了的**（如「账本模式不显示按钮」这类断言）：改断言 + 提交说明写明新旧契约
- **跑不通就问**：如果某条测试的意图在新的单模式下已经不成立（例如「账本模式不该有标记按钮」），说明这条测试本身在守一个已废弃的契约 → 删除前必须在提交说明里写清楚

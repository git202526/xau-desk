# PRD · P21 摊派回滚

| 项 | 内容 |
|---|---|
| 期次 | P21 |
| 版本 | PRD v1.0（待确认，未开发） |
| 日期 | 2026-11-01 |
| 影响页面 | 持仓页（账本列表、记账表单）、计划页（档位卡） |
| 前置期次 | P16 减仓摊派（v6.29）、P20 单模式合一 |

---

## 一、问题：摊派只写一次，事后改不了

P16 让「卖 100g」不再需要逐档点标记，改为按各档净持占比自动摊进档位的「累计卖出」。但摊派**只在保存那一刻执行一次**，之后：

| 操作 | 现在的行为 | 应该有 |
|---|---|---|
| 删掉那笔卖出记录 | 持仓加回来了，**档位的「卖出过」纹丝不动** | 档位也应退回分摊前 |
| 把 100g 改成 80g | 持仓按 80g 算，**档位还是按 100g 摊的** | 档位应按 80g 重摊 |
| 删掉再重新记一笔 | 档位被摊两次，**卖出总量翻倍** | 应与「一次记对」结果相同 |

实测确认：删除卖出记录后，`sold` 字段一个字节都不变，`syncMarksFromBuys` 只处理买入、不处理卖出。

结果是：用户记错一笔减仓，只能手工去每档点「撤销」，而「撤销」清的是整档标记，不是那 100g —— 等于把该档的历史一起抹了。

---

## 二、目标

卖出记录与档位分摊之间建立**可逆**关系：

1. 删除卖出记录 → 该笔分摊自动退回
2. 修改卖出克重 → 先退旧、再摊新
3. 账本列表**仍然只有一行**（不增加记录条数，不改变用户看到的样子）

---

## 三、方案：记录里存一份分摊快照

卖出记录增加一个可选字段，记下「这笔卖出摊到各档多少克」：

```
{ id:"s1", gram:100, priceCny:4000, time:"…",
  allot: { "1":8, "2":12, "3":24, "4":36, "5":12, "6":8 } }
```

### 3.1 为什么必须存快照

分摊依据是「卖出那一刻各档的净持占比」。净持会变 —— 明天又买了 20g，占比就不是原来的了。

事后要精确退回，只有两个办法：

| 办法 | 问题 |
|---|---|
| 重新按当前占比反推 | 占比已变，退回去的位置和当初摊的位置不一致，越退越歪 |
| 记下当初摊在哪 | ✅ 唯一精确的办法 |

### 3.2 这不是「给卖出标档位」

必须区分两件事：

| | 用户选档位 | 系统存分摊快照 |
|---|---|---|
| 语义 | 「这 100g 是从第 3 档卖的」 | 「这 100g 按比例摊到了 6 个档」 |
| 谁决定 | 用户选 | 系统算 |
| 可见性 | 表单下拉 | 记录详情里的一行明细 |
| 记录条数 | — | **不变，仍是 1 条** |

用户仍然不需要回答「哪 100g」，快照是系统的账。

## 四、三种操作的具体行为

### 4.1 新增卖出

```
① 按各档净持占比算分摊（最大余数法保证合计精确）
② 写 allot 到记录
③ 把分摊结果累加进各档「累计卖出」与「回笼金额」
```

### 4.2 删除卖出

```
① 读出这笔记录的 allot
② 各档「累计卖出」减去 allot 对应的克重，夹紧到 ≥ 0
③ 各档「回笼金额」按同比例减掉
④ 删除记录
```

**没有 allot 的老记录**（P16 之前记的）：按「当前各档累计卖出的占比」反摊，总量精确、分布近似。页面对这类记录在删除时提示一次。

### 4.3 修改卖出克重

```
① 先按旧 allot 完全退回（同 4.2）
② 再按新克重重新分摊（同 4.1）
③ 覆盖 allot
```

修改价格（克重不变）不动分摊，只更新记录本身。

## 五、精度边界（必须接受）

| 场景 | 结果 |
|---|---|
| 新记录删除 | **精确**退回 |
| 老记录（无快照）删除 | 总量精确，各档分布近似（用当前占比反推） |
| 同一档被多笔卖出反复摊派后删其中一笔 | 可能夹紧到 0，出现少量漂移；总量对得上，分布可能有误差 |
| 删除期间用户又手工改过某档标记 | 以手工改动为准，反摊只做减法且不越过 0 |

漂移的上限是「该档累计卖出被减到 0 后的剩余量」，不会出现负数、不会把买入记录吃掉。

页面的说明文案：**「删减仓会把档位的卖出量退回去；如果中间又买卖过，各档比例可能有细微偏差，总量不会错。」**

## 六、界面

| 位置 | 变化 |
|---|---|
| 账本列表 | 卖出记录仍然是**一行**「减仓 100g」，不展开成 6 行 |
| 记录详情 | 多一行「已摊入：第1档 8g / 第2档 12g / …」，可折叠 |
| 删除确认 | 文案从「删除这笔减仓记录？持仓会加回来」扩为「…持仓和档位卖出量都会退回去」 |
| 老记录删除 | 额外提示「这笔记录没有分摊明细，将按当前比例近似退回」 |

---

## 七、非目标

| 不做 | 原因 |
|---|---|
| 把一次卖出拆成 N 条带档位的记录 | 账本列表会从 1 行变 6 行，用户看不懂 |
| 卖出时让用户选档位 | 与 P16 已定的「卖出不标档位」冲突 |
| 自动对账（档位卖出总量 ≠ 账本卖出总量时报警） | 两层本来就允许不一致，这是设计 |
| 回滚买入记录的档位反写 | P15 的 `syncMarksFromBuys` 已经处理了，不需要重复 |

---

## 八、边界与异常

| 场景 | 处理 |
|---|---|
| 记录的 allot 合计 ≠ 记录克重（数据损坏） | 以 allot 实际合计为准反摊，同时把记录克重修正为合计，并提示 |
| allot 里的档号超出当前档数（改过档数） | 超出部分跳过，不产生负值 |
| 该档当前累计卖出 < 要退的量 | 夹紧到 0，差额丢弃，不报错 |
| 卖出时各档净持全为 0 | 不产生 allot，记录照常保存（只影响持仓，不影响档位） |
| 同一笔记录被连点删除两次 | 第二次找不到记录，直接返回 |

---

## 九、验收标准

1. 卖 100g（摊到 6 档）→ 删除记录 → 6 档累计卖出**全部回到 0**，净持回到卖出前
2. 卖 100g → 改成 80g → 各档累计卖出等于按 80g 重摊的结果
3. 卖 100g → 删除 → 重新记 100g → 结果与「一次记对」完全一致
4. 老记录（不含 allot）删除 → 各档累计卖出总量减少值 = 记录克重（±0.1g）
5. 账本列表条数不变（卖出仍然 1 行）
6. 反摊后任何档的累计卖出都不为负
7. 反摊不影响买入记录与累计买入
8. 修改价格不改变分摊

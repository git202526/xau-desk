# P11 · 档位分布合计（超 100% 怎么办）

> 版本：v6.24 · 2026-10-31
> 用户原话：「档位分布百分比有 bug。选定档数，修改后超过 100%，怎么办？」

---

## 1. 结论先说：数据模型不是 bug，界面缺的是「看得见」

档位分布格子里的数字是**相对权重**，不是必须凑满 100 的份额。`planBase()` 一直这么算：

```
planᵢ = 总克重 × wᵢ / Σw
```

所以 `[4,5,8,11,14,16,50,50,50,50]`（Σ=258）和 `[2,2,3,4,5,6,19,19,19,19]`（Σ=100）
算出来的克重**一模一样**。超 100 不会算错，但界面上原来只有一行小字：

```
归一化 → 3.1 / 3.9 / 6.2 / 8.5 / 10.9 / 12.4 / 38.8 / 38.8 / 38.8 / 38.8 g
```

用户看不出「已经超了 158%」，也不知道该不该手动凑回 100。这才是要修的东西。

## 2. 三处改动

| 改动 | 行为 |
|---|---|
| 合计提示 | `合计 258%（超 158%）· 归一化 → …g`，合计偏离 100 超过 0.5 时整行标橙 |
| 实时草稿 | 输入框 `oninput` 就更新合计（只改文字，不落盘），不必等失焦 |
| 一键归一化 | 新增「归一化到 100%」按钮：按比例缩放 + 最大余数法取整，保证整数且**恰好** 100 |

最大余数法：先 `floor(wᵢ × 100 / Σw)`，再把差额（≤ n−1）按小数部分从大到小逐档 +1。
不做四舍五入 —— 那样合计可能变成 99 或 101，用户下次打开又要困惑。

## 3. 归一化不是必须动作

- 不点也完全正确：引擎永远按 Σw 折算，合计 258%、40%、1000% 都等价于比例。
- 点了只是让格子里的数字「看起来是份额」，方便口算和交接。
- 归一化后某档可能落到 0（原占比 < 0.5%），想保留就手动加回去。

## 4. 顺带解释一个容易误会的现象

截图里「归一化 → 0 / 0 / 9.6 / …」前两档是 0，**不是权重被清成 0**，而是 P8 配额下沉：
这两档（第 1、2 档）价格已经在现价上方、算「已跌破」，它们的**待补额度**被挪给了同角色里
未失效的档，所以 `planOf()` 里是 0，`planBase()` 里仍有值。关掉「配额下沉」开关就回来了。

## 5. 验收

`tests/test_p11_weight_sum.py`（10 条）：

1. 默认 100% 显示 `合计 100% ✓`，且保留 `归一化 → …` 预览
2. 编辑中（未失焦）就把 8→50：`合计 142%（超 42%）`、整行标橙
3. 8→0：`合计 92%（缺 8%）`
4. 落盘不改数值（`wPct` 仍是 50），`planBase` 总和恒等于总仓
5. 超 100 → 归一化后整数、总和恰好 100、最大档仍最大
6. 10 档 258% → 归一化后仍是 10 档、总和 100、量级关系不变
7. 已 100 时点归一化 = no-op（不产生 ±1 抖动）
8. 归一化后 `planBase` 总和仍等于总仓
9. 320 / 390 宽两个按钮不溢出

全量：`515 passed`（P10 基线 505 + 10）。

## 一、这次动的是「字段」，不是「显示」

如果把 `$3326.68` 直接换成 `¥23,952` 而不改字段，只是把一个假数字换成另一个假数字。真正的改动是：

> **实付人民币进入数据结构，成为唯一成本口径；美元价退化为「只用于比较的参考值」。**

代价是标记结构从四数变六数、已实现的单位从 `$` 变 `¥`、`perOz` 变 `perGram`。这三条都是**契约变更**，会打红一批既有测试。§五列了每一处该怎么改，全部是「补字段 / 换单位」，没有一条是放宽判据。

## 二、契约变化表（必须先看这一节）

| 契约 | 旧 | 新 | 谁受影响 |
|---|---|---|---|
| `gearMarks[i]` 结构 | `{g, cost, sold, proceeds, at}` | `{g, costCny, cost, sold, proceedsCny, proceeds, at}` | 所有构造 fixture 的测试 |
| `gearRealized()` | 返回 `$`，无成本时返回 `0` | 返回 `¥`，**`costCny = 0` 时返回 `null`** | `test_p61` s6/s7、`test_p16`、`test_p18` |
| `gearState().realized` | `$` | `¥` / `null` | `test_p46` s 系 |
| `markBuy(i, g, px)` | 三参 | 四参 `(i, g, px, cny?)`，`cny` 省略时不写 `costCny` | 无（向后兼容） |
| `markSell(i, g, px)` | 三参 | 四参，同上 | 无 |
| `rvSum().perOz` | `$/oz` | **改名 `perGram`**，单位 `¥/g` | `test_p18` b10 |
| `rvSum().realized` | `$` | `¥` + 新增 `cnyKnown:boolean` | `test_p18` b10 |
| `dripInfo().amt` | `$` | `¥` / `null` | 无（UI 未读） |
| `schemaVersion` | 1 | 2 | `test_p24` v1/v4 |
| 阶梯表循环档标签 | `+1234` | `+¥1,234`；未填时 `¥ —` | 无（无测试断言货币符号） |

> **`null` 不是 `0`。** 这是本次唯一容易写错的地方：`gearRealized` 返回 `0` 会让「不知道成本」看起来像「不赚不亏」。所有调用点必须能接 `null`，`num(null)` 要落到「—」。

## 三、批一：数据结构与写入（计算层）

### 3.1 `cleanGearMarks()`（约 3025 行）

四数补齐扩到六数。`costCny` / `proceedsCny` **不补值也不剔除** —— 缺失就是 0（未填），由显示层判断，不在清洗层猜。

```js
var costCny = Number(v && v.costCny) || 0;
var proceedsCny = Number(v && v.proceedsCny) || 0;
out[String(i)] = {
  g: Math.round(g * 10) / 10,
  cost: Math.round(cost * 100) / 100,
  costCny: Math.round(costCny * 100) / 100,
  sold: Math.round(sold * 10) / 10,
  proceeds: Math.round(proceeds * 100) / 100,
  proceedsCny: Math.round(proceedsCny * 100) / 100,
  at: at
};
```

`fromBuys` / `fromReset` 两个来源标记保持原样透传（P15 / P20 依赖）。

### 3.2 `gearRealized()`（约 3080 行）

```js
/* 已实现差价（人民币）= 卖出到账 − 卖掉那部分的成本。
   costCny = 0 表示「不知道花了多少钱」，返回 null 而不是 0：
   0 会被读成「不赚不亏」，而这是两个不同的结论。 */
function gearRealized(m){
  m = m || {};
  var g = Number(m.g) || 0, sold = Number(m.sold) || 0;
  var proceedsCny = Number(m.proceedsCny) || 0;
  var costCny = Number(m.costCny) || 0;
  if(!(g > 0) || !(sold > 0)) return null;
  if(!(costCny > 0)) return null;
  if(!(proceedsCny > 0)) return 0;        // 成本已知、卖出没填金额 → 只能算成 0，显示层会标「未填」
  return proceedsCny - sold * costCny / g;
}
```

参数从 `(m, cost)` 改为 `(m)`。三个调用点（`gearState`、`computeGears`、`__xt`）同步改。

### 3.3 `markBuy()`（约 3535 行）

加第 4 参 `cny`：

```js
function markBuy(i, deltaG, px, cny){
  ...
  var costCny = Number(m.costCny) || 0;
  var addCny = Number(cny) > 0 ? Number(cny) : 0;
  if(addCny > 0) costCny = Math.round((costCny + addCny) * 100) / 100;
  else if(prevG > 0 && costCny > 0){
    /* 这次没填金额，但本档有历史单价 → 按历史单价延续，避免出现「16g 有价、24g 只填了 8g 的钱」 */
    costCny = Math.round((costCny + (costCny / prevG) * deltaG) * 100) / 100;
  }
  S.cfg.gearMarks[k] = {
    g: ..., cost: ..., costCny: costCny,
    sold: ..., proceeds: ..., proceedsCny: ...,
    at: Date.now()
  };
}
```

> 第二分支（`else if`）是给 `doDrip` 和非 UI 调用用的：深档兜底一键买入没有金额输入，就按本档已有单价延续；本档从没填过 → `costCny` 保持 0，标记「未填」。**绝不用 `S.fx` 兜**。

### 3.4 `markSell()`（约 3565 行）

同样加 `cny`：

```js
proceedsCny: Math.round(((Number(m.proceedsCny) || 0) +
  (Number(cny) > 0 ? Number(cny) : q * (Number(m.costCny) || 0) / Math.max(g, 0.01))) * 100) / 100
```

不填金额时按**本档成本单价**记（不是当前价、不是汇率）。语义：卖出所得先按成本价保底，用户之后可改。这条与卖出的默认值保持一致（§4.3）。

### 3.5 `markGear()` 减少分支（约 3610 行）

按比例折 `costCny`，与 `cost` 同比例：

```js
costCny: Math.round(costCny * ratio * 100) / 100,
proceedsCny: Math.round(proceedsCny * (nsold / Math.max(sold, 1e-9)) * 100) / 100
```

### 3.6 `allotSell()` / `unallotSell()`（约 3680 / 3720 行）

`allotSell` 按克重比例把**金额**也摊进去，与克重分摊用同一个 `parts[j]`：

```js
var addCny = Number(cny) > 0 ? Number(cny) * addG / q : addG * (Number(m.costCny) || 0) / Math.max(g, 0.01);
proceedsCny: Math.round(((Number(m.proceedsCny) || 0) + addCny) * 100) / 100,
```

`unallotSell` 的 `giveBack()` 里同比例退：

```js
m.proceedsCny = Math.round(((Number(m.proceedsCny) || 0) * (1 - ratio)) * 100) / 100;
if(m.sold <= 0.05){ m.sold = 0; m.proceeds = 0; m.proceedsCny = 0; }
```

**比例退回是既有精度边界的延续**：P21 的「精确」指的是克重分布精确，金额一直按比例退。本批不改这个性质（改了就得给 lot 存每档金额，属 P21 范围外）。

### 3.7 `syncMarksFromBuys()`（约 3760 行）

一行改动，价值最大：

```js
var gram = Number(b.gram) || 0;
a.g += gram; a.n++;
a.costCny += gram * (Number(b.priceCny) || 0);   // 元/克 × 克 = 真实人民币，无需汇率
var usd = cnyToUsd(Number(b.priceCny) || 0);
if(usd) a.cost += gramToUsd(gram, usd);
```

`costCny` **不受 `cnyToUsd` 返回 null 影响** —— 汇率没到也能算出准确的人民币成本。这让 P20 的汇率门只挡「$/oz 均价」，不再挡「成本」。

### 3.8 `recalcGears()`（约 8310 行）

重排时写标记，`costCny` 沿用 `old.costCny`（重排不改变历史花的钱），没有就 0：

```js
costCny: Number(old.costCny) > 0 ? Number(old.costCny) : 0,
```

### 4.3 `updateMarkAmt()` → `syncMarkAmt()`

不再「根据克重×价算金额」，改为「根据本档单价给建议值，但**用户改过就不覆盖**」：

```js
/* 金额是最终事实，不被别的输入覆盖。
   只有「用户没手动改过」时才跟着克重走（S.markAmtDirty = false）。 */
function syncMarkAmt(){
  var m = curMark();
  var unit = m && m.costCny > 0 && m.g > 0 ? m.costCny / m.g : 0;
  if(unit > 0 && !S.markAmtDirty){
    $("markAmt").value = Math.round(unit * gram * 100) / 100;
    hint = "沿用本档 ¥" + unit.toFixed(2) + "/g";
  } else if(!unit && !S.markAmtDirty){
    $("markAmt").value = "";
    hint = "按实际扣款填，不按汇率折算";
  }
  renderImpliedFx();      // §4.4
}
```

`markAmt` 绑 `input` 事件置 `markAmtDirty = true`；`markGram` 绑 `input` 置 `false` 后调 `syncMarkAmt()`；打开面板时重置为 `false`。

### 4.4 `renderImpliedFx()`

```js
/* 只提示，不落库、不参与任何计算。
   三个数都填了才反推，偏离当前汇率 > 10% 才显示 —— 平时不占位。
   为什么不是 2%：购汇时点与点差本来就有 2~4%，2% 会让提示在正常数据上常驻。 */
function renderImpliedFx(){
  var g = Number($("markGram").value), px = Number($("markPx").value);
  var cny = Number($("markAmt").value);
  var box = $("markFxHint");
  if(!(g > 0) || !(px > 0) || !(cny > 0) || !(Number(S.fx) > 0)){ box.textContent = ""; return; }
  var implied = cny / (g / OZ_PER_G * px);
  var dev = (implied / S.fx - 1) * 100;
  box.textContent = Math.abs(dev) > 10
    ? "隐含汇率 ¥" + implied.toFixed(2) + "/$（当前 ¥" + S.fx.toFixed(2) + "）· 确认金额不是美元？"
    : "";
  box.className = Math.abs(dev) > 10 ? "hint warn" : "hint";
}
```

## 七、风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| `null` 被当 `0` | 页脚显示「已实现 ¥0」 | 统一走 `num(v) === null → "—"`，`rvSum` 用 `cnyKnown` 兜 |
| 老用户数据看起来「坏了」 | 所有已实现变「—」 | CHANGELOG 与 toast 说明：「历史成交的人民币金额未填，补一笔即可」 |
| 面板必填挡路 | 用户只想标克重 | 默认值来自本档单价，多数情况一次回车就过；真没有单价时提示「填 0 也可以跳过统计」→ **不，0 会被拒**。改为提示「不知道就填本次大约扣款，可随时改」 |
| 迁移 v2 在 fx=0 时误判「完成」 | 老数据 `cost` 没补 | v2 只补 `costCny`，与 fx 无关；`cost` 的补写仍由 v7 的汇率门负责，两条互不影响 |
| `allotSell` 金额分摊失真 | 一次摊多档、各档单价不同 | 按各档成本单价摊（默认），而非全局均价；误差只在「同档多次不同价」时出现，与 P21 同源 |

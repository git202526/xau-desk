## 0. 一句话

把「档位模式」从一个**价格公式开关**，改成**三层的独立引擎**：

| 层 | 结构基准 | 目标均价 | 谁在动 |
|---|---|---|---|
| 价格层（档距） | `k = 1`（-13…-18%） | `k` 由目标推出，只在不可达时加深 | 均价模式 |
| 重量层 | 分布规则（手动 / 跌幅 / 结构） | **最小扰动求解**，使六档加权均价 = T | 两模式不同 |
| 分配层 | 剩余额度按重量占比摊 | 同左（共用一套代码） | 共用 |

分叉点只有一个：**重量从哪来**。档距层是均价模式的补丁，不是主角。

## 1. 现状诊断：为什么「两套方案没本质区别」

### 1.1 代码实证

`index.html:914` 的档位表是写死的：

```js
var GEARS = [
  {pct:-13, w:8,  name:"第1档"},
  {pct:-14, w:12, name:"第2档"},
  {pct:-15, w:10, name:"第3档"},
  {pct:-16, w:40, name:"第4档"},
  {pct:-17, w:15, name:"第5档"},
  {pct:-18, w:15, name:"第6档"}
];
```

`w` 是**全局常量**，两种模式共用。均价模式下唯一动的是 `he`（高点）：

```js
// index.html:1676
function avgBase(T){ return T / 0.848286; }   // 目标 → 反解高点
```

### 1.2 根因：目标均价被实现成了「一次整体缩放」

设六档价格 `p_i = H(1 + pct_i/100)`、基准权重 `w_i`。只要令

```
H = T / (1 + Σw_i·pct_i/100 / Σw_i)
```

则 `Σw_i·p_i / Σw_i ≡ T` 是**恒等**，不是近似。权重这个自由度从头到尾没被用过。

**自由度只有 1 个（缩放系数），却被当成两套逻辑写了两遍。**

### 1.3 截图实证（用户提供，2026-10-29 22:21）

目标 3700、高点 4700 手动，档位价 4089/4042/3995/3948/3901/3854，克重 16/24/20/80/30/30。切到均价模式后档位价变 4032/…/3897，**克重仍是 16/24/20/80/30/30**。

## 3. 新架构

```
computeGears()
    │
    ├─ ① 档距层
    │     k  = 1                                        （结构模式恒为 1）
    │     k  = pickSpanK(H, T, …)                       （均价模式，见 §5.6）
    │     p_i = 0.87H − (i−1)·0.01·H·k                  （k=1 时等价于原 −13…−18%）
    │
    ├─ ② 重量层（唯一分叉点）
    │     struct → g_i = distWeights(rule)              （手动 / 跌幅 / 结构，见 §4）
    │     avg    → g_i = solveWeights(p, T, R)           （最小扰动闭式解，见 §5）
    │
    └─ ③ 分配层（共用）
          计划_i = W × g_i / Σg
          待买_i = R × g_i / Σg(open)                   ← R = 总仓位 − 已持仓
```

架构要点：

1. **价格层与重量层解耦**，两处都能单独测。
2. 三个纯函数，不读全局、不写 DOM：
   - `spanPrices(H, k) → p[6]`
   - `distWeights(rule, …) → g[6]`
   - `solveWeights(p, T, R, floor) → {g[], feasible, Tmin, Tmax}`
   - `pickSpanK(H, T, …) → {k, g[], feasible, maxShare}`
3. 渲染层只消费结果（符合既有「数据→计算→渲染」单向链）。

### 3.1 档距公式与 v6.17 的关系

```
p_i = 0.87H − (i−1) × 0.01 × H × k
```

`k = 1` 时逐项展开就是 `H(1−0.13)` … `H(1−0.18)`，与现有公式**完全一致**（实测逐档相同到小数点后 1 位）。所以：

- 结构模式（`k≡1`）的档位价与现在**一模一样**，老用户无感；
- 均价模式放大 `k` 时，**第 1 档价恒为 0.87H 不动**，只把第 2–6 档往深处拉 —— 这样「高点 = 第 1 档触发价」的语义不会被破坏。

> 为什么不用「整条阶梯等比缩放」：那会让第 1 档价变成 `0.87H·s`，用户填了高点 4700 却看到第 1 档 3960，语义直接崩掉。实测过这个版本，弃用。

## 4. 引擎 A · 结构基准（结构定重量）

**决策 D1+D2+D3+D4 全部采纳**：设置页提供「分布方式」三选一，其中「手动」下再给「按钟形生成」辅助。

### 4.1 三种分布规则

| 规则 | 公式 | 参数 | 实测克重（H=4700, W=200） | 六档均价 |
|---|---|---|---|---|
| **D1 手动** | 6 个百分比输入框，预填 `8/12/10/40/15/15` | 用户自填 | 16.0 / 24.0 / 20.0 / 80.0 / 30.0 / 30.0 | 3954.1 |
| **D2 按跌幅** | `w_i ∝ \|pct_i\|` → `13:14:15:16:17:18` | 零参数 | 28.0 / 30.1 / 32.3 / 34.4 / 36.6 / 38.7 | 3962.7 |
| **D3 按结构** | `w_i = base_i × (1 + 0.35·z_i)`，`base` 用 D2 | 结构分 z | 随行情 | 随行情 |
| D4 钟形（辅助） | `w_i ∝ exp(−(i−c)²/2σ²)`，c=3、σ=1.6 默认 | c、σ | 9.2 / 24.5 / 44.1 / 53.6 / 44.1 / 24.5 | 3954.5 |

**D4 不是独立选项**，它是「手动」下的一个按钮：点「按钟形生成」→ 按公式算出一组百分比填进 6 个输入框（归一化到 100）→ 用户可继续手改。这样既保留「第 4 档主力」的习惯，又把写死的 40% 变成可调的 σ。

### 4.2 结构分 z 的来源（D3）

数据已经现成，不用新建数据源：

| 来源 | 函数 | 可用字段 |
|---|---|---|
| 价位重合 | `buildLevels()` | 每簇 `count`（几条独立依据重合）、`strong`（≥3 条）、`srcs` |
| 成交量 | `volumeProfile()` | `poc`（成交最密价位）、`vah/val`（70% 价值区） |
| 通道 | `channelOf()` | 上下轨、`atr` |

```
tol = max(0.5×ATR, p_i × 0.4%)
z_i = 0
对每簇价位（距 p_i 在 tol 内）：
    z_i += min(count, 3) × 0.35
    若 strong            → z_i += 0.40
若 p_i ∈ [val, vah]      → z_i += 0.30
若 |p_i − poc| < tol     → z_i += 0.50
若 |p_i − 通道下轨| < tol → z_i += 0.40
z 横向标准化到 [−1, 1]
```

`β = 0.35` 是硬上限：结构再强也只 ±35%，保证不出现「某档 0 克」或「梭哈一档」，深档永远比浅档多。

### 4.3 执行纪律：结构分每天会变

1. 结构分**不自动生效**。页面标注「结构分更新于 10/29 收盘」，点「按结构重算」才应用
2. 3 日指数平滑（α = 0.5），过滤单日噪音
3. 已买完的档不参与重算

### 4.4 顺手修的既有偏差

`index.html:1760` 结构分支让「最后一档吃尾差」，与均价分支的「等比缩放」不一致。统一为：剩余额度按归一化重量摊，尾差补**末档**。

## 5. 引擎 B · 目标均价（重量驱动）

### 5.1 口径（决策 A2：全部六档）

```
T_new = (T × W − c₀ × H₀) / (W − H₀)
```

- `W` 总仓位、`H₀` 已持仓克重、`c₀` 已持仓成本（$/oz，由元/克 ÷ 汇率 × 31.1035）
- 未持仓时 `T_new = T`
- **口径取「六档全打完的整体均价」**，不是「1–4 档」。理由：只有六档全打，整仓成本才等于 T，这才是用户真正关心的数

参与配重的档位（`activeSet`）：尚未买完的档。已买档退出求解，但其成本进入 `T_new`。

### 5.2 求解模型：最小扰动

6 个未知、2 个等式（总量、总金额），自由度 4 —— 必须加「怎么选」的规则。取：**在基准分布附近做最小改动**。

```
min  Σ (g_i − b_i)² / b_i
s.t. Σ g_i = R
     Σ g_i · p_i = T_new · R
     g_i ≥ floor_i = max(0.5g, 20%·b_i)
```

**为什么不用指数倾斜**：实测 `w_i ∝ b_i·e^{t·i}` 在 T 稍高时把第 1 档推到 50.8%、第 3/4 档压到 8.6%/12.6%，形状塌掉。最小扰动解的偏移正比于价格偏离，物理上更温和。

### 5.3 闭式解

一阶条件给出 `g_i = b_i(α + β p_i)`，代回两条约束得 2×2 线性方程组：

```
α·B₀ + β·B₁ = R
α·B₁ + β·B₂ = T_new·R
B₀=Σb_i   B₁=Σb_i·p_i   B₂=Σb_i·p_i²

det = B₀B₂ − B₁²
α = (R·B₂ − T_new·R·B₁) / det
β = (B₀·T_new·R − B₁·R) / det
```

**无迭代**。只有某档跌破下限时才进主动集循环（钉住该档、在余下档重解，最多 6 轮终止）。

### 5.4 退化性（正确性自证）

`T_new` 恰等于基准均价时必有 `β=0, α=1`，解精确还原基准。实测：

| 口径 | 基准均价 | 求解结果 | 最大偏差 |
|---|---|---|---|
| 六档 | 3954.11 | 16.00 / 24.00 / 20.00 / 80.00 / 30.00 / 30.00 | **0.0000 g** |

这条性质保证：**目标等于现状时不会莫名其妙改计划**。

### 5.5 基础可行域（k = 1）

下限铺满后，剩余额度全给最高档得 `Tmax`、全给最低档得 `Tmin`：

```
Tmax = [Σ floor_i·p_i + (R−Σfloor_i)·p_max] / R
Tmin = [Σ floor_i·p_i + (R−Σfloor_i)·p_min] / R
```

H=4700、W=200、六档：**3874 – 4062**。

**这就是旧方案的全部能力边界** —— 用户截图那个 3700 落在外面，所以旧版只能反复建议改高点。

### 5.6 档距自适应（决策 C2，落地为 C 方案）

#### 5.6.1 先说清一个数学事实

C2 和「两套引擎克重不同」**在数学上互斥**，这不是实现问题：

- 档距可自由缩放 ⇒ 总存在一个 `k` 让「基准分布不动」就精确命中 T（实测 T=3800 时 `k* = 2.142`、T=3850 时 `k* = 1.772`）；
- 反过来说，只要档距允许伸缩，求解器的最优解永远是「几乎不动重量」。

**实测证据**（令目标精确落在第 4 档，`k = (0.87H − T)/(0.03H)`）：

| 目标 T | k | 档价 | 克重 | 结论 |
|---|---|---|---|---|
| 3600 | 3.47 | 4089…3274 | 13 / 21 / 19 / 81 / 32 / 34 | 与基准同形 |
| 3700 | 2.76 | 4089…3441 | 13 / 21 / 19 / 81 / 32 / 34 | 同上 |
| 3980 | 0.77 | 4089…3907 | 13 / 21 / 19 / 81 / 32 / 34 | 同上 |

**三个差得很远的目标，克重一模一样** —— 等于只改价格不改重量，和 v6.17 同源，只是缩放对象从「高点」换成「档距」。所以「目标准星对准第 4 档」这个方案被否决。

> 也试过用「有效档位数（1/Σshare²）」代替「最大单档占比」做评价函数：k=1 的 28/36/25/77/21/13 与 k=1.4 的 49/55/30/54/6/6，前者 4.33 档、后者 4.30 档，几乎一样 —— 说明这两个分布「同样不均匀，只是不均匀的位置一个在深档、一个在浅档」。所以指标不改，仍用最大单档占比，简单可解释。

#### 5.6.2 落地方案 C：档距只兜底，兜底就兜到最均匀

```
① k = 1 可行（T ∈ [3874, 4062]）      → k = 1，档位价与结构模式完全一致（G6）
② k = 1 不可行                          → 在 [k₀, 2.5] 内搜「最大单档占比最小」的 k
③ 全部不可行                            → 报错，给出可达范围与一键改高点
```

`k₀` 是「刚好可行」的下界（二分求得）。**但不取 k₀**，因为 k₀ 处的解必然贴在可行域边界上、极端集中：

| 目标 3700 的三条路线 | k | 档距 | 克重 | 最大单档 |
|---|---|---|---|---|
| 不加深（不可行） | 1.00 | −13…−18% | — | 无解 |
| 刚好可行 | 1.81 | −13…−22.7% | 3 / 5 / 4 / 16 / 6 / **166** | **83%** |
| **均匀化（定稿）** | **2.16** | −13…−23.8% | 3 / 5 / 4 / 69 / 48 / 71 | **35%** |

集中度从 83% 降到 35%——同样是「目标 3700」，一个等于单点抄底，一个是能执行的阶梯。

#### 5.6.3 搜索算法

```
pickSpanK(H, T, R, rule):
  if solve(spanPrices(H,1), T, R) 可行:  return {k:1, …}      # 硬规则，不做微调
  k0 = 二分求「最小可行 k」（Tmin(k) 随 k 单调递减）
  if k0 不存在:  return {feasible:false, reason:"超范围"}
  best = argmin  max(g_i)/Σg   over k ∈ {k0, k0+δ, …, 2.5}
  δ = (2.5−k0)/30，再在最优点 ±0.05 内细化 10 步
  return best
```

- 单调性已实测：`Tmin(k)` 随 k 严格递减（k=1.0→3874、1.2→3831、1.4→3788、1.6→3745、1.8→3702、2.5→3552），故可行 k 是区间 `[k₀, 2.5]`，二分可靠。
- `Tmax(k)` 几乎不随 k 变（4062 → 4040，因第 1 档价固定），所以「目标太高」不能靠加深档距解决。
- 计算量：最坏 40×`solveWeights`（每次 O(6)），可忽略；结果按 `(H, T, W, rule)` 做一次缓存。

#### 5.6.5 可达范围与报错口径

#### 5.6.6 档距变化的执行风险

`k` 一动，第 2–6 档触发价全变。若用户已按旧价挂单，会失配。处理：

1. 已标记「已买入」的档不参与重算，触发价保留原值（沿用现有 `gearCleared` 机制）
2. 档位卡显示 `档距 ×2.16`（`k≠1` 时才显示），并标注「第 1 档 4089 不变」
3. 「按高点重算」按钮在均价模式下按**当前 k** 重算，不重置 k

### 5.7 求解器收尾与校验（实测发现的缺陷）

主动集在某些边界会提前 `break`，返回「未命中目标」的解。实测复现：`H=4700, T=3600, k=2.275` 时均价算出 3614.1，而目标 3600。根因：多个档被钉在下限后没有自由档可解，循环退出时 `g` 停在「下限和」上。

**修复（必须做，否则 G2 会随机失败）**：

```
解完后校验：
  gapW = R − Σg                     # 总量残差
  if |gapW| > 1e-6: g[末档] += gapW
  gapV = T·R − Σg·p                 # 金额残差
  if |gapV| > 1e-6:
      从最高档挪 x 到最低档，使新均价 = T：
      x = gapV / (p_max − p_min)     # 线性，闭式
      g[max] −= x ; g[min] += x
  再校验一次，仍不达标则返回 feasible:false
```

同时 `pickSpanK` 二分收敛后必须**重新调用 `solveWeights` 复核 `feasible`**，不可行则回退到上一个可行 k，并在返回值里带上 `kAdjusted:true`。

## 6. 关键决断：均价模式**不再自动反解高点**

现状：均价模式 + 高点留空 → 高点 = `T/0.848286` → 重量退回基准 → 又变成结构模式。

改法：均价模式的高点取法与结构模式**完全一致**（`H_BASE` 或 D60 自动），不再按目标反解。

反解值降级为卡片上的一条建议（「若保持原分布，高点应为 4362」），不自动执行。

> 与 §5.6 的区别：反解高点 = 整条阶梯缩放（第 1 档价也变，语义崩）；加深档距 = 第 1 档不动、只往深处拉（语义保留）。两者都影响价格，但后者不破坏「高点 = 第 1 档」的定义。

## 7. 已持仓与已买档的口径

| 状态 | 处理 |
|---|---|
| 已买完（`gearBought > 0`） | 退出 `activeSet`，克重不重算；实际克重与成本进入 `H₀ / c₀` |
| 部分买过 | 同上，整档退出；余额不再补（避免「买过又按计划补满」的混乱） |
| 未买 | 进入 `activeSet`，参与求解 |

剩余额度 `R = W − 已持仓` 只分给 `activeSet`。两模式共用同一套分配代码。

**边界**：`R ≤ 0` → 全部克重 0，提示「仓位已满」；`activeSet` 为空 → 跳过求解。

## 11. 决策记录（2026-10-29 拍板）

| 项 | 决策 | 关键数据 |
|---|---|---|
| **A** 目标口径 | **A2 全部六档** | 可行域 3874–4062；只有六档全打，整仓成本才等于 T |
| **B** 不可达处理 | **B1 只提示 + 一键按钮**，绝不擅自改用户填的值 | 三个出口：加深档距 / 改高点 / 接受集中，均由用户点 |
| **C** 档距自适应 | **C2，落地为 C 方案**：`k=1` 优先，不可达才加深，且加深到「最均匀」 | 3700：k=2.16、集中 35%（对比「刚好可行」的 83%） |
| **D** 结构模式克重 | **D1+D2+D3+D4 全采纳**：手动 / 按跌幅 / 按结构 + 钟形生成 | 三种规则六档均价 3954.1 / 3962.7 / 随行情 |

### 11.1 三个已知限制（不是缺陷，是数学必然）

1. **档距与克重互斥**：只要档距能自由缩放，就一定存在「克重几乎不动」的解。本方案用「k=1 优先」把这种退化限制在 `T` 出可行域时才发生。
2. **集中度不可消除**：目标越贴近可达边界，单档占比必然越高（3880 时 70%、4050 时 56%）。只能警示 + 提供「加深档距」或「改高点」两个出口。
3. **`k` 每次重算会漂**：`H` 由 D60 算出，`T` 由用户填，两者一变动 `k` 就变，档位价跟着变。已买档已锁定，所以只影响未成交的档。

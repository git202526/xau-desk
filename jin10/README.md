# 金十中转产物

本目录由 `.github/workflows/jin10.yml` 每 5 分钟写入，勿手工编辑。
浏览器只读这里的同源静态文件，不直连 mcp.jin10.com（CORS 不放行，见 docs/J2-金十MCP探测记录.md）。

| 文件 | 来源工具 | 缓存 TTL | 页面用途 |
|---|---|---|---|
| `calendar.json` | `list_calendar` | 1200s | 事件雷达主源（失败回落 ForexFactory） |
| `kline_1w/1d/4h/1h.json` | `get_kline`（`hf_XAU`） | 240s | K 线源校验；Binance 全挂时兼作备源 |
| `quote.json` | `get_quote` | 60s | 仅落盘，浏览器侧不用（5 分钟滞后救不了 15 秒实时价） |
| `state.json` | — | — | 当日计数与停用标记 |

## 每日额度（北京时间自然日切日）

**服务端硬额度（官方口径）**：每用户、每工具、每天 **1500 次** `tools/call`。
「每工具」= 各自独立计数 —— `get_kline` 用满 1500 不影响 `list_calendar`，反之亦然。
超限返回 `今日该工具调用次数已达上限，请明日再试`。

| 工具 | 硬额度 | 软上限（本脚本） | 正常日耗 | 说明 |
|---|---|---|---|---|
| `get_kline` | 1500 | 1100 | 696 | 四个周期共用一个池，按周期分 TTL |
| `list_calendar` | 1500 | 110 | ≤ 72 | 每 20 分钟一次 |
| `get_quote` | 1500 | 200 | ≤ 200 | 仅落盘，页面不用 |

K 线各周期的 TTL 与日耗：

| 周期 | TTL | 日耗 |
|---|---|---|
| `1w` | 3600s | 24 |
| `1d` | 900s | 96 |
| `4h` | 300s | 288 |
| `1h` | 300s | 288 |
| **合计** | | **696**（硬额度的 46%） |

### 为什么软上限是 1100 而不是 1500

撞**硬额度**的后果是该工具当天彻底停摆，要等到次日 00:00 才恢复；
撞**软上限**只是提前收手，页面上表现为「校验未就绪」，第二天照常。

`get_kline` 单次失败最多重试 3 次（`MAX_RETRY = 2`），一轮 4 个周期全失败就是 12 次。
若上游持续不可用，每 5 分钟烧 12 次，1100 − 696 = 404 次余量能撑约 34 轮（近 3 小时），
期间源恢复就还能继续工作；而 1500 没有余量，一次重试风暴就把当天额度打光。

> 4H / 1H 的 TTL 无法再往下压：Actions cron 最小粒度就是 5 分钟，
> 一轮内每个周期最多抓 1 次，288 次/天 已是这套架构下的天花板。

若 `state.json` 里出现 `get_kline` 的 `quota` / `stopped` 标记，说明判断有误，应回调软上限。

计数按**实际发出的请求**记：超时、5xx、额度用完同样 +1。
剩余 ≤ 2 时不再重试，避免最后一轮把额度烧光。

缓存键用**输出文件名**（`kline_1d.json` 等），不是工具名 ——
四个周期共用 `get_kline`，用工具名做键会让第一个周期的时间戳把后三个顶成「命中缓存」。

## 未实测项（别把推断当结论）

J2 那次探测只发了 3 个请求（`OPTIONS` 预检 ×2 + 无效 Token 的 `initialize` ×1），
**一次 `tools/call` 都没打，也没调过 `tools/list`**。所以下面三件事全是推断：

| 项 | 脚本里的值 | 状态 |
|---|---|---|
| 单次可返回几根 K 线 | `limit: 200`（**请求值**，不是服务端上限） | 未测。要多了怕直接 400，所以按保守值请求 |
| 入参名 | `{code, period, limit}` | 未测。按命名推断，以 `tools/list` 的 `inputSchema` 为准 |
| `t` 是周期起点还是终点 | 按周期起点处理 | 未测。若是终点，同一根会永远差一个周期，需整体平移 |

探明成本：`tools/list` + 一次 `get_kline(limit=1000)` ≈ 2 次调用，占 1500 的 0.13%。
真接通后第一件事就应该是这个，否则四个周期可能在第一步就全 400。

另：`JIN10_TOKEN` 尚未配置，workflow 无 secret 时直接跳过 —— 上面这些额度一次都还没真正消耗过。

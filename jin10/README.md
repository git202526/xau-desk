# 金十中转产物

本目录由 `.github/workflows/jin10.yml` 每 20 分钟运行一次 `tools/fetch_jin10.py` 写入，勿手工编辑。
cron 20 分钟、脚本 TTL 1080s（18 分钟）—— TTL 比 cron 略短，是为了吸收 GitHub 定时任务的触发延迟；
两者相等时，延迟的轮次会命中缓存直接退出，白跑一次 Actions。
浏览器只读这里的同源静态文件，不直连 `mcp.jin10.com`（CORS 不放行，见 `docs/J2-金十MCP探测记录.md`）。

## 只有一个文件

| 文件 | 来源工具 | 缓存 TTL | 页面用途 |
|---|---|---|---|
| `calendar.json` | `list_calendar` | 1080s | 事件雷达主源（失败回落 ForexFactory 周历） |
| `state.json` | — | — | 当日计数与停用标记 |

`list_calendar` 不收任何参数，返回「当前自然周（周一到周日）」的财经日历，正是页面要的口径。

## J5 实测：K 线为什么不能用

`tools/list` 拿到真实 schema，并用 3 次 `tools/call` 验证过：

```json
get_kline: { "code": string(必填),
             "time":  integer,   // 起始 Unix 秒，从此刻往后取，窗口 24 小时内
             "count": integer }  // 从 time 起取 count 根「分钟 K 线」，1–100
```

实测 `get_kline({"code":"XAUUSD","count":100})`：

- **100 根，间隔 60 秒，首末跨度 1.65 小时**
- 返回是**倒序**（新→旧），价格是字符串 `"3945.34"`
- 外层 `{status, message, data:{code, name, klines}}`

对照校验需要的数据量：日线 20 根 = 20 天跨度，缺口约 **290 倍**。没有多周期接口，这条路物理上走不通。

详细记录（请求清单、schema 原文、错误对照表）见 `docs/J5-金十MCP实测记录.md`。

## 每日额度（北京时间自然日切日）

**服务端硬额度**：每用户、每工具、每天 **1500 次** `tools/call`。超限返回
`今日该工具调用次数已达上限，请明日再试`。

| 工具 | 硬额度 | 软上限（本脚本） | 正常日耗 |
|---|---|---|---|
| `list_calendar` | 1500 | 110 | ≤ 72（每 20 分钟一次） |

软上限 110 只是护栏 —— 正常日耗才 72，设 110 是为了防「某个 bug 导致每轮都判定过期」
把额度打光。撞硬额度 = 当天彻底停摆；撞软上限 = 提前收手，第二天照常。

计数按**实际发出的请求**记：超时、5xx、额度用完同样 +1。剩余 ≤ 2 时不再重试。

## 仍未配 Token 时的行为

`JIN10_TOKEN` 没有配置时，workflow 直接跳过并以 2 退出，**不发任何请求**，页面照常运行
（日历回落 ForexFactory，再回落内置的 FOMC / 非农）。

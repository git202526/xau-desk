# XAU Desk · 伦敦金行情智能分析台

单文件网页，浏览器里直接跑。打开即用，不依赖后端、不依赖任何定时任务。

## 它能做什么

- **多周期方向判定**：周线 / 日线 / 4小时 / 1小时，各自跑 5 条条件，满足 3 条成方向
- **结构识别**：自动区分「共振 / 周期背离 / 区间 / 无趋势」，并给出对应判断
- **关键位**：枢轴、斐波那契、摆动高低点、MA20/60/200、PL90/PL180，同价位自动聚类成「强位」
- **趋势通道**：90 根 K 线的迷你图（内联 SVG 手写），回归通道给出方向、通道位、宽度与触轨次数；日线 / 4 小时可切
- **自定义位**：自己加价位、起名、备注，与系统位重合时提示；双设备按 id 并集，删除走墓碑
- **到价提醒**：对任意自定义位设上破 / 下破 / 双向，命中进「今天要处理」+ 响铃 + 挂角标；只在页面打开时提示
- **建仓阶梯**：一条公式、三层数据。价格 `p_i = 0.87·H − (i−1)·d`（第 1 档恒为 `0.87H`），计划 `w_i/Σw × 目标总克重`，执行靠档位标记。每档显示两个数：**净持**（标记克重 − 已卖克重）和**计划**（只随权重与总仓变，200 克时六档为 16 / 24 / 48 / 72 / 24 / 16）。两者之差是**待补**，买多了显示**超买**。改「目标总克重」后两个数等比重算，价格一个都不动
- **档距是唯一自由度**：`d` 有两个来源——填了目标均价就 `d = (0.87H − T) / ī`（一步除法，`ī` 是档位重心，默认分布下 2.56）；改「间隔系数 α」则 `d = α × ATR`（α ∈ 0.6–3.5）。两个输入互不覆盖，**谁后动听谁的**，α 模式下卡片给「对齐目标」一键拧回来
- **推导卡**：告诉你「按现在这套档距买完，六档均价落在哪」（六档全计入）、离目标差多少、命中没命中；再摊开 `档距·α`、`跨度`、`距现价`、`射程 k/6 档 · 买满还需再跌 x%（40 日概率）`
- **标记即执行**：不想记账时，直接点档位标「已买多少克、成交价多少」；记了账也不用手动标，带档位的买入会自动对账到该档。**档位标记是唯一口径** —— 不管你是手标的还是记账带出来的，档位表、待补、下沉、复盘读的都是同一份数据
- **买入 / 卖出流水**：持仓页「买入」「卖出」两个按钮各记一笔，逐笔记克重、单价、时间，自动汇总剩余克重、加权均价、已实现盈亏；记录区可按 全部 / 买入 / 卖出 筛选。盈亏按中文习惯**盈利红、亏损绿**
- **多账户（仓库）**：一个账户对应一个银行积存金账户。每笔买卖可选归属，持仓页按账户筛选，账户卡片给出各账户的克重 / 均价 / 回本价 / 浮盈 / 占比。**账户与档位是两个维度** —— 档位价、权重、目标克重都是全局的，同一档可以在两个账户各买一部分；删除有记录的账户要先转移。卖出不按账户重新分摊成本，所以账户成本相加不等于全局成本（可相加的只有克重与买入总额）
- **回本价**：均价 + 回本加点（默认 10 元/克，可调 0–50）。低于它是「还差 x%」，高于它是「已过 +x%」
- **止盈计划**：候选位覆盖 回本位、盈利档 +15/20/25/30%、枢轴 / 斐波 / 均线、前高、**延伸 127.2% / 161.8% / 200%**、PL90 / PL180、52 周高点、整数关口。每档给**评分 + 触及概率 + 建议克重**，次数不固定（2–8 次），按分数断层自然截断
- **减仓核销与摊派回滚**：点执行位直接记一笔减仓，持仓克重与止盈计划自动跟着重算；这笔减仓按各档净持占比摊进档位，**改克重或删记录时按当时的分摊快照精确退回**（不是按当前比例重算），删掉的卖出记录不会在档位上留下幽灵
- **执行复盘**：一张折叠卡，逐档给出「计划价 → 实际成交均价」、偏差百分比、四态（未到价 / 到过价 / 已周转 / 未成交），末尾给合计与账本对账差额、每克拉低的成本。默认收起，不占首屏；收起时连 K 线都不扫
- **判定回溯**：近 800 根日线的方向色带（红上行 / 灰震荡 / 绿下行）、三态分布、每次方向切换的日期；点某一天，看当天命中了几条、命中的是哪几条
- **档距扫描**：同一条行情、同一份权重，把档距乘 **0.6 / 0.8 / 1.0 / 1.2 / 1.4** 各跑一遍，并排给「触发几档 / 花多少钱 / 比一次性贵还是便宜」。不标「最优」—— 档距越大越便宜但越可能买不到，是权衡不是优劣。点任一行切到那一组的收益率曲线与逐档明细。**无预算上限 · 按档位价成交**，金价按美元/盎司不折算汇率；区间可选 90/180/365 天/全部/自动（首次建仓起）；**不含盘中路径**，结论只看相对优劣，不当收益预测
- **事件雷达**：美联储会议（官方日程）+ 非农（惯例推算）为内置兜底；GDP / CPI / PCE / 初请等来自 `calendar.json`（ForexFactory 周历，服务端抓取、同源交付），取不到时自动回落。底部写明当前用的是哪一级（金十 / 备源 / 内置）
- **状态记录**：方向翻转、档位到价、买入记录，全部写进你自己的 GitHub 私有仓库

### 几个词先对齐

| 词 | 含义 | 别理解成 |
|---|---|---|
| 计划 | 该档应买克重 `w_i/Σw × 总仓` | 已买、目标 |
| 净持 | 档位标记克重 − 该档已卖克重 | 账本持仓 |
| 待补 | 计划 − 净持（> 0 才算） | 未买、缺口 |
| 超买 | 净持 > 计划 | 超配 |
| 账本持仓 | `buys − sells` 汇总，独立于档位 | 真实持仓（它只是你记的账） |
- **状态记录**：方向翻转、档位到价、买入记录，全部写进你自己的 GitHub 私有仓库

## 部署

线上地址：**https://git202526.github.io/xau-desk/**

页面仓库 `git202526/xau-desk`（公开），数据仓库 `git202526/xau-desk-data`（私有）。两个仓库分开，更新页面不会碰持仓数据。

改完代码推送即可，Pages 一分钟内自动重新发布，网址不变：

```bash
git add -A
git commit -m "改了什么"
git push origin main
```

### 这台机器上改用 `tools/deploy.py`

`git push` 到 github.com:443 会卡在对象协商上（实测 45~90 秒无响应，时通时断），
所以这台机器上的部署走 GitHub Data API——同一个域名、同样的令牌，几百毫秒稳定返回：

```bash
python3 tools/deploy.py --dry-run              # 先看会推哪些文件，不写远端
python3 tools/deploy.py --wait 180             # 推 + 等 Pages 构建完成后校验字节
python3 tools/deploy.py --only index.html      # 只推指定文件
python3 tools/deploy.py --verify               # 只做线上校验（不推）
```

它比 `git push` 多两道闸，都是踩过坑才加的：

| 闸 | 拦什么 | 来由 |
|---|---|---|
| 按 blob 内容算差异 | 只推真正变了的文件，不再整份快照覆盖 | 旧的一次性脚本把 `xau/klines.json` 从 11-09 02:20 覆盖回 11-08，回退 1 根日线 7.7 小时 |
| 数据文件按时间戳拦截 | 本地副本旧于远端时跳过该文件并告警 | `calendar.json` / `macro.json` / `jin10/*.json` 由 Actions 在云端直写，本地副本天然更旧 |

`screenshots/`、`versions/`、缓存目录永远不进部署包。无差异时不会产生空提交。
部署后用 `python3 -m pytest -m deploy` 复核，d2 判的是「远端 index.html 的内容
是否等于本地 HEAD 的 index.html」，所以 API 部署产生的不同 commit sha 不会被误判成「没上线」。

> 本地 `origin/main` 引用不会因 API 部署而更新，`git status` 可能提示 ahead——
> 那是引用陈旧，不是没上线。以后提交继续用 `tools/deploy.py` 即可；想恢复普通 git 流程，
> 等网络好的时候 `git fetch` 一次，`git reset --soft origin/main` 对齐。

## 测试

Playwright + pytest，行情 / GitHub API / 汇率全部 mock，不依赖外网。

```bash
python3 -m pytest tests/test_smoke.py    # 冒烟 19 条，约 30 秒，**改完先跑这个**
python3 -m pytest -m smoke               # 同上（按 marker 选，等价）
python3 -m pytest                        # 全量 1132 条，8 进程约 5 分钟，发布前跑
python3 -m pytest -m deploy              # 上线门禁 5 条，8 秒，**收尾必跑**
python3 -m pytest tests/test_p18_review.py -q    # 单个文件
```

| 层 | 条数 | 耗时 | 什么时候跑 |
|---|---|---|---|
| 冒烟 `test_smoke.py` | 19 | 约 30 秒 | 每次改完 |
| 全量 | 1132 | 8 进程约 5 分钟 | 每期收尾、发布前 |
| 上线门禁 `-m deploy` | 5 | 8 秒 | 每次 `tools/deploy.py` 之后 |

`-m deploy` 被 `addopts` 默认排除（`-m "not deploy"`），日常全量不联网。它查的是「线上那份文件是不是本地这份」：工作区干净、**提交的 index.html 内容已在远端**、线上 sha256 相等、版本号相等。详见 `docs/约束-代码与DOM.md` 第八节。

冒烟不是全量的随机抽样，而是**按链路挑**：十条链路各一两条主路径，回答「这个功能还活着吗」。边界仍归全量。`pytest.ini` 开了 `--strict-markers`，marker 写错会直接报错，不会静默少跑。

两条纪律：

- **先冒烟，后全量**。冒烟红了就修，别急着上全量 —— 全量只会把同一个错误放大 779 次
- **红了先找根因**。改断言让它变绿，等于把 bug 转成测试的债；只有「测试自己写错了」才改测试，并且要在 docstring 里写清新旧契约

已知的一条时序敏感用例：`test_l8_period_tags_update_not_wrap` 曾用固定 `wait_for_timeout(200)` 等重排，全量串跑时偶发红。现已改成轮询到布局稳定（上限 3s），判据未放宽。

## 数据来源

| 用途 | 接口 | 说明 |
|---|---|---|
| 实时价 | `api.gold-api.com/price/XAU` | XAU/USD 现货，15 秒刷新 |
| K 线（主） | `xau/klines.json`（Actions 抓 Dukascopy） | 真实 XAU/USD：1h 2424 / 4h 654 / 1d 523 / 1w 106 根，15 分钟更新 |
| K 线（降级） | `data-api.binance.vision/api/v3/klines` | PAXG/USDT，仅在 `xau/klines.json` 不可用时启用，页头会标注「PAXG 代用」 |
| 宏观（TIPS） | `fred.stlouisfed.org/graph/fredgraph.csv?id=DFII10` | 10 年期实际收益率，日频、无需 key |
| 宏观（美元） | `ts-api.cnbc.com/.../1M.json?symbol=.DXY` | ICE 美元指数日线，无需 key；Yahoo 对共享出口 429、Stooq 有 JS 挑战 |
| 宏观产物 | `macro.json`（Actions 抓，每小时） | `tips_10y` / `dxy` / `hist` / `fetched_at`；抓取超 90 分钟前端判「数据延迟」 |
| 汇率 | `open.er-api.com/v6/latest/USD` | 仅用于持仓成本折算，不参与行情点位计算 |

**K 线为什么走 Actions 中转**：`datafeed.dukascopy.com` 无 CORS，浏览器直连必失败，沙箱出口也不通。
`.github/workflows/xau.yml` 每 15 分钟抓最近 4 天的 `BID_candles_min_1.bi5`，清洗、聚合后落 `xau/klines.json`；
日线深度来自年度文件 `XAUUSD/{Y}/BID_candles_day_1.bi5`（1 个请求 = 1 年）。
清洗规则：剔除 `v=0` 且四价相等的休市填充根（实测累计 66214 根），周六/周日不入日线（周日那根只有开盘后 2 小时，与 23 小时交易日不可比）。

**休市判定**：按纽约时区——周五 17:00 收盘、周日 17:00 开盘、周一至周四 17:00–18:00 每日结算停盘。
停盘只冻结箱体触碰计数，不清空图形；缺口分 `session`（正常休市）/ `missing`（真实缺数据）。
通道图在断点处留白、通道带按段绘制，周五收盘不会用一条线连到周一开盘。

**宏观为什么也走 Actions**：`fred.stlouisfed.org` 与 `ts-api.cnbc.com` 在浏览器侧都受 CORS 限制，
`.github/workflows/macro.yml` 每小时抓一次、落 `macro.json`，前端同源读取。
两个源必须都成功才落盘——只有 TIPS 没有美元的半张卡比一张明确标注「数据延迟」的旧卡更容易误导。

**回滚**：`localStorage.wb_v76_off = "1"` 立即回到 v7.5 的 PAXG 链路。

| 层 | 覆盖 | 来源 |

## 金十（只做日历）

金十的 MCP 端点 `mcp.jin10.com` **不能从浏览器直连** —— 预检不返回任何 `Access-Control-*` 头，
带 `Origin` 的 POST 被 403 拒（要求 `Origin == Host`）。实测记录见 `docs/J2-金十MCP探测记录.md`。

所以走中转：

```
GitHub Actions（每 20 分钟） → tools/fetch_jin10.py → jin10/calendar.json → 浏览器只读同源文件
```

启用只需一步：仓库 Settings → Secrets 加 `JIN10_TOKEN`。没有这个 secret 时 workflow 直接跳过，
不发起任何请求，页面照常运行（日历回落 ForexFactory，再回落内置事件）。

**只用一个工具**：`list_calendar`，返回当前自然周（周一到周日）的财经日历，正是页面要的口径。
正常日耗 ≤ 72 次，官方额度是每工具每天 1500，余量充足。

另外两个工具已下线（v6.58），原因都实测过：

- **`get_kline` 救不了 K 线**：只有分钟级接口，`count` 上限 100、窗口 24 小时，
  凑不出 4H / 日线任何一根 bar。曾想用它当校验源和备源，实测后两者都不成立，
  前端那行「K 线校验」也一并拆了。
- **`get_quote` 救不了报价**：中转最快 5 分钟一份快照，页面的报价是 15 秒一次。

代价是日历最多滞后 20 分钟，对事件雷达够用（事件按分钟排，滞后只影响新事件的加入时点）。详细实测数据见 `docs/J5-金十MCP实测记录.md`。

```bash
python3 tools/fetch_jin10.py --selftest   # 本地假 transport 跑全链路，不联网、不要 Token
JIN10_TOKEN=*** python3 tools/fetch_jin10.py          # 按 TTL 增量抓
JIN10_TOKEN=*** python3 tools/fetch_jin10.py --force  # 忽略 TTL
```

软上限 110 次/日（正常日耗 72），到顶只停该工具；额度用完停到次日，不重试。
Actions 的 cron 已与脚本 TTL 对齐到 20 分钟 —— 按 5 分钟跑的话，4 次里有 3 次是空转。

`calendar.json` 由 `tools/fetch_calendar.py` 生成。ForexFactory 的周历接口不返回
`Access-Control-Allow-Origin`，浏览器端直接 fetch 会被拦，所以只能服务端抓完、以同源静态文件交付。

**想让它自动更新**：把 `tools/calendar-workflow.yml` 的内容放到仓库的
`.github/workflows/calendar.yml`（GitHub 网页端新建文件即可），之后每 6 小时抓一次。
不启用也能用——`calendar.json` 会在每次改版时刷新一次，页面按 `updatedAt` 判断新鲜度：
超过 3 天标「N 天未更新」，超过 7 天自动回落到内置的 FOMC + 非农，不会白屏。

手动刷新：

```bash
python3 tools/fetch_calendar.py          # 写 calendar.json
python3 tools/fetch_calendar.py --dry-run # 只打印前几条，不写盘
```

上线前可以先跑一遍真机走查（真浏览器、真行情接口、不挂调试桥）：

```bash
python3 tools/verify_v618.py --out /tmp/v618
```

390×844 与 320×568 各截「建仓 / 设置」，顺便断言无横向溢出、六格分布与 α 输入完整、
档位行不缺，并收集 console error。

## 使用步骤

1. 打开页面，等 3–5 秒加载 K 线（右上角变「实时」）
2. 看「方向判定」——先知道现在能不能做
3. 切「建仓」看档位，到价时「今天要处理」会提示
4. 真的买了，点档位 → 确认克重 → 记入，弹药进度会累加
5. 每买一次就点「买入」，填克重和单价（元/克），总金额与均价自动算
6. 止盈计划按均价自动排出来：分数高、够得着、离得开的位分到的克重更多
7. 卖出时点「卖出」记一笔（止盈到价时点执行位也行），剩余持仓、已实现盈亏和计划会立刻重算

## 止盈是怎么算的

每个候选位跑三步：

1. **评分（0–100）**：位置强度（几个来源指认，0–36）+ 空间（0–24）+ 趋势配合（0–30）+ 位类型（延伸位加、整数关口减，-6~+12）。太近、概率太低的位扣分
2. **触及概率**：日线 ATR14 折算成「还差几个日均波幅」，用 `100 / (1 + 0.75 × 需走天数^1.3)` 打底，多头 ×1.22、空头 ×0.82，强位再 ×1.05。显示为「触及 37% · 约 1 日行程」
3. **分配**：先按「减仓比例」扣掉底仓，剩下的按 `分数 × 可达性 × 空间` 加权分给入选位，最后一笔吸收尾差

选位不写死次数：按分数从高到低取，遇到「相邻两档分差 ≥ 18 且后一档 < 56」就停，最多 8 个、最少 2 个。间距小于 1.2% 的同价位只留分数高的那个。

### 保本线：止盈和止损分开算

计划执行位会按你的**均价成本**切成两段，顶部各算各的：

- **止盈段**（位价 ≥ 成本）：`止盈 49.2g · 均价 1004 · +5.7%`，这一段的均价才是"期望均价"
- **止损段**（位价 < 成本）：`止损 40.8g · 均价 918 · −3.4%`，卖出即亏，卡片上标「止损」

设置里有个「允许在成本下方减仓」开关。关掉后，低于成本的压力位只列参考、不分配克重，计划表里只剩真正赚钱的位——这时期望成交会明显变少，但每一笔都是止盈。

> 注意：期望均价是「所有位全部成交」的算术平均，不含概率。远位成交概率往往只有 3–6%，别把它当预期收益看。

### 关于建仓高点

- **留空** = 自动算：近 60 个交易日最高收盘（退化时取 20 日）
- **手动填** = 用你锁定的高点，第 1 档价 = `0.87 × 高点`

档距由「目标均价」或「间隔系数 α」决定，二者谁后改听谁的。六档全部跌穿而一档未买时，
页面置顶提示「高点脱锚」，点进去填新值即可——第 1 档会自动跟着锚定，不需要另点重算。

### 关于目标总克重与底仓

- **目标总克重**：你计划一共持有多少克。六档计划克重 = `权重 / Σ权重 × 目标总克重`，**不扣已持仓**；少买的部分由「待买」自己收敛（`Σ待买 = 总仓 − 已持仓`）
- **底仓保留**：涨到位也不卖的克重，这是唯一需要你填的口径。右边「本轮计划减仓」由持仓减掉底仓自动折算，显示成 `90.0 g（90%）`，不用手填百分比。改完一失焦就重算，不用点保存

两个参数都在「设置」里，改完立刻重算建仓与止盈，不用手动改档位。底仓按克锁定：持仓增加时减仓量跟着变，底仓克重不变。

## 数据存储

**唯一数据源是你的 GitHub 私有仓库里的 `data.json`。浏览器不保存业务数据。**

打开页面 → 用令牌读云端 → 渲染。任何修改（记一笔、改参数、删记录）都是"先写云端，再刷新界面"。所以：

- 换手机、换电脑、换浏览器：打开同一网址，数据完全一致
- 清浏览器缓存、隐私模式、换系统：数据都不受影响
- 浏览器里只留两样东西：令牌（`wb_xau_desk_gh`）和一份**只读**离线快照（`wb_xau_desk_snap`），断网时用来查看，不会被写回云端
- 打开时如果连不上网，页面会明确标注「离线只读 · 时间」，联网后自动回到云端版本

### 仓库怎么分

| 仓库 | 可见性 | 放什么 | 为什么 |
|---|---|---|---|
| `xau-desk` | 公开 | `index.html` | GitHub Pages 免费版要求页面仓库公开 |
| `xau-desk-data` | **私有** | `data.json` | 持仓克重和成本价不能公开 |

页面公开，别人打开链接只会看到一个空工作台——他的浏览器里没有令牌，读不到你的数据。

### 接一次，之后不用管

1. 打开网址，点右上角「未接入」或顶部红色提示
2. 粘贴**接入码**（在已接入的设备上点「复制接入码」），或手填仓库 + 令牌
3. 点「保存并开启同步」

接入码是一串 `XAU1.…`，把仓库、分支、路径、令牌打包在一起，新设备粘一次就接好。**它等同于密码，别发到群里。**

### 写入时机

- 任何保存操作后 0.8 秒写一次（连续操作合并成一次）
- 页面切到后台立即写
- 打开页面、切回前台时读一次
- 冲突（远端已被改）自动重读 sha 重试一次
- 断网时网络请求退避重试（6/12/18 秒），最多 5 次

### 两台设备同时记账不会互相覆盖

写入前会先读一遍云端，把两边的记录**按 id 取并集**再写回，参数以当前操作的设备为准。删除会记一条墓碑 id，避免被另一台设备"复活"。

数据文件超过 1 MB 会被 GitHub 拒绝。`feed` 只保留最近 200 条、止盈计划最多 40 条，正常用几年都到不了上限。
